## 摘要

這份文件定義了 CrawlerService 等相關服務需新增對賽事結果資訊 (ResultInfo) 和其他資訊 (OtherInfo) 的支援。具體變更包含：DB 新增欄位、更新 CrawlerService/CrawlerFlowService/FlowControlService 的處理策略、PriceSubscriptionSystem 的 Hub 輸出、以及 PriceCenterService API 增加回傳欄位。閱讀後可理解這類資訊在系統中的完整資料流與各服務的責任範圍。

---

## 關鍵業務規則

- - sitegame_{gameType} 和 games_{gameType} 資料表需新增 resultinfo 與 otherinfo 欄位，類型為 map<text,text>。
- CrawlerService 更新 sitegame 策略時，需根據爬到的資料判斷並設定 resultinfo 欄位。
- CrawlerFlowService 需將賽事結果其他資訊寫入 processgamedata 的 Match 物件中。
- FlowControlService 需將賽事結果其他資訊同步至 Redis。
- PriceSubscriptionSystem 需透過 Hub 對外輸出賽事結果 (resultinfo) 和賽事其他資訊 (otherinfo)。
- PriceCenterService 的取得 sitegame API (GET /pricecenter/api/sitesinglegame/...) 回傳的 SiteGameDTO 需增加 ResultInfo 和 OtherInfo 兩個欄位，型別為 List<KeyValue>。
- 遊戲合併 (merge game) 時，resultinfo 與 otherinfo 也應一併合併，確保合併後的賽事保有完整資訊。

---

## 關鍵設計決策

- - resultinfo 和 otherinfo 採用字典結構 (map<text,text>)，以便存儲賽事中不同類型的統計資料（如角球、進球時段、紅牌等），保持彈性。
- 不同服務間傳遞的模型採用統一的 IDictionary<string, string> 或對應的序列化形式，確保爬蟲、流程處理到 API 輸出的一致性。
- 對外 API 回傳設計為物件列表 (List)，每個項目包含 Key/Value，方便前端渲染動態表格。
