## 摘要

此文件定義了從 footballant.com 抓取足球賽事資料的欄位對應與擷取邏輯，涵蓋賽前、賽中、賽後三種頁面狀態。對 AI 開發爬蟲服務的幫助在於：明確指出各階段所需欄位的資料來源路徑（如 JSON key 或 HTML 屬性），並規範了特殊欄位的萃取方式（如從圖片 URL 中擷取隊伍 ID、使用正則表達式抓取聯盟 ID）。提供了具體的資料結構映射，可做為開發與維護 footballant 爬蟲解析器的直接參考。

---

## 關鍵業務規則

- - page_type 參數用來標示比賽狀態（賽前、賽中、賽果），爬蟲需根據不同狀態對應不同的資料結構。
- 賽中資料的 team_home_id 與 team_away_id 需從圖片來源字串中取出數字。
- 賽果資料的 league_id 需使用正則表達式 'href="/football-data/league/(\d+)"' 從 href 屬性中抓取。
- 賽果資料的 league 名稱需使用正則表達式 'title="([^"]+)"' 從 title 屬性中抓取。
- 賽果資料的角球 (corner) 欄位，HTML 結構中先出現的為 '主隊'，後出現的為 '客隊'。
- 賽果資料的黃牌 (yellow_card) 與紅牌 (red_card) 欄位，只有在該隊伍有獲得牌數時才會出現。
- start_time 欄位（比賽開始的實際時間戳）應用於計算 playbyplay 的相對時間。

---

## 關鍵設計決策

- - 選擇直接從 API 回傳的 JSON 或 HTML DOM 中取值，而非透過更高層的抽象物件，以最直接的方式取得原始資料。
- 針對部分字串型態的 ID（如 team ID 藏在圖片 URL 中），採用後處理的字串提取邏輯，而非要求資料來源提供純淨 ID。
- 使用頁面類型 (page_type) 做為區分 API 回應結構的依據，是一個隱含的狀態機設計，爬蟲需具備根據此狀態切換解析邏輯的能力。

## 注意事項

- ⚠️ - ⚠️ 文件中的圖片無法顯示，需人工確認對應的 JSON 結構或 HTML class name 是否仍然存在，特別是賽果部分仰賴特定 CSS class（如 font-20 color-black）。
- ⚠️ 賽前 game_id 從 ScheduleID 取得，賽中則從 matchId 取得，命名不一致，開發時需注意區分。
- ⚠️ team_home_id 與 team_away_id 的提取方式（從字串中取數字）依賴圖片 URL 的格式，若圖片 CDN 或命名規則變更，會導致擷取失敗。
- ⚠️ 時間戳的格式未明確說明，只提到「用 datetime 去轉換」，需人工確認是秒還是毫秒。
