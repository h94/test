## 摘要

文件介紹 .NET Provider 的六種類型及其適用場景，提供使用 WindowForm 開發的規範（如 c,d 類型需用 .NET Framework 4.7）。詳述通用程式架構：DataProvider 處理請求、KafkaLogger 與 KafkaMessageProvider 負責日誌與訊息傳遞。並重點說明 MainForm.cs 中賽事清單取得、單一賽事抓取、移除過期比賽、心跳與自動重啟等主要流程。對 AI 開發的幫助：可據此實作新 Provider，整合到現有爬蟲與 Kafka 傳輸機制。

## 關鍵設計決策

- - 將 Provider 分為 a(完整資訊)、b(部分資訊)、c(無 API 需模擬瀏覽器)、d(混合 b,c)、e(Socket 接收)、f(ZBA 整合) 六類，新 Provider 應複製對應範例程式碼修改。
- 選用 WindowForm 開發，以便透過 Controller 自動更新與重啟。
- 模擬瀏覽器型 Provider (c,d 類) 因相容性限制，專案必須使用 .NET Framework 4.7，不可用 .NET 6。
- 一般 Provider 更新只需覆蓋 Z 槽對應目錄的 exe 與 pdb；c,d 類型首次部署須複製整個 bin/debug 目錄，後續僅覆蓋 exe、pdb。
- 程式架構採用 Kafka 輸出訊息，並在 Infrastructure/DataProvider 中實作 Heartbeat 至 Dashboard。
- MainForm 採用多執行緒設計：ExecuteAsync 讀取賽事清單，toGetSingleGame / toGetRBSingleGame 逐一抓取單一賽事，processGetGameData 解析並組裝 Kafka 訊息。
