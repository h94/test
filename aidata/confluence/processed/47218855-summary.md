## 摘要

這是一份 Sprint 管理流程手冊，定義了從需求估算、Sprint 建立、開發測試、Code Review、測試案例審查到 Release 與 Launch 的標準程序，並包含每日檢查清單。對 AI 開發的幫助在於理解團隊的開發節奏、品質把關點（如 Sonarqube、Gateway 配置、Swagger 更新）以及文件補齊的要求，可輔助自動化流程設計或知識庫建構。

---

## 關鍵業務規則

- - 新增 Service 或 API 接口時，必須檢查 Gateway 是否已有對應配置
- 新增 Service 或 API 接口時，必須修改對應的 swagger.json 文件
- 每日需確認成員確實填寫 JIRA Work Log
- 測試階段需監控 Bug 數量是否收斂
- 測試後期需請成員補齊分析文件
- 每日下班前確認 JIRA 問題和回覆都已填寫
- 若出現需要長期關注的線上問題，必須在 JIRA 上建立 Task 追蹤
