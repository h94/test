## 摘要


本文档是 GameService 的 WebAPI 技术设计，定义了查询合并主档（games/leagues/teams）和信息源原始数据（sitegames/siteleagues/siteteams）的 RESTful API 规范，以及过期数据清理端点。明确了路由结构、请求参数、响应格式、数据库表映射和 JOIN 规则，关键设计包括列表返回裸数组、无分页、时间区间默认当日、show_detail 控制字段详略。对 AI 开发可直接提供精确的 API 契约和业务规则，生成代码和测试用例。

---

## 關鍵業務規則


- - game_type 必须在白名单内（大小写不敏感），非法值返回 400
- 列表端点均返回裸数组 [...], 无外层 key，不提供分页（无 page/limit/next_page）
- 合并主档 games 列表 GET 查询支持 show_detail（默认 false），start/end 时间区间；未传 start/end 时默认当日 00:00~23:59；只传 start 则区间为 start ~ start 当日 23:59；只传 end 则为 end 当日 00:00 ~ end；两者都传则用参数值
- 单笔 GET（/{id}）始终返回完整字段，忽略 show_detail
- 信息源列表 GET 路径必须包含 {source} 参数（单个 source），Provider 层用 WHERE source = %s 筛选
- teams/siteteams/games/sitegames 的 league 字段由 JOIN 得到字串，DB create_at 映射为 API 字段 created_at
- gtime 统一返回 HH:MM 格式（不含秒），请求时间格式为 YYYY-MM-DD HH:MM（不要用 %20）
- 过期清理端点 clean_games 和 clean_sitegames 删除所有白名单球种中 gdate 超过 1 年（今日日期减 1 年）的数据，无 game_type 参数，成功返回 200 空 body
- 错误码：400（参数/白名单错误），404（id 不存在），409（唯一键冲突），422（FK 不存在），500（DB 异常）
- game_type 路径参数由 Service 层统一转为小写后拼接表名，Provider 层用白名单验证防止 SQL 注入

---

## 關鍵設計決策


- - 采用 Flask + flask-smorest 三層架构（Resources → Service → Provider），与 CommunityService 惯例一致
- 列表直接返回裸数组，不包裹在 JSON 对象中，简化客户端调用
- 信息源列表由 POST 改为 GET + query（v2.9），source 改为 path 参数，消除 body 查询方式
- 动态表名拼接：根据 game_type 动态生成 {table}_{game_type}，白名单验证确保安全性
- 第一阶段不实现认证，仅限内网服务间调用，降低初期复杂度
- games/sitegames 时间筛选逻辑复杂，提供了详细的默认值规则以满足业务常用查询场景
