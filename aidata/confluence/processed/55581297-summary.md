## 摘要

本文件定義了 TCZB 團隊 Sprint 的標準作業流程，從需求分析、開發、測試、部署到回顧的各階段步驟與檢查清單。對於 AI 開發，這份文件可作為自動化 sprint 管理工具的流程定義基礎，協助團隊確保每個 Sprint 的關鍵活動不被遺漏。文件包含具體的檢查項，如 JIRA Sprint 建立、Sonarqube 檢查、Code Review 確認、Gateway 和 Swagger 更新等，可用於設計自動化提醒或稽核規則。

---

## 關鍵業務規則

- - 在 Sprint 前第三日，SM 必須與需求方確認 Story，安排開發和測試分析，並請需求方講解需求，討論時程後公告。
- Sprint 前第二日，需建立 JIRA Sprint/Story/SubTask，建立 Confluence 需求分析頁面，建立 Git 分支，並執行 Sonarqube 取得警告數與 UT 覆蓋率。
- 若 Story 的 StoryPoint 為 13，必須召開 Design Review。
- Kickoff Meeting 時，必須估算 StoryPoint，安排 Release/Launch 負責人與 Code Review 人員。
- Code Review 時，需檢查 Review 內容是否都已被修改或記錄。
- 當有新增 Service 或 API 接口時，必須檢查 Gateway 是否已配置，並修改對應的 swagger.json。
- Launch 階段，必須安排人員合併主線、監控系統狀況，並要求成員填寫回顧會議內容。
- Sprint 結束時，需關閉 JIRA Sprint，並回報 PRD 監控結果。
