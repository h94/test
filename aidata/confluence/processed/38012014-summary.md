## 摘要

此文件定義了股票後台會員管理的 API 設計，包含對外接口 (memberservice) 和內部過水層 (pricebackendservice) 的六個端點：新增使用者、查詢使用者列表（含分頁、模糊搜尋、排序）、變更聯絡資訊、變更會員層級、變更密碼、變更啟用狀態。文件同時規範了帳號密碼格式、會員層級列舉、發送訊息方式以及分頁固定每頁 20 筆的業務規則，對 AI 開發 memberservice 或 pricebackendservice 的 API 實作與資料驗證邏輯有直接幫助。

---

## 關鍵業務規則

- - 會員帳號必須為 4~10 位英數字元。
- 會員密碼必須為 6~12 位英數及特殊符號字元。
- 會員層級 Rank 數值定義：0 未驗證會員、1 免費會員、2 付費會員、3 VIP會員。
- 發送訊息方式 SendAction 可為 'email'（電子信箱）或 'telegram'（Telegram）；'phone'（手機簡訊）暫不使用。
- 會員 Email 欄位不得為空。
- 取得全部會員列表使用分頁，每頁固定 20 筆資料 (pageSize=20)。
- 會員付費服務到期日 SubEndTime 格式為 'yyyy-MM-dd HH:mm:ss'，到期時間為當天 23:59:59。
- 新增會員時必須提供 Account、Password、Rank、Email、SubEndTime，且 Enabled 預設狀態未在請求中指定（推測後端可能預設值，需人工確認）。
- 變更聯絡資訊時，需提供 Account（於 URL 中，PriceBackendService 路徑為 /{account}），以及 SendAction 與對應的聯絡資料（Email 或 ChatID），Phone 欄位雖可提供但無實際作用。
- 變更會員層級時，需提供 Account（於 URL 中）及 Rank、SubEndTime。
- 變更會員密碼時，需提供 Account（於 URL 中）及新 Password。
- 變更會員啟用狀態時，需提供 Account（於 URL 中）及 Enabled (0 停用 / 1 啟用)。
- 查詢使用者列表支援以下選用過濾參數：account（模糊）、email（模糊）、enabled、rank；並支援排序欄位 sortCol（Account、Rank、AddTime、SubEndTime）及排序方式 sort（ASC/DESC）。

## 關鍵設計決策

- - 採用過水層架構：外部 API 掛在 memberservice 路徑下，實際邏輯由 pricebackendservice 處理，以隔離直接暴露後端服務。
- 變更資源類的 API（聯絡資訊、層級、密碼、啟用狀態）採用 PUT 方法，並將 Account 作為路徑參數（{account}），使 URI 更符合 REST 風格且避免在 body 中重複指定。
- 查詢列表 API 設計了豐富的查詢參數（模糊搜尋、過濾、排序），允許前端靈活獲取資料。
- 響應統一使用 MsgCode Model，包含 Code 與 Message 以標準化錯誤與成功回應。
