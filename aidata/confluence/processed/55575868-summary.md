## 摘要

本文件為球王站台功能的 API 規格書，涵蓋會員瀏覽人次寫入、會員預測注單查詢、大頭貼更新及莊家殺手結果查詢等端點。重點在於 API 的參數與回應格式定義，並包含部分業務規則，如大頭貼檔案限制。此文件可作為 AI 開發 predictservice 和 memberservice 時，實作對應端點與資料格式的參考依據。

---

## 關鍵業務規則

- - 大頭貼圖片大小限制在 100KB 以內。
- 大頭貼圖片格式限定為 png、jpeg。
- 更新會員大頭貼時，若 headShotFile 欄位不為 null，則使用上傳的圖片；若為 null，則使用預設的球衣圖片路徑。
- 呼叫取得使用者今日預測注單 API (predict/header/details/{authKey}/today) 時，無需再傳遞 Parameter gameType、lid。
- 呼叫取得會員今日預測注單 API (predict/header/{account}/today) 時，無需再傳遞 Parameter gameType、lid。

---

## 關鍵設計決策

- - 移除取得預測注單 API 的 gameType、lid 參數，簡化客戶端請求。推測是由後端根據使用者或全域設定決定查詢範圍。
- 會員瀏覽人數使用 Cassandra DB 的 gameuserviews 表格，以年 (year) 作為 partition key，日期 (datetime) 和會員 (account) 作為 clustering key，適合查詢特定年份下的使用者瀏覽紀錄。
- 更新大頭貼 API 從 POST 改為 PUT，使其符合 RESTful 風格，更準確地表達更新操作。
- 解鎖會員鎖定預測賽事 API 從 predict/lockgames/{gameType}/{account}/unlock/{authKey} 簡化為 predict/lockgames/{account}/unlock/{authKey}，移除路徑中的 gameType 參數。
- 策略目標為移除未使用的多餘程式碼，保持服務架構乾淨。

- ⚠️ 主客隊隊徽 teamLogo 的 JSON 結構中，key 名為 'player1'，但內容是球隊隊徽資訊，此命名可能造成混淆。
- ⚠️ 大頭貼上傳若檔案為空 (null) 則使用預設球衣，但未說明如果上傳了不符合規範的檔案（如超過大小或格式錯誤）應如何回應。
- ⚠️ 資料庫欄位 year 和 datetime 皆使用 text 型別，在進行範圍或排序查詢時可能有效能疑慮，需人工確認如此設計的原因。
