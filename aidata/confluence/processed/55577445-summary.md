## 摘要

這份文件定義了大發體育 (dafabet) 爬蟲的 API 請求格式與資料映射規則。主要說明如何組合 Payload 呼叫三個核心 API（事件資料、PBP 比分板）來取得完整的比賽、賠率與節數分數資料。文件中提供了關鍵的球種 ID 對照表、Feedcode 路由規則，以及從 API 回應中解析主客隊分數、聯賽資訊所需的 JSON 欄位路徑（Mapping），是實作 dafabet 爬蟲流程的必要技術規格書。

## 關鍵設計決策

- - 為了統一處理滾球與非滾球賽事，決定在請求事件資料 API 時固定將 periodType 設為 PRE_MATCH，並透過 includeLiveEvents 參數來控制是否輸出進行中的比賽。
- 為了解決部分球種在事件 API 中只能取得總分而無法取得各節分數的問題，決定額外引入兩支 PBP (Play-by-Play) API (nextbet / akamaized)，透過 feedcode 前綴碼來路由請求以補齊每節分數資料。
- 定義了 API 請求中僅允許動態調整的參數（eventPathIds, page, eventsPerPage, includeLiveEvents, dateTo），簡化了爬蟲邏輯中的可變因子控制。

## 注意事項

- ⚠️ - ⚠️ 需人工確認：文件中的 API Payload 範例註解提到 dateTo 用於限制比賽時間區間，但備註又寫「只有要抓正在打的比賽時才要加這個欄位」，兩者對於 dateTo 的使用時機不完全一致（過濾時間 vs 過濾狀態），實作時需釐清確切邏輯。
- ⚠️ 易誤解處：PBP API 使用到的球種 ID (sportId) 明確標注「不等於站台的球種 ID」，AI 開發時不可混用，需建立獨立的映射關係。
- ⚠️ 易誤解處：文件中提及 Feedcode 如果開頭為 1 用 nextbet 路由，開頭為 4 用 akamaized。雖然籃球範例 Feedcode 截圖看起來是 1 開頭，但需確認實際情況是否包含 2,3 等其他前綴的處理方式。
