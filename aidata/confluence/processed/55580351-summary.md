## 摘要

本文件記錄了 TCZB 團隊在 Sprint 173 期間所使用的 Sprint 管理流程，涵蓋從時程估算、JIRA 建立、需求分析、開發測試、上線到回顧的各階段工作項目與每日檢查清單。對 AI 開發而言，可藉此理解團隊協作節奏與檢查點，用於建置自動化流程提醒或開發輔助工具。

---

## 關鍵業務規則

- - Day(-3) 需與需求方確認 Story、安排開發測試分析並請需求方講解需求。
- Day(-2) 需建立 JIRA Sprint/Story/SubTask、Confluence 需求分析頁面及 Git 分支，並執行 Sonarqube 取得警告數及 UT 覆蓋率。
- 若 Story 點數達 13，需召開 Design Review 會議。
- Kickoff Meeting 需估算 StoryPoint、安排 Release/Launch 負責人與 Code Review 人員。
- Release 階段若新增 Service/API 接口，必須檢查 Gateway 配置，並修改對應的 swagger.json。
- Code Review 內容必須被全數修改或記錄。
- Sprint 結束時需關閉 JIRA Sprint 並回報 PRD 監控結果。
