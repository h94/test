## 摘要

這是一份排行榜功能的早期規劃筆記，定義了前後端架構與資料庫設計。對 AI 開發而言，此文件提供了 leaderboardservice 的核心資料模型（charts、templates、users 三張表）、API 職責劃分（會員帳號歸 memberservice、排行榜資料歸 leaderboardservice）、以及前端 JS 動態渲染排行榜的客戶端整合方式。可作為理解排行榜功能邊界與資料流的參考。

---

## 關鍵業務規則

- - 排行榜後台帳號分為兩級：管理帳號（Rank=1）可新增公司帳號、修改公司帳號密碼；公司帳號（Rank=2）可新增排行榜、修改排行榜、修改自己的密碼
- 管理帳號和公司帳號沒有子帳號，一個帳號只對應一個層級
- 排行榜資料來源分為「api」和「檔案」兩種，檔案來源格式為 CSV
- 排行榜畫面樣式有 5 種可選，且能自訂版面配色
- 新增排行榜後會生成一個 token，客戶端透過 token 取得排行榜資料與畫面

---

## 關鍵設計決策

- - 前端渲染方式：客戶端引用我方提供的 JS 檔案，由 JS 呼叫 API 取得排行榜資料與樣式後，在客戶端動態渲染 HTML/CSS，而非 server-side rendering
- JS 檔案部署：直接寫好上傳到網路空間（https://www.zbdigital.net/js/xxxx.js），不走即時打包
- 資料來源分離：排行榜的「資料」與「樣式」分開儲存與呼叫（先取資料、再取樣式，由中介層組合後回傳）
- 資料庫設計：charts 表同時儲存「現在排行榜內容」與「上一次排行榜內容」，用於顯示排名變化（目前排名 vs 上次排名）
- 樣式自訂機制：templates 表的 EditClass 欄位定義哪些 CSS class 可被修改，DefaultClass 定義預設值，charts 表的 Style 欄位儲存使用者自訂的 CSS 覆蓋值
