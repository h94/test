## 摘要

本文件定義 ASCbet 爬蟲的重構技術細節：列出賽前/賽中 API 端點與 payload，說明取得 cookie 的流程，提供 SportID 對照表，並詳細規範比賽基本資訊、比分、playbyplay 的 parser 欄位（從 match 陣列依索引取值與 split 處理）。同時記錄多球種的賠率結構（讓分、大小、半場等）與特例玩法（如足球角球、籃球各節讓分），並以 appsetting 配置各球種的賠率欄位索引與玩法映射。爬蟲開發時可直接依此構建資料擷取與標準化邏輯。

---

## 關鍵業務規則

- - SportID 與運動類型對應：1=SC, 2=BK, 3=FL, 4=BS, 5=HL, 7=TN, 9=TB, 11=CK, 12=VB, 13=HB, 17=SN, 20=DT, 21=MA, 26=ES
- 取得資料前必須先以 session.get('https://www.ascbet.net/asc/PublicMain.aspx') 取得 cookie
- 賽前 API (NLive.aspx) 的 Stage 參數可為 1,2,4；賽中 API (Live.aspx) 的 Stage 固定為 3
- 遊戲基本資訊從 match 陣列解析，其中 team_home/away 與 ID 需以 '|' 做 split
- 比賽日期時間（match[6]）需額外拆分為日期與時間兩個欄位
- 比分欄位：score_home 為 match[13]、score_away 為 match[14]；目前觀察無分節分數
- playbyplay 取自 match[7]，足球包含節數與時間，其他球種待觀察
- 通用賠率結構包含 HA(1X2,讓分), OU(大小), Others-HalfHA, Others-HalfOU，並有多組 match 索引對應
- 各球種特定玩法是否採集已明確規範，例如：SC 角球讓分/大小、第一角球要採集；BK 第一至第四節讓分要採集；多數球種的「總比賽勝利數」不採集；MA 公斤級冠軍不採集（詳見內文表格）
- 足球另有「角球數」「第一角球」「罰牌」「第一張罰牌」等玩法區塊，籃球有各節讓分/大小

---

## 關鍵設計決策

- - 選用 POST 方式呼叫 ASCbet 的 Live/NLive API，並以固定 payload 傳遞 SportID、OddsStyle、Stage 等參數，透過 Stage 區分賽前/賽中
- 資料解析採用 match 陣列索引對應欄位，簡化 parser 實作
- 針對不同球種的賠率欄位索引與玩法組合，定義在 AppSetting 結構中，使爬蟲可透過設定檔驅動，提升可維護性
- 特殊玩法（如 BK 各節讓分、SC 角球）以獨立區塊描述，允許針對特定球種客製擴展
