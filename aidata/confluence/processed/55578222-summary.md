## 摘要

本文件提供一個為期 12 天的 Sprint 標準時程與每日檢查清單，從需求分析、Kickoff、編碼、測試到發佈及回顧等階段均有明確步驟。對 AI 開發的幫助在於了解團隊協作節奏與發佈流程，但未涉及服務的業務邏輯或技術細節。

---

## 關鍵業務規則

- - Day(-3) 前需與需求方確認 Story、安排開發與測試分析、討論時程並公告
- Day(-2) 需建立 JIRA Sprint/Story/SubTask、Confluence 需求分析頁面、Git 分支，並執行 Sonarqube 取得警告數與單元測試覆蓋率
- Story 點數為 13 時必須召開 Design Review
- 新增 Service 或 API 接口時，必須檢查 Gateway 配置並修改對應的 swagger.json 文件
- 測試階段需監控 Bug 數是否收斂，並要求成員補齊分析文件
- Release 責任人需確保所有 Code Review 內容已被修改或記錄
- 每日管理需確認成員填寫 JIRA Work Log、回覆問題，並於上線後監控系統狀況
