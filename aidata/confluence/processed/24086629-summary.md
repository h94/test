## 摘要

本文档设计了联盟战绩数据的三个视图（总览、一对一、积分榜）及其数据格式，但注明总览和积分榜未实现。重点定义了一对一视图的 JSON 结构（包含队伍近况、近期交战记录、赛前赛程等），并给出了棒球积分榜数据库表结构与新增/编辑 Overview 的 API 端点。前端通过直接读取预生成的静态 JSON 文件来降低逻辑复杂度，文件路径采用日期和联盟 ID 组织。对开发 pricecenterservice 而言，本文提供了明确的 API 契约和数据规约，是生成联盟战绩数据功能的技术底座。

---

## 關鍵業務規則

- - 一对一页面仅需展示用户选定的 A 队与 B 队数据，无需提供其他队伍选择功能
- 部分较大的联盟数据直接爬取官网获取（而非内部计算）

---

## 關鍵設計決策

- - 前端每个页面仅读取一个预生成的 JSON 文件，以减少前端逻辑动作（决策来源：问题列表中的问答）
- JSON 文件按日期和联盟 ID 分目录存放，如 downloads/BS/20211005/联盟ID/...，便于静态发布与缓存
- 一对一视图的 JSON 文件名使用 gameid.json，包含 Status、RecentGame、BeforeGame、AfterGame 四个主要区块
- 新增/编辑 Overview 使用 POST /overview 端点，接收数组格式的积分榜数据以便批量处理
- 数据库存储棒球积分榜数据（表未命名，但字段为 site, sitelid, sitetid, partition, gdate, win, lose, draw, pct, rs, ra），以文本或整数存储
