## 摘要

本文件定義了一個 Sprint 從預估、需求分析、開發、測試、上線到回顧的完整流程與每日檢查清單。內容包含各階段（如 Kickoff、Code Review、Release）的必要任務與時間點（Day -3 至 Day 12），可作為 AI 輔助 Sprint 管理時自動化提醒、檢查項目完成度及流程合規性判斷的依據。

---

## 關鍵業務規則

- - Sprint 開始前第 3 天需完成與需求方確認 Story、安排分析、請需求方講解需求及公告時程。
- Sprint 開始前第 2 天需建立 JIRA Sprint/Story/SubTask、Confluence 需求分析頁、Git 分支，並執行 Sonarqube 取得警告數及 UT 覆蓋率。
- 若 Story 的 StoryPoint 為 13，需召開 Design Review。
- Kickoff Meeting (Day 0) 需估算 StoryPoint、安排 Release/Launch 負責人及 Code Review 人員。
- Code Review (Day 4) 後須檢查 Review 內容皆已修改或紀錄。
- 釋出版本 (Release, Day 9) 時，若有新增 Service 或 API 接口，需檢查 Gateway 配置並修改對應的 swagger.json。
- 上線 (Launch, Day 10) 需安排人員 Merge 主線、監控上線系統狀況，並請成員填寫回顧會議內容。
- Sprint 結束 (Day 12) 需關閉 JIRA Sprint 並回報 PRD 監控結果。
- 每日檢查清單包含：Daily Meeting 回報進度、確認 JIRA Work Log 填寫、測試階段注意 Bug 收斂、測試後期補齊分析文件、下班前確認 JIRA 問題回覆、線上問題長期關注需開 JIRA Task。
