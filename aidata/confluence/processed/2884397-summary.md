## 摘要

本文件定義 LiveChat 服務的資料庫表格結構（Tokens、MessageLogs、Logs、QuickMessages、HelloMessages、Feedbacks、IssueType）及 Redis 鍵值設計（LiveChat_{CompanyCode}、LiveChat_Channel_{ConnectID} 等），說明每個欄位的資料型態與用途，例如 Token 會話管理、訊息記錄、快速回覆分類、回應評分等。對 AI 開發能快速了解持久層與快取層設計，有助於實作資料存取邏輯。

## 關鍵設計決策

- - 連線與使用者會話以 Tokens 表管理，以 HashKey 為主鍵，儲存 CompanyCode、AddTime、Enabled、UserData、UsedTime、ConnectID、IP，其中 CompanyCode 來自 Gateway Header X-Company。
- 訊息記錄 MessageLogs 關聯 Token 的 HashKey 與 ConnectID，記錄內容、使用者資料、接聽客服 Agents（多人以逗號分隔）、客戶端環境資訊（Location、Device、OS、Browser、Service）。
- 快速回覆 QuickMessages 依 CompanyCode 與 GroupType（Common/Payment/Application/CS）分類，支援啟用與停用。
- 公司迎賓訊息 HelloMessages 每個 CompanyCode 僅有一筆（CompanyCode 為 PK）。
- 使用者回饋 Feedbacks 關聯 ConnectID（SignalRID），評分範圍 1~10，並可輸入意見。
- 問題類型 IssueType 按 CompanyCode 劃分，支援新增、編輯、啟用與停用。
- Redis 設計使用 Set 集合與 Char 字串快取資料：LiveChat_{CompanyCode} 儲存線上使用者與狀態資訊；LiveChat_Channel_{ConnectID} 儲存特定通道內容；LiveChat_IssueType_{CompanyCode} 快取問題類型；LiveChat_QuickMessages_{CompanyCode}_{GroupType} 快取快速回覆；LiveChat_HelloMessages_{CompanyCode} 快取迎賓訊息；但未定義 TTL。
- Logs 表記錄 Token 或用戶的操作動作（Action、User、AddTime），用於後續行為追蹤。
