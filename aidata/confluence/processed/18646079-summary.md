## 摘要

该文档定义了 Python 数值分析服务需要通过 PriceCenterService 获取的数据及使用规则。核心包括：支持 BK、BS、SC 三类游戏，按 inplay/pregame 分成六种配置；数据获取优先选择 bet365 站点，无则降级到 ku888（pregame 不需要 match）；只拉取 HA/OU/RBHA/RBOU 四种 odd history 模式用于后续公式计算；最终合并所有 site game 生成一张图表，图表纵轴参数因球种而异（BK/BS 取 Spread 且 Main=true，SC 取 OddValue 且 Main=true），且部分计算逻辑标记为后续 sprint 实现。此外，要求 pregame 和 inplay 图片分开、添加浮水印。

---

## 關鍵業務規則

- - Python docker 应根据 GameType(SC, BS, BK) 和 inplay/pregame 分为 3×2=6 种配置，各自设定不同的执行间隔
- 站点清单为 bet365.com, ku888, pinnacle.com, betfair.com, twsl, bwin.com
- Odd history 数据仅需拉取 HA / OU / RBHA / RBOU 四种模式，若有多个 HA、OU 则全部给出，供后续公式换算使用
- Match 数据优先使用 bet365，无 bet365 时才使用 ku888；pregame 阶段不需要 match 数据
- 根据 game 获取所有 site game 后，需合并数据并输出为一张图，仅包含成功合并的赛事
- 画图参数：BK 时横轴为时间，纵轴为 Odd 的 Spread 且 Main=true；BS 时横轴为时间，纵轴为 Spread 且 Main=true（需公式换算，待后续 Sprint）；SC 时横轴为时间，纵轴为 OddValue 且 Main=true（需公式换算，待后续 Sprint）
- 比分差和比分合暂时直接相加相减（需公式换算，待后续 Sprint）
- pregame 和 inplay 的图表文件需分开生成
- 图表必须添加浮水印

---

## 關鍵設計決策

- - 采用 6 种独立的 docker 配置来隔离不同游戏类型和比赛状态的执行频率
- 数据源优先选择 bet365，确保稳定性和数据质量
- 合并所有 site game 后再生成单张图片，保证数据完整性
