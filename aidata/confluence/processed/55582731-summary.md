## 摘要

本文件定義了 CrawlerAgentAipredict 從四個外部網站（sportsline、oddstrader、dimers、picksandparlays）爬取 NBA AI 預測資料的技術實作細節。對 AI 開發而言，讀完這篇你會知道：(1) 如何用 page_type 區分不同資料來源並交給 DataTransformer 處理；(2) 各網站 AI 預測的大小分（total）與讓分（handicap）在 JSON 中的確切欄位路徑與解析規則；(3) game_id 的組合規則（league + 主客隊 + 日期時間），這是跨系統比對比賽資料的關鍵鍵值。

## 關鍵設計決策

- - 使用 page_type 參數（即網站名稱）讓 DataTransformer 區分不同資料來源的解析邏輯，而非在 DataProvider 中直接解析，將爬取與解析責任分離
- league 參數採用「網站名稱_聯盟名稱」組合（如 sportsline_NBA），以區隔不同網站但相同聯盟的資料
- game_id 由 league、team_home、team_away、game_date、game_time 五個欄位組合而成，作為比賽的唯一識別鍵
- other_info 欄位以 JSON 格式儲存 AI 預測結果，包含 predict_OU（大小分數值）、predict_HA（讓分數值）、bet_OU（大小分方向 Over/Under）
- sportsline：從 HTML 內嵌的 competitions JSON 區塊提取比賽清單，使用 homeTeamName + homeTeamNickName 組合成完整隊名，gameStartDtStamp 需轉換時區
- oddstrader：從 window.__INITIAL_STATE__ 全域變數提取 picks 與 events 資料，判斷 idty==402 取 AI 大小分預測、idty==401 且 paid 有值取讓分預測；bet_OU 從 stat 欄位取 '-' 後的值作為方向
- dimers：從特殊 JSON 結構（rt:json 標記區塊）提取比賽資料，隊名由 Market + Nickname 組成；type==total 取 markValue 為大小分、type==line 取 lineValue 為讓分；bet_OU 取 bet 欄位值
- picksandparlays：透過 API 直接獲取 JSON（非 HTML 解析），URL 參數 rangeStart/rangeEnd 控制分頁；讓分與大小分只會出現其中一個，皆取 pick.value

## 注意事項

- ⚠️ - ⚠️ picksandparlays 的 URL rangeStart=0&rangeEnd=4 看起來是測試用的分頁範圍，正式環境可能需要調整，需人工確認
- ⚠️ 四個資料來源的網站皆為外部第三方，HTML 結構或 API 格式隨時可能變動而導致爬取失敗，此為爬蟲的潛在風險
- ⚠️ bet_OU 欄位在文件中註明是「測試時需要」，正式環境是否仍需要此欄位需人工確認
