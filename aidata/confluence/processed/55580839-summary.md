## 摘要

本文件定義了 TCZB 團隊一個 Sprint 的完整流程，包含從估算、需求分析、開發、測試到釋出與回顧的各階段時間點與檢查清單。對於 AI 開發來說，可了解團隊在 Sprint 中必須執行的步驟與注意事項，例如新增 API 需檢查 Gateway 配置、更新 Swagger 文件、StoryPoint=13 需進行 Design Review 等，確保開發過程符合團隊規範。

---

## 關鍵業務規則

- - 每日召開 Daily Meeting 了解成員問題，判斷是否影響時程，並盡快回報上級
- 每日確認成員確實填寫 JIRA Work Log
- 測試階段要注意 Bug 數是否收斂
- 測試後期請成員補齊分析文件
- 下班前確認 JIRA 問題和回覆都有填寫
- 如有線上問題需要長期關注，應於 JIRA 上開 Task 監督狀況
- Story 項目較大時（StoryPoint=13）需召開 Design Review
- 如有新增 Service / API 接口，要檢查 Gateway 是否有配置
- 新增 Service / API 接口，要修改對應的 swagger.json
