## 摘要

本文件定義 CommunityService 中「文章置頂」功能的兩個 REST API：PUT 端點可批次更新多篇文章的置頂狀態（top=true 置頂、top=false 解除），GET 端點可取得指定球種所有置頂文章。後端實作時需檢查每筆請求的 top 值與資料庫現狀是否相同，僅對狀態有變更的文章執行更新，以確保冪等性。這份設計可協助 AI 開發者正確實作置頂文章的讀寫邏輯與 API 合約。

---

## 關鍵業務規則

- - 更新文章置頂狀態時（PUT 請求），後端必須逐一檢查每個 id 目前的 top 值，僅在與請求中的 top 值不同時才執行更新
- top 欄位為 true 代表將文章設為置頂，false 代表解除置頂
- GET /gameType/get_top_articles 回傳該球種下所有 top=true 的文章

---

## 關鍵設計決策

- - 採用批次 PUT 單一端點同時處理多篇文章的置頂/解除，減少了前後端多次請求的複雜度
- API 路由設計將 gameType 作為路徑參數，使置頂文章範圍按球種隔離

## 注意事項

- ⚠️ - ⚠️ 文件中未提及置頂文章的權限控制或驗證機制，需人工確認呼叫方是否有權限操作
- ⚠️ PUT 端點的 request body 範例為陣列，但未標註 Content-Type，需確認是否為 application/json
- ⚠️ 開發時需注意冪等性：僅更新狀態有變化的文章，避免不必要的寫入
