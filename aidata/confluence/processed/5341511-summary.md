## 摘要

本文旨在說明 PriceCenterService 相關的系統互動流程，但大部分章節內容缺失。唯一有完整內容的 MLB Parser 時序圖描述了從 ZooKeeper 取得設定、透過 DataProvider 呼叫外部 API 取得MLB比賽資料、經過 Parser 過濾與儲存、最後由 MLBService 比對新舊資料並將新資料推送給 nginx 的完整流程。此圖對 AI 開發的幫助在於理解 MLB 資料的獲取、處理與分發管線，以及各元件間的職責劃分。

## 關鍵設計決策

- - 資料獲取分兩階段進行：先取得時間範圍內的所有比賽 (Get All Game Data Within Time Range)，再針對每場比賽取得詳細資料 (Get Match Data for each match)。
- MLBService 會將新資料與記憶體中的 dictionary 進行比對，達成增量更新 (compare new match data with data in dictionary, and update dictionary)。
- 採用 ZooKeeper 進行組態推送，服務啟動時會從 ZooKeeper 取得設定。
- API 呼叫失敗時，DataProvider 會將錯誤日誌寫入 MQueue，而非直接拋出異常中斷流程。
