## 摘要

這是一份 GS 營運版專案（InplayZ）的啟動需求文件，說明了從既有 GameSettingFrontEndTools 繼承後的變更範圍。核心變動包括：會員系統新增公司代號與 admin/trader 角色、登入頁增加公司代號欄位；新增帳號管理功能讓 admin 管理子帳號（含停啟用、新增、修改密碼）；賽事查詢頁改為依帳號訂閱內容顯示球種與玩法選項；以及全局 API 遇到「Login information does not exist」錯誤時強制登出的安全機制。對 AI 開發而言，這份文件定義了新專案的權限模型、訂閱內容與選項的關聯規則，以及錯誤處理的統一規範。

---

## 關鍵業務規則

- - 會員登入頁需新增「公司代號」欄位，作為登入必要資訊。
- 會員需新增「公司代號」與「角色」屬性，角色固定分為 admin 與 trader。
- 當任何 API 返回 Error: Login information does not exist 時，系統必須清除登入資料並強制登出使用者。
- 帳號管理功能僅限 admin 角色可見與操作，可查看所有子帳號的帳號、角色、狀態，並進行停用/啟用、新增子帳號、修改子帳號密碼。
- 球種與玩法選項不再顯示全部，必須根據當前帳號的訂閱內容（額外玩法、訂閱球種、訂閱到期日）動態過濾顯示。
- 站台賽事資訊更名為賽事查詢，移除站台搜尋欄位，移除表格中的「察看詳細資料」按鈕與「球頭」欄位。
- 站台聯盟的賽事列表頁需刪除，其連結也需一併移除。
- 合併賽事資訊頁面需完全移除。

---

## 關鍵設計決策

- - 專案代號命名為 InplayZ，繼承 GameSettingFrontEndTools 現有進度進行改造，而非從零開始，以加速 GS 營運版開發。
- 調整站台賽事詳細資料、聯盟資訊、隊伍詳細資料、賽事賠率紀錄等多個既有頁面的 API 調用與網址結構，推測是配合營運版的後端 API 路徑或站台 ID 規則變更。
- 選擇移除合併賽事資訊頁面與賽事列表頁，而非保留隱藏，代表這些功能在 GS 營運版被認定為冗餘。
