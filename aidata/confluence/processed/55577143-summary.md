## 摘要

本文件為 Sprint 執行流程的操作指引，包含每日檢查清單（Daily CheckList）與從日程估計到 Sprint 關閉的 14 個階段性步驟。內容涵蓋 Sprint 籌備、需求分析、開發、測試、發佈與回顧等任務核對項，確保團隊按規範完成 JIRA 管理、Code Review、Gateway 配置及 Swagger 更新等工作。作為流程模板，可用於自動化 Sprint 管理或提醒機制。

---

## 關鍵業務規則

- - 如有新增 Service 或 API 接口，Release 階段必須檢查 Gateway 是否已配置（步驟 #19）。
- 新增 Service 或 API 接口時，必須修改對應的 swagger.json 文件（步驟 #20）。
- 在 Create JIRA Sprint 階段需執行 Sonarqube 取得警告數和 UT 覆蓋率作為初始品質基準（步驟 #9）。
- Story Point 為 13 的 Story 必須召開 Design Review（步驟 #10）。
- Kickoff Meeting 中需安排 Release/Launch 負責人及 Code Review 人員（步驟 #15、#16）。
- 每日需確認所有成員確實填寫 JIRA Work Log（Daily CheckList #2）；測試階段須關注 Bug 收斂狀況（#3）；測試後期須要求成員補齊分析文件（#4）；下班前確認 JIRA 問題回覆均已填寫（#5）；如有線上問題需長期關注則在 JIRA 開 Task 監督（#6）。
