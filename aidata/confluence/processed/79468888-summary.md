## 摘要

文件描述 OpenclawService 的賽事合併功能，提供兩支 GET API 分別查詢 games 與 sitegames（含聯盟、隊伍多語翻譯），供外部系統「龍蝦」排程取得資料並以模糊比對進行合併，結果按球種回傳並寫入 PRD DB 新表 openclaw_merge_<game_type>。合併比對依賴詞集關鍵字匹配，容許時間差 10-15 分鐘，支援主客隊互換辨識；早期嘗試 GPT 合併因效果不佳而棄用，現改為本地腳本透過 Windows 排程全自動執行，不消耗 token。文中記錄了兩個主要難點：聯盟名稱過長導致誤匹配，以及非英文名稱缺乏翻譯，目前僅能手動觸發翻譯快取。對 AI 開發而言，本文定義了合併服務的 API 合約、資料格式、排程規則與已知限制，可作為維護與增強的基礎。

---

## 關鍵業務規則

- - 定時任務每整點執行一次，處理從當前整點到隔天同一整點之間每小時的資料（例如 16:00 執行，處理 16:00-17:00、17:00-18:00... 直到隔天 15:00-16:00，共 12 個小時）。
- /api/merge/games 與 /api/merge/sitegames 均透過 query 參數 date、start_time、end_time 過濾，一次性返回該時段所有球種的比賽資料。
- 合併結果為 dict，key 為 game_type（球種代碼如 SC、BK），value 為合併物件陣列；每個合併物件包含 source_id、gdate、lid、targets 陣列，targets 中 site、sitegdate、sitegid 為對應的站台資訊，swap 布林值表示主客隊是否與 games 相反。
- 合併邏輯採用模糊比對，將聯盟名稱與隊伍名稱拆分為關鍵字集後比對（單詞順序不影響相似度），時間相近 10-15 分鐘視為相同；若名稱相似度不足，不強行對應。
- 若站台的聯盟名稱過長（如包含完整聯賽名稱）或僅含非英文名稱且無英文 name_map，可能無法成功匹配；目前只能透過手動通知龍蝦觸發翻譯快取，無法自動處理。
- 寫入合併結果使用 POST /api/merge/pending-result/<game_type>，JSON body 為該球種下的合併物件陣列，資料存入 PRD DB 新表 openclaw_merge_<game_type>。

## 關鍵設計決策

- - 捨棄 GPT 合併方案，採用龍蝦本地執行模糊比對，因早期 GPT 測試結果不佳且消耗 token，改為本地批次處理以實現零 token 成本全自動化。
- 透過 Windows 排程器觸發腳本，每個整點執行一次，將整個流程封裝為獨立排程任務，無需外部服務觸發。
- 每次僅查詢一小時範圍的資料（共 12 次循環），避免單次資料量過大，並與最終排程的粒度一致。（最初設計為每次兩小時，後續修改為一小時，以排程描述為準）
- 合併結果獨立儲存於新表 openclaw_merge_<game_type>，以 gdate、lid、id 為分區鍵和叢集鍵，支援按日期和賽事快速查詢歷史合併記錄。
- 對於非英文名稱翻譯障礙，提供手動觸發的翻譯快取機制（透過龍蝦訊息請求），但不內建自動翻譯，以簡化系統架構並避免依賴外部翻譯 API 的限制。

## 注意事項

- ⚠️ - ⚠️ 時間範圍規則有不一致：前半段描述「每次拿兩小時的資料」，後半段給龍蝦的指示為「一次只拿一個小時的資料」，最終排程採用後者；需確認並統一口徑。
- ⚠️ GPT 合併方案已棄用，但文件中仍保留其 prompt、API key 位置等資訊，開發時不應依賴或實作此路徑。
- ⚠️ 合併結果寫入 PRD DB，IP 192.168.55.80，表名 openclaw_merge_<game_type>，CQL 範例為 test_openclaw_merge_SC，正式表結構可能略有差異，需與實際 DB 對照。
- ⚠️ 聯盟名稱過長或非英文名稱無法自動化處理，屬於已知缺陷，需評估是否投入自動翻譯或改善比對演算法，否則合併涵蓋率受限。
- ⚠️ 文中所有 IP 位址（55.87、55.80）為內網環境，外部開發需透過 VPN 或對應叢集 IP 訪問。
