## 摘要

本文件定義一個爬蟲（CrawlerAgentPleague）從 P. League+ 官網抓取比賽資料的技術規範。內容說明了從賽程頁面提取比賽詳細頁面 URL 的方法，以及從比賽頁面中透過正則表達式擷取比賽狀態、聯盟資訊、主客隊、日期時間、比賽 ID 與各節分數等欄位的規則。對 AI 開發而言，這份文件提供了完整且可執行的資料擷取邏輯，能直接指導爬蟲模組的實作，確保資料欄位格式與映射關係正確。

---

## 關鍵業務規則

- - 比賽狀態值映射: HTML 中的「尚未開始」→ '2', 「LIVE」→ '0', 「已完賽」→ '1'。
- 聯盟名稱映射: HTML 中擷取的 'PLG' → 'Plus League', 'EASL' → '東亞超級聯賽'。
- game_id 組合規則: {league_id}_{比賽日期年份}_{從 window.gid 擷取的數字 ID}，例如 EASL_2025_55。
- 每節分數擷取規則: 依序匹配多個 <td class="score_home"> 與 <td class="score_away">，組合成 (主隊分數, 客隊分數) 的 tuple 列表，以反映各節比數（通常為 4 節）。
- 比賽詳細頁面 URL 規則: 從賽程頁中擷取所有符合模式 <a href="(?=/game/|/easl/)(.*?\d+)" class 的連結作為標的頁面。

---

## 關鍵設計決策

- - 選擇解析 HTML 而非使用結構化 API：因為目標網站未提供正式 JSON API，故以 HTML 匹配正則表達式提取資料，需注意網站改版風險。
- 入口設計：以多個 schedule 頁面（熱身賽、例行賽、季後賽、冠軍賽、EASL）為清單來源，再逐一爬取比賽細節，可完整涵蓋所有賽事類型。
- game_id 組合設計：使用人工可讀的格式（聯盟代碼_年份_ID），以便於後續資料庫儲存與人工識別，且保證唯一性。
- 分數結構設計：將各節分數以有序 tuple 列表儲存，保持比賽進程的節次資訊，適合後續統計分析。

## 注意事項

- ⚠️ - ⚠️ 爬蟲依賴官網 HTML 結構，若 PLG 網站改版，本文件的正則表達式可能失效，需定期維護。
- ⚠️ 比賽狀態的對應值（'2','0','1'）未見於官網文件，為內部約定，需與消費端資料庫設計一致。
- ⚠️ 聯盟名稱映射目前僅有 PLG 與 EASL，若未來新增其他聯盟（如跨國聯賽），爬蟲需額外擴充。
