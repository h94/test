## 摘要


本文件定義新運彩水桶禁言與訊息中心通知兩大功能，指定 MemberService 為核心資料服務，NewLotteryBackEndService 為後台 BFF，NewLotterySite 為前台 BFF。明確水桶名單前必須檢查同一帳號僅能有一筆 active 記錄、endtime 固定格式且不得為空（無永久禁言），並規範通知主題與文章採用 soft delete、多語系欄位統一使用 zh-TW/en-US key、GET 訊息端點須支援 tid 過濾。所有設計決策均已確認，可直接指導相關微服務的 API 與資料庫開發。

---

## 關鍵業務規則


- - 水桶名單同一帳號最多只能有一筆 active（未到期）記錄；新增前必須檢查是否存在未到期的記錄。
- 水桶 endtime 為 text 型別，格式嚴格為 yyyy-MM-dd HH:mm:ss，必須有值，不允許空值或永久禁言。
- 發文時的水桶檢核直接查詢 Cassandra newlottery_banned 表，不引入 Redis 快取。
- 通知主題與文章採用 soft delete：刪除時將 enabled 設為 0，前端查詢一律過濾 enabled=1。
- 通知相關多語系欄位（names, titles, contents）的 map key 一律使用 zh-TW 與 en-US，前後端不得混用其他格式（如 zh_Hant）。
- 現有 GET /api/v1/newlottery/notification/messages 必須加上 tid query param，以便依主題過濾文章，不得回傳全部訊息。
- 所有新運彩後台 API 路由格式均沿用 /api/v1/newlottery/... 慣例。

---

## 關鍵設計決策


- - 水桶名單 newlottery_banned 與既有的 gameusers_banned 獨立運作，兩表不相混用，避免跨系統干擾。
- 通知刪除採用 enabled=0 的 soft delete 策略，不提供實體 DELETE 端點，以保留資料與操作紀錄。
- 在現有 GET messages 端點擴充 tid 查詢參數，而不另外建立新端點，簡化 API 設計並維持一致性。
- 後台管理工具 newlotterytools 不直接呼叫 MemberService，統一透過 NewLotteryBackEndService 轉發，確保後台 BFF 層的介接控制。

---

## 注意事項


- ⚠️ - ⚠️ endtime 為 text 類型，格式固定為 yyyy-MM-dd HH:mm:ss，非 Unix timestamp 或 datetime 物件，輸出入時需嚴格轉換。
- ⚠️ 同一帳號僅允許一筆 active ban，新增時必須檢查未到期記錄，否則可能產生重複禁言導致混亂。
- ⚠️ 多語系 map key 不得使用 zh_Hant、zh-TW2 等變體，使用不一致會造成前端無法正確顯示。
- ⚠️ 前台查詢通知主題與文章若未過濾 enabled=1，會將已停用內容顯示給使用者。
- ⚠️ 文件中已確認 Q&A（如無永久禁言、無 Redis 快取、tid 過濾等），開發時應視為最終決策，不可再另闢設計。
