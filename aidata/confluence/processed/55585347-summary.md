## 摘要

此文件為 90vs 爬蟲提供者的程式碼審查結果，列出多項修正要求：包括 AppSetting 命名調整、Selenium 物件統一定位初始化、Dashboard API 連接前需先註解 Thread、變數命名語意化（如 match_list）、球種須加註解、刪除未使用設定、線程重複建立處理、以及缺失函數需從其他專案補回。對 AI 開發的幫助在於理解 crawler service 的實作規範與團隊 coding style，確保未來開發遵循相同標準。

---

## 關鍵業務規則

- - CrawlerService 中呼叫 call_dashboard 的 Thread 必須在站台尚未設定 AppSetting 時先註解，否則會導致 API 回傳 500 錯誤。
- Selenium 物件的實例化一律在 GetDriver 類別中進行，初始化時呼叫 self.open_web.open_web('網址')。
- GetDriver 類別內部不得包含 main function。
- 變數命名必須語意清晰，例如傳入比賽清單時應使用 match_list 或 match_box，禁止使用 datas_1 等不明確的名稱。
- 處理足球球種的 else 區塊必須加註解說明對應的球種代碼（例如 #SC），或改用明確的 elif game_type == "SC" 語法。
- AppSetting 中未使用的設定項目必須刪除，避免混淆。
- 存放多個站台網址的變數應命名為 site_url，homepage 僅用於存放站台首頁網址。
- CrawlerService 中若出現重複的線程建立，應刪除未設定 daemon=True 的版本。
- 若 self.close_program 函數缺失，需從 panda 專案複製該函數回來，否則執行時會出錯。
- Dashboard 內的 AIScore 標籤應改為 90vs，避免與其他爬蟲混淆；driver 名稱應設為 90vsdriver。

---

## 關鍵設計決策

- - Selenium 驅動統一在 GetDriver 層實例化，使瀏覽器管理集中化。
- 強制使用語意化變數命名，提升多人協作時的程式可讀性。
- 球種類型要求明確標註，避免維護者需另外查閱 AppSetting 才能理解邏輯。
- 清理 AppSetting 中無用的設定，保持配置檔精簡。
- Dashboard 呼叫延後至站台設定完成，防止因缺少設定而觸發 500 錯誤。

## 注意事項

- ⚠️ - ⚠️ 目前 call_dashboard 的 Thread 被註解是暫時性的，待站台設定完成後需將註解移除，否則爬蟲將無法回報狀態。
- ⚠️ self.close_program 函數需從其它專案複製，若有版本差異可能需人工確認內容。
