## 摘要

本文件定義了新運彩錦標賽（Championship）與彩池（BetPool）系統的資料結構與 API 介面。彩池群組可包含多個彩池（週/月/季），並設定派彩規則、獲勝條件與抽水比例；錦標賽則依球種區分，關聯特定彩池群組，並設定門票費用、賣牌抽成與關盤時間。投注注單會記錄錦標賽 ID，用於後續計算排名與派彩。此文件提供完整的 CRUD API 與 Cassandra 資料表定義，是實作 PredictService 中錦標賽模組的技術基礎。

## 關鍵設計決策

- - 彩池群組與錦標賽為多對多關係：一個彩池群組可被多個錦標賽關聯，錦標賽的門票與賣牌抽成會流入該群組中進行中的彩池加碼獎金
- 彩池以 bType 區分週期（week/moon/season），同一個彩池群組下可同時存在多個不同週期的彩池
- 派彩分配支援兩種模式：avg（平均分配）與 custom（自訂比例），自訂時 payout_options 的 key 為名次、value 為比例，且名次數量需等於派彩數量
- 錦標賽只允許選擇已被鎖定的聯盟（leagues），確保只有受控的聯盟可參與錦標賽
- 投注注單（predictbets_{gameType}_newlottery）新增 cid 欄位記錄錦標賽 ID，將注單與錦標賽關聯以利後續統計排名
- 錦標賽的關盤時間（closeTime）定義為開賽前 N 分鐘，用於控制投注截止
- 門票費用區分為 ticket_Fee_Coin（鑽石）與 ticket_Fee_Point（點數），兩者為不同貨幣單位
- 賣牌機制包含名次範圍（Sell_Rank_Start/End）與費用、抽成比例，抽成比例依彩池週期（週/月/季）分別設定

## 注意事項

- ⚠️ - ⚠️ mainbet、match_a、match_h 欄位標注為「保留，暫不使用」，實際開發時不應依賴這些欄位
- ⚠️ 文件提到「依據 TCZB-4066 調整」，但未說明調整了什麼內容，需人工確認前後版本差異
- ⚠️ 彩池狀態 status 的語意與錦標賽 status 的語意不同：彩池為 0=未結算/1=已結算，錦標賽為 0=未啟用/1=啟用，容易混淆
- ⚠️ bonusprofitcoin 備註「手動設定的，不包含抽成等其它加碼」，但錦標賽門票與賣牌抽成的加碼邏輯未在 API 參數中體現，需人工確認加碼金的實際寫入流程
