## 摘要

這篇文件描述後台會員查詢功能的優化方案：在既有查詢帳號資訊（錢包 API）的彈窗中，新增會員訂閱紀錄的查詢。文件提供了合併後的 API 規格（GET /pricebackendservice/api/member/game/users/detail/{authKey}），Response 同時回傳 userWalletDTO（錢包資訊）與 userSubLogs（訂閱紀錄陣列）。對 AI 開發的幫助：了解 pricebackendservice 的會員查詢 API 已經擴展，開發時可一次取得會員錢包與訂閱歷史，不需分別呼叫兩個 API。訂閱紀錄欄位包含 subID、payType、payMethod、subTime、subEndTime、autoSub 等，可用於判斷會員當前訂閱狀態。

## 關鍵設計決策

- - 選擇在既有會員查詢帳號資訊的彈窗中擴充功能，而非建立獨立頁面，減少操作步驟
- API 設計採用合併 Response，在同一個 endpoint 同時回傳錢包資訊（userWalletDTO）與訂閱紀錄（userSubLogs），一次呼叫即可取得完整會員資訊
- 訂閱紀錄以陣列形式回傳，支援多筆歷史紀錄，查詢邏輯需根據 subEndTime 判斷最新有效訂閱
