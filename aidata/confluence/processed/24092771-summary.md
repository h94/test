## 摘要

本文件定義一個股票後台工具的 API 規格，包含六個端點：取得分點進出用的股票代碼清單、移除特定代碼、取得所有股票在指定日期的價格資料（含 limit）、取得單一股票向前推若干交易日的歷史、取得加權指數及櫃買指數向前推若干交易日的歷史。後續會運用這些歷史資料計算 5、20、40、60、120 MA 並寫入 DB。對 AI 開發的幫助：可快速了解現有股票資料查詢的參數與回應格式，以及均線寫入觸發點。

---

## 關鍵業務規則

- - api/getstock?page_num=5：從某個頁面（page）取出 5 個股票代碼，用於分點進出。page 的定義與來源需人工確認
- api/removestock?code=2330：從 page 中移除指定的股票代碼。移除後對其他查詢的影響未說明
- api/stockprice/count?lastdate=2022-02-17&limit=5：取得指定日期（lastdate）及 limit 數量的所有股票價格資料，回傳巢狀列表，每層代表一個股票的多筆紀錄
- api/getstockdata?date=2022-02-07&code=2330&cross=5：回傳指定股票在指定日期往前推 cross 個交易日的所有資料（實例回傳 6 筆，包含指定日當天），實際交易日數計算方式需人工確認
- api/twiiprice?lastdate=2022-02-09&limit=5：回傳加權指數在指定日期往前推 limit 個交易日的歷史資料
- api/twoiprice?lastdate=2022-02-09&limit=5：回傳櫃買指數在指定日期往前推 limit 個交易日的歷史資料
- 呼叫上述 API 取得必要歷史資料後，帶入公式計算 5MA, 20MA, 40MA, 60MA, 120MA 均線，並寫入資料庫。但未說明觸發計算的排程或條件

## 關鍵設計決策

- - 採用 RESTful GET 方法提供股票代碼、價格、指數等查詢，參數以 query string 傳遞，回應統一為 JSON
- 使用 page 概念管理股票代碼集合，可能用於分批處理或分點進出篩選，實際 page 實作方式未知
- 指數資料與個股資料使用相同結構（code、date、change、closeprice 等），但加權指數 code 值為 '發行量加權股價指數'，櫃買指數 code 值為 '櫃買指數'
- 均線計算採用先撈原始資料、再計算平均值後寫入 DB 的離線處理模式，避免即時運算負擔
