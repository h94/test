## 摘要

本文件記錄 SportKing 預測功能 API 的新增與修改需求，包含 6 支 API 的規格定義（Route、Parameter、Response）。重點在於既有 API 的調整：新增會員賽事預測 API 將 LID 從 URL 路徑移至 Request Body、取得玩家預測資訊 API 加入 visitor 參數驗證、排行榜 API 將 ThisMonth 欄位改為 ThisKiller。同時文件強調 Web API 應落實三層式架構，Controller 對應 API Service、DomainService 不互相依賴、格式轉換歸屬於 Infrastructure。開發 SportKing 預測相關 AI 功能時，可依此文件確認 API 輸入輸出規格及架構約束。

---

## 關鍵業務規則

- - API #1 新增會員賽事預測：Route 已移除原本的 {lid} 路徑參數，改為從 Request Body 的 LID 欄位提供聯盟 ID
- API #2 取得玩家近期預測資訊：若會員已登入，visitor 參數需帶入會員的 authKey；未登入則不帶 visitor 參數
- API #3 取得球種聯盟某日期近 10 期週期：若未帶入 date 參數，預設使用今天日期
- API #5 取得預測聯盟賽事排行榜：回應欄位從原本的 ThisMonth 變更為 ThisKiller（對應週期殺手概念而非月分概念）

---

## 關鍵設計決策

- - Web API 架構優化：落實三層式架構設計，Controller 對應到 API Service、DomainService 不互相依賴、資料格式轉換與基本驗證歸屬於 Infrastructure 層
- 既有 API Route 變更：將原本放在 URL 路徑中的 {lid} 移除，改由 Request Body 傳遞，降低 URL 結構複雜度並統一參數傳遞方式（見 API #1）
- API 回應格式調整：API #6 的輸出格式已變更，需注意與舊版不一致（文件中未詳列新舊差異，需人工確認完整規格）
