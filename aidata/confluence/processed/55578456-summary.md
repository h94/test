## 摘要

本文件定義了從 7m.com.cn 抓取籃球（BK）賽前、賽中、賽果資料的 API 端點、參數結構及數據欄位映射。它區分了籃球（BK）與足球（SC）的不同路徑，並提供多個 API 的實際回傳範例，有助於開發爬蟲程式解析 JSON 數據。對於 AI 開發，這份文件可直接作為數據獲取的規格書，避免從零摸索 7M 網站結構。

---

## 關鍵業務規則

- - league_id 與 league 必須從賽事 API（https://bdata.7m.com.cn/analyse/big/js/{game_id}.js）獲得，而非從其他 API 直接取得
- game_status 欄位含義：'2' 代表賽前（pregame），'0' 代表賽中（ingame），'1' 代表賽果（result），'4' 代表取消（cancel）
- playbyplay 時間格式在籃球為 'Q1 15:00'（節與倒數時間），足球為 '2H: 50:00'（半場與經過時間）
- 賽後 result_info 中的 h_stat_t 與 a_stat_t 陣列，索引 1 為兩分球、索引 2 為三分球、索引 3 為罰球（以陣列第二、三、四格表示）

---

## 關鍵設計決策

- - 數據源採用 7m.com.cn 的 .js 檔案格式（實為 JavaScript 物件）而非 HTML 解析，以簡化數據提取
- 根據比賽類型（SC 足球 / BK 籃球）使用不同的主機與路徑，例如籃球使用 bdata.7m.com.cn 與 js-basket.7m.com.cn
- 依功能拆分 API：賽程（bdata/datafile/{tomorrow}）、賽中（js-basket/livedts）、賽果（bdata/datafile/{yesterday}）、單場詳情（bdata/stat_data/{game_id}）
- 將頁面類型（page_type）分為 SC 與 BK，並為每種頁面類型定義多種子類型（pregame, ingame, result, single, check_ingame, cancel）對應不同 API 組合
- 日期參數格式：{tomorrow(ymd)} 為西元年月日無分隔（如 20240427），{yesterday} 可能為 y-m-d 格式（如 2024-05-02）

## 注意事項

- ⚠️ - ⚠️ {tomorrow} 與 {yesterday} 的日期格式不同，需注意實作時的轉換
- ⚠️ 文件中的 API 範例網址包含硬編碼日期（如 20240427），需確認是否需要動態代入參數
- ⚠️ 'game_info' 陣列的索引順序可能依 7M 網站變動，需人工確認
