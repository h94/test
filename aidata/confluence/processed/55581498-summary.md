## 摘要

這是一份 Sprint 管理流程的操作手冊，定義了從需求估算、開發、測試到上線的完整 Sprint 週期（Day -3 到 Day 12），包含各階段的 Checklist 與 Daily CheckList。對 AI 開發的幫助是：可以了解 TCZB 團隊的標準開發流程、各階段該完成的任務與檢查點，以及 Release 時需注意的 Gateway 配置與 Swagger 文件更新要求。

---

## 關鍵業務規則

- - Sprint 啟動前 3 天需完成：SM 和需求方確認 Story、安排開發和測試分析、請需求方講解需求、與需求方及成員討論時程、公告時程。
- Sprint 啟動前 2 天需完成：建立 JIRA Sprint/Story/SubTask、建立 Confluence 需求分析 Page、建立 Git 分支、執行 Sonarqube 取得警告數和 UT 覆蓋率。
- Story 項目較大時（StoryPoint=13）需召開 Design Review。
- Kickoff Meeting 需完成：開發測試人員講解需求、StoryPoint 估算、安排 Release/Launch 負責人、安排 Code Review 人員。
- Release 階段如有新增 Service 或 API 接口，需檢查 Gateway 是否有配置。
- Release 階段如有新增 Service 或 API 接口，需修改對應的 swagger.json。
- Launch 完成後需安排人員 Merge 主線、安排人員監控上線系統狀況、請成員填寫回顧會議內容。
- Daily CheckList：Daily Meeting 了解 Member 問題、判斷是否影響時程、確認 Members 確實填寫 JIRA Work Log、測試階段注意 Bug 數是否收斂、測試後期請成員補齊分析文件、下班前確認 JIRA 問題和回覆都有填寫、線上問題需長期關注則於 JIRA 上開 Task 監督狀況。

---

## 關鍵設計決策

- - Sprint 週期設計為 Day -3 到 Day 12，共 15 天，其中 Coding 佔 Day 1-5、Local Test 佔 Day 6-8、Demo Meeting 在 Day 8、Release 在 Day 9、Launch 在 Day 10。
- Code Review 安排在 Day 4，在 Coding 階段結束前進行，確保程式碼品質。
- TestCase Review Meeting 安排在 Day 4，與 Code Review 同日進行，測試案例在開發完成前就需審查。
