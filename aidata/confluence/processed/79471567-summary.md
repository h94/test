## 摘要

本文件定義了針對泰金999（tg666.net）的爬蟲實作，包括帳號列表、登錄 API 獲取認證 token（ssstoken/sssmbid）、使用 GameDetail API 分兩步抓取比賽清單與完整玩法，以及 GameResult API 取得賽果。Parser 部份規範了基本欄位（聯盟、賽事、隊伍、分數）的對應關係，特別說明了彩球/賽馬無主客隊時的處理方案（other_info 或組合 ID+日期），並指出因網站數據問題只取總分而不取各節分數。此文件提供爬蟲開發所需的 API 細節與解析規則。

---

## 關鍵業務規則

- - 對於彩球（LB）與賽馬（HR）無主客隊之分，teamhome 與 teamaway 無法套用常規名稱，需採用 GF（Guest/For）方式處理。
- 為區分同聯盟內多場彩球/賽馬賽事，可將描述資訊（如「台灣三星彩：(百位數)」）放入 other_info，或組合成 game_id+game_date 作為唯一標識（方案未最終決定）。
- 分數欄位 scores 僅使用主隊與客隊總分組成 [score_home, score_away]，不採用各節分數，因為網站提供的各節分數有問題（文件中附圖證實）。
- 比賽狀態 GameType 值：3 表示 Pregame（賽前），2 表示 Inplay（滾球）。

---

## 關鍵設計決策

- - 登錄流程設計為先呼叫 /api/mb/sin/login，從回應中獲取 ssstoken 與 sssmbid，作為後續 API 呼叫的必要 header，避免硬編碼 token 過期失效。
- 獲取比賽資料分成兩階段：先用第一個 payload（GameType、CatID、WagerTypeKey）獲取該球種下所有比賽；再用第二個 payload（EvtIDs）取得單場比賽的全部玩法資訊。
- 對彩球/賽馬的處理設計兩種方案：方案一將描述資訊塞入 other_info；方案二將描述資訊結合成 game_id+game_date 供區分，但文件中未明確選定，需人工確認。
- 分數設計只取總分，因原始網站各節分數存在異常，為保證數據準確性捨棄細節數據。
- 語言切換需在登入頁面設定，透過 ssslang header 傳遞語言代碼（cn/en/vi 等對應 zh-CN/en-US/vi-VN），預設為 tw。
- 帳號列表為多組測試帳號，且標註「帳號會變化」，暗示實作中可能需動態分配帳號或實作帳號輪替機制。
