## 摘要

本文件定義了 CrawlerAgentUbl 從 UBL 棒球聯賽網站爬取比賽數據的技術設計。流程為：由外部 provider 提供 game_id 與 league 資訊，爬蟲進入特定比賽頁面，使用正則表達式解析 HTML 內容，提取主客隊名稱、比賽日期時間、狀態（賽前／賽果）、總分及各節分數等欄位。文件詳細列出了每個欄位的正則表達式與擷取規則，含主客隊索引、狀態判斷邏輯及日期格式轉換方式。這份規範可作為開發、維護或重構 CrawlerAgentUbl 時的實作指引。

## 關鍵設計決策

- - 選擇直接對 HTML 原始碼使用正則表達式擷取資料，而非 DOM 解析或 API，因為網站前端結構簡單且無官方 API。
- game_id 與 league 由外部 provider 提供，爬蟲自身不負責探索或管理比賽清單，僅解析單場比賽頁面。
- 比賽狀態（game_status）透過判斷頁面內容中是否出現特定字串（『比賽將於』表賽前，『比賽時間』表賽果）來決定，而非依賴統一的結構化標記。
- 主客隊名稱與分數靠正則匹配結果的索引區分：主隊名稱取匹配清單 index 0，客隊取 index 1；總分方面主隊 index 1、客隊 index 0（顛倒設計）；各節分數則直接取全部匹配結果。
- 日期格式從原文『2024.12.25』轉換為『2024-12-25』，以符合後續系統儲存格式。
- 使用同一正則在不同頁面狀態（賽前／賽果）提取時間，但依賴不同的模式與上下文定位，避免互相干擾。

## 注意事項

- ⚠️ - ⚠️ game_id 與 league 由 provider 提供的機制需人工確認：provider 是內部其他服務還是手動輸入？若 provider 變更，會影響整個爬蟲。
- ⚠️ 主客隊分數的正則匹配後索引與直覺相反（主隊 index 1、客隊 index 0），實作時須特別標注避免對調。
- ⚠️ 各節分數解析未區分主客，可能僅為一段連續分數列表，若後續需求需要主客各節對應，需人工確認處理邏輯。
