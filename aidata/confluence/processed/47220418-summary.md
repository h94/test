## 摘要

本文件定義了在 MemberService 中新增 SportKing 會員訂閱功能的 API 與資料庫設計。共規劃三個端點，分別用於建立遊戲會員帳號、新增訂閱記錄及查詢訂閱記錄。資料庫方面預計在 gameusers 表新增欄位，並建立 sublogs 表來儲存訂閱歷程，以 authkey 作為分區鍵，並以訂閱日期、交易單號等作為集群鍵。此文件提供了 API 規格與 DB Schema 藍圖，可作為實作 SportKing 訂閱模組的技術基礎。

## 關鍵設計決策

- - 採用 POST /memberservice/api/game/users 建立賽事會員帳號，而非 PUT 或 PATCH，推測為每次請求建立全新資源
- 訂閱記錄的查詢與新增路由結構不對稱：新增用 /users/sublogs/{authKey}，查詢用 /user/sublogs/{authKey}（單複數不一致，需人工確認是否為筆誤）
- sublogs 表選用 authkey 作為 partition_key，推測是為了將同一會員的所有訂閱記錄集中在同一分區，提高查詢效率
- sublogs 表同時使用 subtime、tradeno、addtime 作為 clustering key，表示資料會依照訂閱日期、交易單號、新增時間排序儲存
