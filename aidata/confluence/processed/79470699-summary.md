## 摘要

此文件详细定义了球王社群系统的所有 RESTful API 端点，涵盖文章/回文的 CRUD、图片上传、Hashtag 管理、点赞、检举、文章置顶、热门文章获取、内容隐藏/解除隐藏以及统计报表等功能。对各端点的请求参数、响应格式、错误状态码及业务限制（如字数限制、分页逻辑、点赞去重）有明确定义。为 AI 开发 communityservice 提供了完整的接口契约和数据结构参考。

---

## 關鍵業務規則

- - 建立文章时，内文字数最少 1 字，最多 2000 字（目前设定），违反将返回 422。
- 回文字数下限 1 字，上限 200 字。
- 创建回文时，若 respCommentID 未给或为空字串，视为一般回文；否则为回复指定回文。
- 文章分页查询每页最多 20 篇文章。参数 index（时间戳）或 page（页码）择一使用。
- 筛选 hashtag 时，同一类型内多个 tag 以底线分隔（如 vip_vlsport），查询逻辑为 AND。
- 分页响应包含 next_page (是否还有下一页) 和 need_click (是否需要前端手动点击“查看更多”)。
- 同一用户对同一文章/回文仅能点赞一次（按照 emoji 类型），重复点赞返回 409。
- 隐藏用户内容的 mute API 的时间范围依据文章创建时间而非留言时间，且 end 必须大于等于 start。
- 热門文章第一页会包含置顶文章，每页最多 20 篇。
- 建立/更新 hashtag 时，传入的 data 会直接覆盖所有语系（不会合并），且语系必须为系统支持列表（en-US, zh-TW 等），否则为无效请求。
- 删除 hashtag 类型功能尚未实作（hashtag_id=0 的行为未实做）。
- 图片存储路径中的日期为文章创建日期，非当前日期。
- 统计报表 API 的 start 和 end 参数为 13 位毫秒时间戳，end >= start。

---

## 關鍵設計決策

- - hashtag 的更新采用全量覆盖策略，避免增量合并导致的多语系不一致问题。
- 文章分页同时支持基于时间戳的游标分页 (index) 和传统页码分页 (page)，并透过 need_click 控制前端自动加载 vs 手动触发。
- 文章隐藏操作基于文章创建时间区间，而非留言时间，确保管理操作语义清晰，整批文章范围可控。
- 点赞使用 emoji 类型作为区分，未来可能支持多种反应。
- 图片上传路径结构固定：/{日期}/{文章ID}/article/ 或 /comment/{回文ID}/，便于静态资源缓存和清理。
