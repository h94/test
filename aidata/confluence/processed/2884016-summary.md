## 摘要

本文件描述第一版ZB系統的基礎架構，包含 Gateway & PRE 測試集群與 PRD 生產集群的機器配置、關鍵組件（Nginx、K8s、Harbor、Redis、Kafka、MySQL、Cassandra）及服務分佈。說明了從 GitLab 提交、Jenkins 構建、推送 Harbor 再到通過 Kubeapps 發佈到 K8S 的 CI/CD 流程。提供 API Gateway 路由設定、基於 Zookeeper 的配置服務、基於 Kafka 的日誌中心和 Prometheus/Grafana 性能監控的整合方式，對開發服務的日誌、配置、監控有直接指導。特別指出 LogXService 和 AppLogXService 應使用 Docker 部署在 Gateway & PRE 集群的 VM3，而 GatewayAgent 無需 Docker，這對開發相關服務的部署有參考價值。

---

## 關鍵業務規則

- - PRE 測試環境中的 Services 需要讀取 PRD 的線上資料
- 所有相關的內部管理系統應部署在 Gateway & PRE 集群
- Jenkins 腳本必須將打包好的 Docker image 推送至 Gateway & PRE 集群的 Harbor，且 PRD/PRE 的 K8s 不能與本地開發環境混用
- LogXService 和 AppLogXService 必須使用 Docker 部署，GatewayAgent 不使用 Docker

---

## 關鍵設計決策

- - 選擇 Gateway & PRE 集群運行內部管理系統和測試環境，因 VM3 機器要求等級較低，節省成本；生產流量透過 Nginx 分流。
- PRE 測試環境直接讀取 PRD 線上資料，以確保測試的真實性和效率，避免數據同步問題。
- 使用 Harbor 作為鏡像倉庫，並隔離 PRE/PRD 倉庫，確保部署安全性。
- LogXService 和 AppLogXService 採用 Docker 部署以便快速擴展和管理；GatewayAgent 以傳統方式部署，可能因無狀態或管理考量。
- 採用 Zookeeper 動態配置 .NET Core 服務，避免重啟。
- 透過 Kafka 集中收集 Nginx 訪問日誌和應用事件日誌，並儲存至 Cassandra，實現日誌歸檔和查詢。
- 使用 Prometheus 監控服務指標，並通過 Grafana 可視化（文中誤標為 Kibana）。
