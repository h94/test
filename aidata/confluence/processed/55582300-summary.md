## 摘要

這份文件記錄了美嘉站台（MC766）爬蟲 MCProvider / CrawlerAgentMc 的技術實作細節，包含支援的球種清單、資料抽取 API（比賽列表、單場比賽、賽果）的端點與 payload 參數設定，以及解析比賽資料時對應的 JSON 欄位路徑。從 AI 開發角度，此文件提供爬蟲需要遵守的請求規則與資料解析邏輯，特別是不同球種的抓取策略（如足球籃球只抓列表、其餘需單場請求）和分數解析的球種差異性，有助於正確實作與維護爬蟲服務。

---

## 關鍵業務規則

- - 所有 API 請求的 oddsType 一律使用 3（歐洲盤），因為其他盤口頁面存在 bug。
- 足球（sportId=1）和籃球（sportId=2）只抓比賽列表，不需要透過單場比賽 API 請求賠率，因其列表已包含足夠賠率資訊。
- 除足球、籃球外的球種（如網球、棒球、桌球等）必須對每場比賽使用單場比賽 API 請求才能取得賠率。
- 走地（periodId=3）比賽列表的 pageSize 統一設為 999，今日（1）與早盤（2）則設為 10。
- 早盤比賽可透過 selectDate 參數指定日期，1 代表明天，2 代表後天。
- 賽果資料僅支援足球和籃球，其餘球種無賽果 API。
- 比賽狀態由 game_data['isb'] 決定：0 表示 pregame，1 表示 inplay。
- 網域名稱無法解析時，代表站台可能已更換 domain，需手動調整。

---

## 關鍵設計決策

- - 因美嘉站台的香港盤等頁面存在 bug，故強制所有 request 使用 oddsType=3（歐洲盤），降低資料錯誤風險。
- 足球與籃球的賠率在比賽列表中已涵蓋較多盤口，為減少請求數量與效能負擔，設計為僅擷取列表而不進行單場查詢。
- 走地比賽為了減少分頁請求，pageSize 特別設定為 999 以單次取得大量資料（其他情境因資料量較小維持預設或 10 筆）。
- Game ID 採用 hash 組合而成，但文件未揭露具體組成方式，推測為各欄位拼接後雜湊，便於去重或對應。

## 注意事項

- ⚠️ - ⚠️ 2025/6/30 觀察到 API 回應 502/503，美嘉站台可能已故障或改版，目前爬蟲可能無法正常運作。
- ⚠️ 網域名稱變更時需手動更新，文件未提供自動偵測或 fallback 機制。
- ⚠️ 分數解析的 mo 字典中，不同球種所用的 key 值不一致（如 sca、sc 等），實作時需針對各球種獨立處理。
- ⚠️ Game ID 的 hash 演算法未明確給出，若需重現或驗證，有待人工確認。
- ⚠️ 單場比賽 API 中的 pageSize 也設為 999，但走地以外情境使用 10，需注意一致性，避免錯誤請求。
