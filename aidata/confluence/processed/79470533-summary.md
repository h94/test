## 摘要

這是一份使用 Claude Code 輔助開發的完整實戰記錄，描述如何在 NewLotterySite 中整合 CommunityService 的社群功能（討論版、文章 CRUD、按讚等）。文件記錄了從產生 Plan、實作 Controller/Service/Provider、整合測試到前端 UI 開發的完整流程，包含大量 AI 輔助開發的經驗教訓，如人工檢查 Plan 的必要性、API 文件完善度對 AI 開發的影響、以及遇到 Queue 延遲等實戰問題的解法。對 AI 開發最有價值的部分是明確的設計模式：Provider 只做資料存取、Service 處理業務邏輯與驗證、Controller 定義 I/O 並使用 FormPost 處理檔案上傳。

---

## 關鍵業務規則

- - 取得討論版清單、文章標題清單、文章內容、按讚玩家清單等讀取操作無須登入檢查
- 新增/修改/刪除文章或回文、按讚等操作必須透過 authKey 驗證玩家登入，驗證失敗需用 _logger.Log(LogLevel.Trace, "err reason") 記錄
- 修改或刪除文章/回文時必須檢查是否為該玩家所張貼，非擁有者操作需記錄 LogLevel.Trace
- 每個玩家對同一文章或回文只能按讚一次，收回讚時必須該玩家已點過讚
- 新增 subject 時，input 的 comment 會同時建立 subject 和第一筆 comment
- 文章擁有者修改時可同時修改 subject 和第一筆 comment，但內部調用 CommunityService 需分別呼叫修改 subject 和修改 comment 的 API
- 第二筆以後的 comment，即使是 subject 建立者也只能修改 comment，只調用修改 comment 的 API
- 新增 subject 和 comment 時 status 固定為 1
- 上傳檔案需透過 IFormFile 接收，經 CommunityValidator.ValidateUploadImg 檢查後用 ImageTransfer 轉換成 webp 格式
- 轉換後的檔案名稱格式為 {PublicLibary.GenerateHashKey()}.webp
- 檔案上傳轉換失敗需用 _logger.Log(LogLevel.Error) 記錄，log 內容需包含玩家 Account 和 UserName
- CommunityService 非 200/204 回應時，需 JSON 反序列化 body 取出 message，若無 message 則用 status
- CommunityService 因 Queue 機制有資料寫入延遲，修改後查詢需等待約 250ms（⚠️需人工確認實際延遲時間）

## 關鍵設計決策

- - 使用 Claude Code 先產生完整 Plan 再人工檢查後實作，人工檢查 Plan 不可省略，Plan 越詳細越能減少實作時的錯誤
- Controller 內部調用 API 統一使用 /api/newlottery/ 系列，不使用 /api/community/
- 實作順序：先定義 Controller I/O（不實作 Service），確認 I/O 後再處理 Service
- Provider 只負責調用 CommunityService API，驗證邏輯和業務檢查放在 Service 層
- 新增/修改 subject 和 comment 因需接收檔案，對外接口使用 FormPost，調用 CommunityService 也使用 FormPost（例外允許使用 HttpClient）
- GetSubjectDetail 輸出時將第一筆 comment 的內容提升到主層（Content、ImagePaths、ContentId、時間戳），並從 Comments 列表中移除第一筆
- 為避免影響 EditSubject 的檢查邏輯，GetSubjectDetail 使用專用 DTO（SubjectDetailResponseDTO）而非共用 Model
- DTO 型別命名去掉後綴 DTO（如 SubjectListItemDTO → SubjectListItem），已加入 coding rules
- 前端論壇相關資料不使用 store 進行狀態管理
- 整合測試使用 WebApplicationFactory<Program> + HttpClient，不可直接呼叫 Controller method 或 Service class
- API 文件需完善 Output 規格（含 Code=200 的回應格式），否則 AI 無法確認輸出規格

## 注意事項

- ⚠️ - ⚠️ CommunityService 使用 Queue 機制處理資料變更，寫入後立即讀取可能取得舊資料，需等待約 250ms（確切延遲時間需人工確認）
- ⚠️ ECFramework 封裝造成 WebApplicationFactory.CreateClient 卡住，需升級至 3.01 版本並修改 Program.cs 的 CreateWebHostBuilder 才能執行整合測試
- ⚠️ CommunityService.json 原始版本缺少 200 回應規格，需 API 工程師補強文件內容後 AI 才能正確開發
- ⚠️ CommunityService 修改 subject 的 input 後續有變動，支持同時傳入 subject 和 content，不再需要另外呼叫 EditNewLotteryComment
