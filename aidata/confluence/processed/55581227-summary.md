## 摘要

定義球王站台站內信系統 API，包含信件新增、查詢、閱讀狀態更新等功能。使用 MySQL 作為持久存儲，Redis 作為信件列表快取，寫入時先寫 Redis 再寫 DB。閱讀狀態更新邏輯：第一次讀取未讀信件時會同時更新 DB 與 Redis，之後不再重複操作。API 路由均在 /pricecentermanage/api/sport/notifications/ 下。

---

## 關鍵業務規則

- - 信件無固定存活時間，由會員自行刪除。
- 查詢郵件列表時 startTime 預設前 2 天時間，endTime 預設現在時間。
- 讀取信件時，若快取列表狀態為 0（未讀），同時更新 DB 和 Redis 的閱讀狀態為已讀；第二次讀取後不做任何動作。

---

## 關鍵設計決策

- - 採用 Redis 作為信件列表快取，以提升讀取效能，寫入時先更新 Redis 再寫入 DB。
- 閱讀狀態更新僅在首次讀取未讀信件時觸發，避免重複更新 DB 和 Redis，減少開銷。
- 信件 ID 使用 CHAR(10) 格式，在 Redis 與 DB 中保持一致。

---

## 注意事項

- ⚠️ - ⚠️ 注意 startTime 預設前 2 天，若無信件可能返回空列表，前端應避免誤導。
- ⚠️ 閱讀狀態更新基於快取列表狀態為 0 時才執行，須確保快取中狀態與 DB 一致，否則可能漏更新或重複更新。
