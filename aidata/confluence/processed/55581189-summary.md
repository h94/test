## 摘要

本文件定義了 PriceBackendService 中站內信管理與主推連勝排行榜生成/更新的 API 設計。包含四個端點：生成/更新主推連勝排行榜(POST)、新增通知站內信(POST)、上傳信件內文圖片(POST)、取得通知站內信(GET)。每個 API 均提供路由、請求參數範例及回應格式，有助於開發時掌握輸入輸出規格。

---

## 關鍵業務規則

- - 站內信內容支援 HTML 格式，可包含 <h1> 等標籤
- 站內信需指定收件人帳號清單 (RecipientAccounts)、主旨 (Subject)、發送時間 (SendTime, Unix timestamp) 與內容 (Content)
- 上傳的圖片可使用於站內信內文，回傳可供訪問的完整圖片 URL
- 查詢站內信時，若未指定 startDate 與 endDate，預設查詢範圍為昨日 00:00:00 至今日 23:59:59

---

## 關鍵設計決策

- - 主推連勝排行榜採用 POST /predict/filterleaderboards/mainbet/winstreak 生成或更新，無需額外請求參數（參數可能透過既有的排行邏輯或服務內部決定）
- 站內信收件人採帳號清單而非單一收件人，可一次發送給多個使用者
- 圖片上傳直接回傳已轉存的完整 URL，避免客戶端自行組合路徑，保證可訪問性
- 將站內信管理功能集中於 PriceBackendService，而不另開獨立的 message 服務（推測為減少服務數量或管理便利性）

## 注意事項

- ⚠️ - ⚠️ 主推連勝排行榜的請求參數與回應均未詳細定義，需人工確認其實際傳入邏輯
- ⚠️ 上傳圖片的請求參數僅提供截圖，缺少文字描述，需人工確認上傳格式（multipart/form-data、欄位名稱等）
- ⚠️ 取得站內信 API 的回應結構包含 id 欄位（例如 "cOBIbphCbE"），但未說明其生成規則，推測為系統自動產生
