## 摘要

這是一份 Sprint 管理流程手冊，定義了從排程、需求分析、開發到發布和回顧的各階段活動與每日檢查事項。主要供 Scrum Master 使用，確保 Sprint 各環節按規範執行。對 AI 開發特定服務幫助有限，但提供了團隊工作流程與 Release 時必須檢查 Gateway 及更新 Swagger 文件的準則。

---

## 關鍵業務規則

- - 每日需確認團隊成員是否確實填寫 JIRA Work Log。
- 測試階段後期需要求成員補齊分析文件。
- 線上問題若需長期關注，應在 JIRA 上建立 Task 監督狀況。
- Sprint 估算階段：Story 規模較大（StoryPoint=13）時需召開 Design Review。
- Kickoff Meeting：需進行 StoryPoint 估算、安排 Release/Launch 負責人、安排 Code Review 人員。
- Release 階段：如有新增 Service 或 API 接口，需檢查 Gateway 是否有配置。
- Release 階段：新增 Service 或 API 接口時，必須修改對應的 swagger.json（修改步驟參考特定頁面）。
- Code Review 需確保檢查內容都被修改或記錄。
- Launch 後需安排人員 Merge 主線、監控上線系統，並請成員填寫回顧會議內容。
