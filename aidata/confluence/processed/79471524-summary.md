## 摘要


本文件定義 TradeGameService 的 REST API，涵蓋即時股價查詢（GET/POST）、買入賣出下單、以及依賽事或用戶維度的交易倉查詢、單日交易倉查詢與賽事所有交易重算功能。關鍵業務邏輯包括賣出時依最新股價計算獲利（手續費 0.3%）、持股不足會拒絕交易，且買賣記錄寫入 trade_history 並標記為 user 行為。對 AI 開發者而言，可據此實作股票交易、倉位查詢與重算等核心操作，並理解查詢參數的限制（如 gdate 可單獨使用但 gid 不可單獨使用）。

---

## 關鍵業務規則


- - 取得即時股價 (GET) 的 gdate 與 gid 為可選參數，可以只選填 gdate，但不能只選填 gid。
- 新增/更新交易倉時，trade_type 為 'buy'（買入）或 'sell'（賣出），需提供 mode (HA/OU)、oddtype (H/A/O/U)、spread、stock_num、trade_price 等欄位。
- 賣出時系統會取得最新股價計算獲利，公式為：賣出股價 × 股數 − 手續費（賣出股價 × 股數 × 0.003），範例 45×1−45×1×0.003 = 44（需人工確認取整方式）。
- 買入或賣出會寫入資料庫（trade_history），並記錄為 user 行為。
- 股票數量不足（賣出超過持有）時，回應 HTTP 400 且 message 為「股票數量不足」。
- 查詢球種聯盟交易倉或使用者交易倉的 API，若不帶日期參數則預設取當日資料。
- 重新計算單場賽事所有交易的 PUT API 會直接重新結單該賽事全部交易，且原本的股價會退還（具體邏輯需確認）。
- 系統也可能自動執行賣出、重算 (recalculate) 或重新賣出 (resell) 操作，並在 trade_history 中記錄對應的 trade_operator (system)。
