## 摘要

本文件定義從 konibet 體育博彩站點解析比賽資料的技術設計。資料流為前端爬取 API 回應 → Kafka → Python 解析 → 存入 gamedata。詳細列出兩支 API（賽事列表與比賽詳情）的端點與回傳 JSON 結構，並指定需提取的欄位與對應含義（如主客隊名、比分、狀態、聯賽/運動類型等）。對 AI 開發而言，此文件提供具體的資料來源位置與欄位映射，可據此實作 konibet 站的資料擷取與正規化。

---

## 關鍵業務規則

- - 主客隊名稱需從 HomeTeamName / AwayTeamName 取得，無 ID 機制，必須透過 NAME MAP 進行緩存，以建立穩定的隊伍識別。
- 賽事狀態由 Status 與 IsLive 欄位判斷，IsLive=true 表示進行中，Status 提供文字階段說明（如 '3rd period'）。
- 比賽時間由 DateOfMatch 欄位提供（ISO 8601格式）。
- 聯賽層級由 Category.Name / OriginalName（國家）及 Tournament.ID / Name（聯盟）組合定義，SportType.Name 為運動種類。
- 詳細比分需從 MatchInfo API 的 ScoreInfo.Items 集合中取出各節分數，並以 Total.Set='Total' 取得總比分。

---

## 關鍵設計決策

- - 採用前端爬取 API 而非直接解析 HTML，因為 API 回傳結構化 JSON，減少解析複雜度。
- 使用 Kafka 作為爬取與解析之間的緩衝，實現解耦與流量控制，Python 解析服務可獨立擴展。
- 解析後的資料寫入 gamedata（應為內部統一資料儲存），以便後續服務取用。
