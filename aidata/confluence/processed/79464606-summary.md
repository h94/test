## 摘要

本文件描述 WNBA 官網爬蟲的技術實作，說明使用兩個 API（全年賽程與今日賽程）取得比賽數據，並規範各自的呼叫頻率與用途（全年 API 每10分鐘，不處理走地；今日 API 每10秒，用於走地）。文中詳細列出各資料欄位（聯盟、主客隊、日期、時間、賽事 ID、狀態、分數、節次得分、play-by-play）在 JSON 回應中的對應路徑或解析方式，包含特殊處理如年度 API 無 period 資料時需另外爬取單場 HTML。對爬蟲服務的開發與維護提供明確實作指引。

---

## 關鍵業務規則

- - 全年賽程 API (https://www.wnba.com/api/schedule?season=2025&regionId=32) 每10分鐘呼叫一次，不回解析走地比賽（因 PBP 延遲）。
- 今日賽程 API (https://cdn.wnba.com/static/json/liveData/scoreboard/todaysScoreboard_10.json) 每10秒呼叫一次，用於走地比賽解析。
- 聯盟 (league) 固定為 'Women's National Basketball Association'，直接寫死。
- 主隊／客隊名稱由 teamName 與 teamCity 兩個欄位拼接而成。
- game_date 來源：今日 API 使用 gameTimeUTC，全年 API 使用 gameDateTimeUTC。
- game_status 對應：1 = 賽前，2 = 走地，3 = 賽果。
- 節次得分 (scores) 僅存在於今日 API 的 periods 鍵中；全年 API 無此資料，須另行請求單場 HTML 頁面並用正則表達式解析。
- play-by-play 文字 (playbyplay) 取自今日 API 的 gameStatusText 欄位。

---

## 關鍵設計決策

- - 走地數據不使用全年 API 而改用今日 API，原因是前者 PBP 會延遲，故需更高頻率（10 秒）的今日 API。
- 全年 API 即使比賽結束也不提供 periods 資料，因此設計獨立邏輯：針對單場賽事頁面做 HTML 正則解析以取得節次得分。
