## 摘要


本文件為管理者系統的測試流程規劃，定義了四層測試策略（L1 單元/契約、L2 整合、L3 CLI 腳本、L4 人工檢核頁），詳細列出各層的測試案例、環境準備、執行命令與通過標準。文中記錄了目前 pytest 17/22 通過、5 個待修問題（B1-B5），並說明 Phase 5 將調整路由與設定，以及待確認的業務規則（如 delete API、active 欄位處理）。對 AI 開發的幫助：提供明確的測試基準與已知缺陷，可作為自動化測試驗證與錯誤修復的參考，確保 API 行為符合預期權限與回傳格式。

---

## 關鍵業務規則


- - admin 權限等級不足時（如 viewer level=10）存取 GET /api/admin/admins 應回傳 HTTP 403。
- manager 不能將同級或更低級別的管理員提升到與自己同等或更高的級別（例如 manager 無法將 query 升到 80）。
- manager 不能建立 level 大於等於自身 level 的新管理員帳號。
- manager 不能修改 superadmin（level > 100）的任何屬性。
- 操作紀錄查詢時，若指定 target_account=superadmin，因無人擁有高於 superadmin 的權限，永遠查不到記錄。
- 密碼重設 API（PUT /api/admin/admins/{account}/password）的請求 body 欄位必須為 "password"，而非 "new_password"。
- 被停用的管理員帳號嘗試登入時應回傳 HTTP 403，並帶有 account disabled 的訊息。
- 建立管理員帳號時，若缺少必填欄位 active，API 應回傳 HTTP 422 驗證錯誤。

## 關鍵設計決策


- - 測試劃分為四層：L1 單元測試使用 mock 及 TestClient，不依賴外部服務；L2 整合測試使用真實 Postgres 與 Redis，驗證端到端權限情境；L3 CLI 腳本以 HTTP 請求模擬實際使用者流程；L4 使用手動檢核頁面進行最終人工驗證。
- 整合測試的操作者帳號為預先 seed 的 superadmin / 1qaz2wsx，確保測試起點一致。
- CLI 腳本中的測試帳號使用前綴 `permtest_{pid}` 以避免衝突。
- Phase 5 計畫將啟用/停用路由由 PUT /active 改為 /disable，並同步調整相關測試與 checklist。
- Phase 5 計畫將 session TTL 從目前的 3600 秒修改為 28800 秒，以符合主計畫規範。
