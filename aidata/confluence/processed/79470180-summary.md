## 摘要

本文件定義一個 Sprint 週期（約兩週）的標準流程，從需求分析、Kickoff、開發、測試到 Release/Launch，並提供每日檢查清單與各階段須完成的步驟。對 AI 開發而言，可據此了解團隊工作節奏與協作規範，例如 JIRA 管理、Sonarqube 掃描、Swagger 更新時機、Gateway 配置檢查等，有助於自動化任務提醒或流程稽核。

## 關鍵業務規則

- - Sprint 開始前 3 天需與需求方確認 Story、安排分析與時程討論
- Story Point 為 13 時需召開 Design Review
- 新增 Service 或 API 接口時，Release 階段必須檢查 Gateway 配置並修改對應 swagger.json
- Sprint 結束後需安排人員 Merge 主線、監控上線系統狀況
- 每日需確認 JIRA Work Log 填寫正確、測試階段觀察 Bug 收斂趨勢
- 線上問題若需長期關注，應在 JIRA 建立 Task 追蹤
