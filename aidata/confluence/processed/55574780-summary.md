## 摘要

這份會議記錄列出了球王 APP 各功能模組的開發進度與待修改事項，重點說明了首頁、預測、我的預測、收藏等頁面的 API 調用規則、數據更新頻率、默認球種切換邏輯，以及近期設計變更（如 API 拆分、收藏天數調整）。對 AI 開發的幫助在於理解前端與後端的互動模式、關鍵 API 的使用情境與觸發條件。

---

## 關鍵業務規則

- - 首頁：進入時調用 default API 取得全局數據，一分鐘執行一次；若 live 中 default.gameCounters 與 API 數量不同，或 hub 更新時無對應 gid，則重新撈取 API
- 首次進入 Live/Pre/Result 時，若 SC 球種無比賽則自動切換至 defaultGameType，否則不切換；此檢查僅在第一次進入時執行，後續不再檢查
- 預測頁：進入時調用 predictdefault API 取得 gameCounters 顯示於球種上，一分鐘更新一次；點擊球種時調用聯盟列表 API，依聯盟名稱排序顯示各聯盟比賽數量
- 我的預測：原今日與歷史合併的 API 已拆分為兩個獨立 API，分別用於今日推薦與歷史推薦
- 收藏頁：賽事固定按開賽時間排序，收藏賽事儲存天數改為兩天；點擊收藏聯盟卡片顯示該聯盟 Live、Pre、Result 比賽
- 預測頁足球：切換不同足球聯盟時不再重新請求後端，改由前端從已有的 all 資料中篩選同聯盟賽事
- 設定：語言切換需等待翻譯文本完成；時區已按照手機預設判斷，需確認是否提供手動切換選項

---

## 關鍵設計決策

- - 今日/歷史推薦 API 拆分：將合一的 API 分為兩個，以針對不同用途優化
- 收藏賽事儲存天數從原先改為兩天，減少不必要的資料累積
- 足球聯盟切換改為前端篩選，避免重複請求後端，因足球數據皆取自 all 資料
- 預測頁新增賽事數量快顯，並在預測按鈕左方顯示賠率類型文字（獨贏/讓分/大小）
