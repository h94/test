## 摘要

本文件定义球王商城商品系统的扩展设计，新增商品兑换纪录与库存纪录的 CRUD 功能。包含 Cassandra 与 Redis 资料表结构（含新增栏位），以及 15 个 REST API 的路径、参数、回应与操作规则。明确列出商品状态、兑换纪录状态变更、地址验证、库存计算等业务限制，并说明商品删除时的连锁删除策略。对 AI 开发 ProductService 提供完整的资料模型、接口契约与执行规则。

---

## 關鍵業務規則

- - 非站内商品(inplayz)创建时，商品状态只能为已下架(0)，必须先生成库存才能上架。
- 商品兑换纪录状态为审核中(2)时，允许更改收件人资讯（地址、电话、收件人）。
- 非站内商品种类兑换时，必须提供寄送地址(Address)，否则不能建立兑换纪录。
- 兑换纪录创建后，会员暱称(cname)与会员大头贴(cheadshot)固定，不可修改。
- 删除商城商品时，必须同时删除该商品的所有兑换纪录与库存纪录，不保留任何纪录。
- 商品剩余数量计算统一采用「库存总量 - 提领数量」,不另在 Cassandra 维护 Quantity 栏位。
- 只有兑换状态为失败(0)的兑换纪录才可以被删除。
- 更新兑换纪录状态时：status=2 才能改为 1 或 0；status=0 的状态不能改为其他非 0 状态。
- 更新兑换纪录(收件人、电话、地址)时，商品种类不得为 inplayz（站内商品不涉及寄送）。
- API 更新兑换纪录时，Account 栏位必须与纪录中的帐号一致，不得变更。

## 關鍵設計決策

- - 库存数量不存入 Cassandra 的独立栏位，而是通过库存纪录总和动态计算，避免数据不一致。
- 商品删除采用级联删除（cascade），不保留兑换与库存纪录，简化数据管理并符合业务不展示历史纪录的需求。
- 兑换纪录中的会员暱称与头贴在建档时固化，后续不跟随会员资料变动，确保历史纪录可追溯。
- Redis 缓存 Store_{class}_Products 作为商品查询的快取层，支援 cache 参数切换资料来源（true 读 Redis, false 读 Cassandra）。
- API 路径设计采用分层 RESTful 风格，区分商品、兑换纪录、库存纪录的资源层级。
