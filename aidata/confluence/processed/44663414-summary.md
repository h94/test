## 摘要

本文件定義了新 Merge 站台的聯盟合併功能所需的 API 規格，包括取得 League 列表、根據時間區段或 LID 取得 SiteLeague，以及執行合併聯盟的操作。合併時若 LID 為空則新增全新聯盟，否則將指定 SiteLID 加入該 LID。文件亦規範了使用者操作記錄的端點及日誌所需的結構化 detail 欄位，有助於前端實作合併功能與後續審計。

## 關鍵設計決策

- - 合併聯盟時若 LID 為空，則新增一個全新的聯盟，並將指定的 SiteLID 加入；若 LID 非空，則將 SiteLID 合併到該 LID 之下，不可為空。
- 使用者操作記錄的 detail 欄位需為 Dictionary<string, string> 轉 JSON，必須包含 message（事件詳細說明）、result（成功/失敗），若是站台聯盟合併還需帶入 mainSiteLID 與 mergeSiteLID 的逗號分隔列表。
- 取得 SiteLeague 的時間區段介面要求 startDate、endDate、startTime、endTime 四個參數皆為必填。
- 以 LID 查詢 SiteLeague 時，若不篩選 site，則將 site 參數設為 'all'。
