## 摘要

文件說明如何從 Naver Sports API 取得賽事資訊，包含兩個端點：比賽清單與單場詳情。清單依日期（昨天～後天）與球種過濾，排除聯盟名稱含「기타」的項目；海外球種需改用 upperCategoryIds 參數。根據比賽狀態（賽前、賽中、賽果）採用不同請求策略：賽前僅當快取無全名時才取單場，賽中另開線程請求，賽果跟清單一併請求。

---

## 關鍵業務規則

- - 抓取比賽清單後，必須過濾掉聯盟 (categoryName) 包含「기타」的比賽
- API 請求日期範圍固定為昨天到後天 (fromDate = 昨日, toDate = 後日)
- 海外分類 (如海外足球/棒球) 應使用 upperCategoryId 參數取代 categoryId；支援多個球種時用 upperCategoryIds 並以逗號分隔
- 高爾夫球種不進行抓取 (需人工確認範圍)
- 請求球種清單時不加 category (聯盟) 參數，取得後再過濾掉 기타 相關比賽
- 賽前：只在快取中無對應隊伍全名時才 call 單場 API 獲取 homeTeamFullName / awayTeamFullName
- 賽中：以獨立 thread 請求單場 API，確保即時更新
- 賽果：在抓取清單時同步請求單場 API，不另開 thread

---

## 關鍵設計決策

- - 採用兩個 API 分工：清單 API 提供比賽基本資訊與 ID，單場 API 提供隊伍全名、每節比分等細節，以平衡資料量與請求次數
- 快取球隊全名：首次獲取後存入快取，後續清單中已快取的隊伍不再請求單場，減少重複請求
- 依比賽狀態區分請求策略：賽中需頻繁更新故獨立線程，賽前按需請求，賽果不再變化可同步處理，優化資源使用
- 海外球種透過 upperCategoryIds 支援一次請求多個分類，提高批次效率
- 日期範圍固定為三天（昨到後），確保抓取近期足夠的比賽而不過度載入

---

## 注意事項

- ⚠️ - ⚠️ 高爾夫球種不抓的規則僅簡短提及，需確認是否為永久排除或需設定開關
- ⚠️ 清單中可能混入非比賽項目，過濾邏輯僅依賴 '기타' 文字，若有其他非賽事項可能無法過濾
- ⚠️ 海外與國內球種參數差異易混淆：海外用 upperCategoryId，國內用 categoryId，實作時需明確區分
- ⚠️ 文件未提及 API 調用失敗的重試機制或速率限制，需另外設計
