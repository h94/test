## 摘要

這是一份 Sprint 流程指引，定義從需求分析到上線的標準步驟與每日檢查清單。對 AI 開發而言，可了解團隊的開發節奏與關鍵檢查點，用於流程自動化或儀表板提示，但需注意文件可能已過時。

## 關鍵業務規則

- - Day(-3) 需完成：SM 與需求方確認 Story、安排開發/測試分析、請需求方講解需求、與需求方及成員討論時程
- Day(-2) 需建立 JIRA Sprint/Story/SubTask、Confluence 需求分析頁面、Git 分支，並執行 Sonarqube 取得警告數與 UT 覆蓋率
- 若 Story 較大（StoryPoint=13），需在需求分析階段召開 Design Review
- Day(0) Kickoff Meeting 需完成需求講解、StoryPoint 估算、安排 Release/Launch 負責人與 Code Review 人員
- Day(4) Code Review 階段需確認所有 Code Review 內容都已修改或記錄
- Day(6-8) Local Test 階段需確認 Sprint 進度是否正常
- Day(9) Release 若新增 Service/API 接口，須檢查 Gateway 配置並修改對應的 swagger.json
- Day(10) Launch 需安排 Merge 主線、監控上線系統、請成員填寫回顧會議內容
- Day(12) Sprint Close 需結束 JIRA Sprint 並回報 PRD 監控結果
