## 摘要

此文件定義了 TCZB Sprint 的標準流程，包含 Sprint 排程表、每日檢查清單及從需求分析到 Sprint 結束的完整步驟檢查清單。對 AI 開發無直接業務規則貢獻，但可作為團隊 Sprint 運作指引，幫助 AI 理解開發節奏與注意事項。

## 關鍵業務規則

- - Sprint 開始前 Day(-3) 需與需求方確認 Story、安排開發與測試分析，並請需求方講解需求。
- StoryPoint 為 13 的 Story 需召開 Design Review。
- 新增 Service / API 時，須檢查 Gateway 是否有配置，並修改對應的 swagger.json（修改 Swagger 步驟參考相關頁面）。
- Release 負責人須在 Code Review 後確認所有修改皆有記錄。
- Launch 時需安排人員 Merge 主線及監控上線系統狀況。
