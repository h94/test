## 摘要

本文件定義 GameSettingService 中「營運版商務號」的完整功能設計，包含商務號與其下帳號的 CRUD API、場中賽事設定規則、以及 DB Schema。對 AI 開發而言，這份文件提供了商務號模組的操作邊界、欄位驗證規則（如 ExtraPlayModes 可為 null、InplayCount 為每月次數）、以及賽事狀態機與 Redis Key 格式的明確規範，可直接用於生成 API 文件和測試案例。

---

## 關鍵業務規則

- - 新增商務號時，系統自動以申請的 Email 建立一個 admin 帳號，密碼預設為 12345678。
- admin 帳號可新增 trader 帳號，每個商務號最多新增 3 個 trader 帳號。
- 設定場中賽事時，需先判斷賽事狀態：pregame 狀態可設定為取消（Enabled=0），inplay 狀態只能設定為新增（Enabled=1），其他狀態不可設定。
- 場中賽事設定驗證通過後，寫入 Redis，Key 格式為 {gameType}_{sitelid}_{gdate}_{sitegid}。
- ExtraPlayModes 欄位可為 null（非必填）。
- inplayCount 欄位代表該商務號「每月」賽中場次次數上限。
- 帳號狀態改為停用時，若該帳號有既有登入資訊，必須一併刪除。
- 取得商務號月份賽中場次 API 的 month 參數格式為 yyyy-MM，回傳值為 Redis Key 陣列。

---

## 關鍵設計決策

- - 營運版商務號與既有 GS 訂閱者分離，獨立命名為「商務號」，以區分不同的後台機制。
- 商務號根據付費方案給予不同球種和賽中場次次數，帳號採取分層設計（admin / trader）。
- 場中賽事狀態驗證邏輯前置於寫入 Redis 之前，確保資料一致性。
- Redis Key 組合使用底線分隔的五段式結構，便於依維度查詢與清理。
