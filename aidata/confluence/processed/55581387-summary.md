## 摘要

本文件說明如何於現有會員服務（MemberService）中實作 Apple 第三方登入機制。因 Apple SDK 限制，使用者 email 僅在首次授權時提供，故設計 appleinfos_game 資料表儲存 Apple ID 與 email 的對應關係。後續登入時，透過 Apple ID 查表取得 email 後，即可重複使用原有第三方登入註冊流程，且 API 端點僅需透過 Site=apple 參數區分。

---

## 關鍵業務規則

- - Apple 第三方登入機制中，僅有第一次授權請求會攜帶使用者 email 資訊，後續請求不再提供。
- 為確保帳號關聯性，必須於首次收到 email 時將其與 Apple ID 一併儲存至 appleinfos_game 資料表。
- 會員登入 API（/memberservice/api/game/user/login/site）可透過帶入 Site=apple 參數觸發 Apple 登入邏輯，參數與回應格式不變。

---

## 關鍵設計決策

- - 採用獨立資料表（appleinfos_game）儲存 Apple 帳號資訊，而非直接修改會員主表，因其僅用於解決 Apple 首次授權後 email 缺失的登入關聯問題。
- 重複使用現有的第三方登入 API 端點（/game/user/login/site），僅透過 Site=apple 參數區分，避免為了單一登入方式新增獨立路由，保持 API 的統一性。
