## 摘要

本文件為 PriceCenterSite 定義 SportKing 相關服務的 API 規格，包含訂閱方案查詢（payment/subplans）、賽事隊伍分析（games/analysis/{gameType}/{lid}/{date}/{gid}）以及預測排行榜（predict/leaderboard/{gameType}/{lid}）。同時說明綠界支付整合：跳轉網址格式與回調（callback）API 的欄位規格及成功/失敗回傳字串。對 AI 開發可掌握 API 契約、欄位用途（如不同球種對應不同數據欄位）與支付流程中的關鍵參數。

---

## 關鍵業務規則

- - 各球種新增主要賠率站台：BK-au8、SC-188bet、BS-au8、HL-au8、FL-au8、ES-au8、其他-zba。
- 遊戲 analysis API 回傳資料中，ats、atS_Mar、oU_Mar 僅籃球使用；ml 僅足球、棒球使用；date 格式為 YYYYMMDD（例如 20230426）。
- 預測排行榜 API (predict/leaderboard) 為現有 API，已登入會員需額外傳遞 authKey 參數；回傳結果僅限前 100 名；並回傳登入會員在各時間區間（lastThirty, lastFourteen, lastSeven, thisKiller）的當前排名。
- 綠界支付回調 (ecpay/callback) 成功時回應字串「1|OK」，失敗時回應「2|FAIL」；CustomField1 欄位為 JSON 字串，內含 account、subid、ut 等資訊。
- 跳轉綠界支付頁面時需提供 subID（訂閱方案 id）與 authKey（會員 authKey）作為查詢參數。

---

## 關鍵設計決策

- - 採用 Razor Page 實作綠界支付驗證與跳轉，以伺服器端渲染確保安全性與簡化前後端分離。
- 比賽分析 API (games/analysis) 根據不同球種返回不同類型的賠率數據（籃球含走地數據，足球/棒球僅 ML），以減少無效欄位並降低資料傳輸量。
- 預測排行榜 API 使用現有 authKey 機制進行會員身份識別，而非重新設計 token，以保持與現有會員系統一致性。

## 注意事項

- ⚠️ - ⚠️ 文件標題提及「SportKing API」但內文未明確說明 SportKing 服務的用途或來源，需人工確認是否為外部服務或內部代號。
- ⚠️ 綠界支付回調規格中的 CustomField1 範例顯示 "ut": "xxx"，疑似為測試用 placeholder，上線前需確認正式值。
- ⚠️ Standing 範例中的 ML 欄位在籃球 (BK) 資料中為 null，與 analysis API 備註「ml 足球、棒球用到」一致，但需注意若未來籃球出現 ML 資料時，前端應能處理 null 值。
