## 摘要


本文件定義了 GameService 的 REST API 介面與 PostgreSQL 資料庫結構。對 AI 開發的幫助：1) 明確知道如何透過 API 查詢賽事、聯盟、隊伍資料（含一般賽事與資訊源賽事），並了解 show_detail 參數對回應欄位的影響；2) 理解 games_xx、sitegames_xx 等資料表的欄位用途與關聯，特別是 siteidmaps 欄位用於跨站台賽事 ID 對應（IDMAP 概念）；3) 掌握資料清理 API 的行為：自動刪除超過一年的賽事資料。

## 關鍵設計決策


- - 採用分表設計（games_xx、leagues_xx、teams_xx 等），表名中的 xx 推測為球種代碼（如 bk, bm 等），但文件中未明確說明分表規則。
- siteidmaps 欄位使用 JSONB 格式儲存同一場比賽在不同站點的 ID 對應，供 AutoMerge 合併與後續查詢／比對賠率使用，此設計稱之為 IDMAP 概念。
- show_detail 參數控制 API 回應欄位範圍：false 時僅回傳核心欄位，true 時額外回傳比數、節詳情、IDMAP 等詳細資料。
- 時間範圍查詢支援 partial 參數：只給 start 時，範圍為 start 當天 00:00~23:59；只給 end 時，範圍為 end 當天 00:00~end；都不給時預設為今天 00:00~23:59。
- 資料清理 API（clean_games、clean_sitegames）基於賽事時間自動刪除超過一年的資料，無需手動指定範圍。
