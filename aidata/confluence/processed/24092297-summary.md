## 摘要

此文件說明如何實作賽事基底變化（gtime）的偵測、記錄與同步機制：透過定時任務比對 games 表的 sitegid 與 Redis 中的 gtime，將不一致的賽事寫入 datum_log 表，同時更新 games 表和 zba sitegames，並提供兩個 API 供寫入與查詢變化紀錄，讓第三方可以獲取合併資料的變更資訊。

---

## 關鍵業務規則

- - 當賽事基底 gtime 變更時，必須同步更新對應的 games_{gameType} 表與 zba sitegames
- 變化紀錄保存於 datum_log 表，以 gdate、gametype、league、gid 作為主鍵，包含修改前後的時間
- 第三方可透過 GET /pricecenter/api/log/datum/{gDate}/{gameType}?league=&gid= 查詢指定日期與聯賽的賽事變化紀錄

---

## 關鍵設計決策

- - 以定時任務（xxl-job）週期性比對今明兩天的 games 表與 Redis 中的 gtime，而非事件驅動，降低耦合
- 選用 Cassandra 模型（datum_log）儲存變化日誌，以日期和類型為分區鍵，聯賽與賽事 ID 為集群鍵，便於按時間和類型快速查詢
- 同時更新 games 表和 zba sitegames，確保價格中心與合併資料的一致性
