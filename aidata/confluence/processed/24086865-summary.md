## 摘要

本文件定義了產出聯盟戰績總覽所需的 JSON 格式、後端資料庫結構（涵蓋棒球、籃球、冰球、美足四種球類）與一組新增／匯出 API。對 AI 開發而言，可掌握戰績數據在不同運動間的欄位差異、如何透過 POST /overview/{gameType} 寫入資料、以及前端只取單一 JSON 檔的設計前提，有助於理解爬蟲輸出與 PriceCenterService 積分計算的資料來源。

---

## 關鍵業務規則

- - 部分較大的聯盟直接爬取官網資料，不經過其他轉換。
- 「一對一」頁面僅需顯示已點選的 A 隊與 B 隊對戰資料，不需提供選擇其他隊伍的功能。
- 前端每個頁面只需讀取一個 JSON 檔案（如 overview.json 或 rank.json），以減少前端邏輯動作。

---

## 關鍵設計決策

- - 以 gameType 路徑參數區分不同運動類型（BS=棒球, BK=籃球, HL=冰球, FL=美足），共用同一 API 路由。
- 採用依運動分別設計的 DB 表格結構，各表的必要欄位不同（例如棒球無和局、籃球多了 conf/div/home/road 等），以反映真實賽事統計差異。
- 前端採用靜態 JSON 檔案模式，由後端定期匯出，減少即時查詢壓力。
- API 提供 POST /overview/{gameType} 供爬蟲寫入最新戰績數據，並提供 GET /system/overview/{gameType} 匯出彙整後的 JSON。
