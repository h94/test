## 摘要

本文件定義了 NewLotterySite 專案中四個社群與排行相關的 API 端點設計：錦標賽排行榜、玩家搜尋、關注列表與通知中心。重點說明了排行榜 API 針對訪客與已登入會員的回傳資料差異（訪客僅顯示總獲利，隱藏其他數據設為 -1），以及關注功能的上限為 100 位。對 AI 開發而言，這份文件提供了精確的 Request/Response 規格與權限區隔邏輯，可直接用於生成 API 接頭與測試案例。

---

## 關鍵業務規則

- - 排行榜 GET championships/{gameType}/{id}/leaderboard：訪客（未登入）僅可查看每位玩家的總獲利 (profitPoint)，其他數據如勝率、平均賠率等皆回傳 -1 隱藏；已登入會員可查看完整數據並取得自己的排名 (myIndex)
- 關注功能 POST /users/{authKey}/focus：每次請求最多新增 1 筆關注，不可批次新增多筆使用者
- 關注數量限制：每位使用者最多可關注 100 位其他使用者（文件註記：使用者關注最多 100 位）
- 通知中心 GET /notifications：lang 參數預設值為 zh-TW，若未傳入則以此預設值回傳繁體中文通知內容
- 排行榜排名依據：系統根據總獲利 (profitPoint)、勝率 (winPercentage)、平均賠率 (avgWinOdd) 對玩家進行排序，排名欄位 (rank) 由 API 直接回傳

---

## 關鍵設計決策

- - 訪客隱私與數據保護：設計上訪客僅能看到總獲利，其餘統計數據以 -1 標記，這可能是基於保護玩家詳細數據隱私或商業機密的考量（需人工確認具體策略原因）
- 關注功能限制單筆新增：設計成每次請求只能新增 1 筆而非批次處理，可能為了簡化錯誤處理或避免超大量請求的複雜度（需人工確認）

## 注意事項

- ⚠️ - ⚠️ 文件標註「排行榜目前因目前沒有VIP機制」，暗示 VIP 機制未來可能導入並改變排行榜的存取權限，目前設計為臨時方案，需持續關注 VIP 需求變更
- ⚠️ 使用者互動設計章節中的 Response 範例顯示「有登入」狀態下 myIndex 僅回傳 uid 與 rank，但細節中玩家自己的完整數據已包含在 details 陣列中，前端需自行比對 uid 取得個人細節，此設計可能造成混淆
