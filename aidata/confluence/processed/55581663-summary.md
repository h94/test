## 摘要

本文說明透過雷速 (Leisu) API V2 獲取籃球比賽資料的方式。主要調用兩個端點：match/list 用於增量變動數據（1min/次），match/diary 用於定時全量賽程賽果（當天10min、未來30min）。FetchGame 負責組合場地、聯賽、球隊資訊並維護 inplay cache；GetInplayInfo 則獲取即時統計並從 cache 取出已組合比賽送出。對開發 crawler 服務（leisuparserv2）提供了數據整合流程與呼叫頻率的明確規範。

---

## 關鍵業務規則

- - match/list API 僅查詢前30天比賽資料，首次全量使用 id 參數，後續增量使用 time 參數，建議 1 分鐘查詢一次。
- match/diary API 僅查詢前後30天賽程賽果，當天賽程建議 10 分鐘全量更新，未來賽程建議 30 分鐘全量更新。
- 所有 API 請求的 payload 必須包含 user='dgc' 與 secret='d936105a4e78666150'。
- FetchGame 必須先呼叫 info API 獲取 LocationInfo、LeagueInfo、TeamInfo 再組合成比賽字典，並將進行中比賽加入 inplay cache。
- GetInplayInfo 從即時統計 API 取得資料後，必須從 inplay cache 取出已組合的比賽資料一併送出。

---

## 關鍵設計決策

- - 採用兩個 API 分離增量更新（match/list）與定時全量（match/diary），以平衡即時性與負載。
- 集中由 FetchGame 負責比賽資訊組合與 inplay cache 建立，避免重複調用 info API 並加速 GetInplayInfo 回應。
- inplay cache 機制使即時統計資料能直接搭配已組合的比賽數據，減少延遲。
