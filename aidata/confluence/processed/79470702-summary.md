## 摘要

這份文件定義了球王社群系統使用的資料儲存結構，包含文章、hashtag、按讚及檢舉等主要資料表。文章與相關元數據主要存放於 Meilisearch 的 community index，點讚記錄獨立存放在 like index，檢舉資料則使用 Cassandra 資料庫的 report table。對於 AI 開發者，可以快速掌握社群內容的資料模型、索引設計及關聯關係，便於設計查詢、寫入與資料同步邏輯。

---

## 關鍵業務規則

- - 文章類型（articType）僅有 normal（一般文章）與 predict（預測單）兩種，過濾時需以此為準
- 預測單內容（predictContent）為 JSON 結構，包含賽事資訊、讓分、賠率及勝負結果等欄位
- 文章 JSON 中的按讚數量（like_count）僅記錄各 emoji 總數，實際按讚明細需從獨立的 like index 查詢，且 content_type 區分文章（article）或留言（comment）
- 檢舉狀態（status）僅有 open（已提交尚未處理）與 done（處理完畢）兩種，不可使用其他值
- hashtag 資料分三種固定類型（leagues、articTopics、memberShips），各自儲存多語系標籤，不允許動態新增類型

---

## 關鍵設計決策

- - 選擇 Meilisearch 作為文章、hashtag 及點讚的儲存，以支援高效全文搜尋與多條件過濾（如按遊戲種類、聯盟、會員等）
- 將按讚總數與按讚明細分離，文章 JSON 僅保留總數，細部記錄放在獨立 index，既可減少文章資料量，又保留查詢明細的彈性
- 檢舉系統使用 Cassandra 而非 Meilisearch，因為此類資料以單筆寫入與查詢為主，無需搜尋引擎功能，且 Cassandra 更適合日誌型高寫入場景
- hashtag 採用結構化 JSON 存入單一 index，並以 hashtag_type 區分類別，避免為每種 hashtag 建立獨立索引，降低維護複雜度
