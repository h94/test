## 摘要

本文详述了针对 188bet 体育网站的爬虫实现：通过模拟登录获取验证码，分赛前、赛中、赛果三条链路抓取足球比赛数据。赛前使用队列与线程并发收集比赛 ID 并调用详情 API 推至 Kafka；赛中采用 Selenium 获取完整页面并按标志位截取所需 HTML；赛果以 JSON 包裹 HTML 形式发送；语系仅输出英文 namemap。对 AI 开发此抓取逻辑提供了具体 API 调用方式、数据截取边界和消息格式。

---

## 關鍵業務規則

- - 球种只抓足球，站台球种代号为 1
- 所有后端 API 请求必须携带验证码头部，否则返回 401
- 赛果数据抓取当天和昨天的页面，HTML 内容嵌入 JSON 的 data 字段，并附带 tczb、machinename、timestamp 等元信息
- 语系只发送英文 namemap，键固定为 “EN_SC_List”，data 为字典格式
- 赛中 HTML 切分起始标记为 “主要市场”，结束标记为 “sbk-footer-container”
- 赛前从 today 页面抓取当天所有比赛 ID，从 early 页面通过联盟 API 获取明天和后天比赛 ID，统一放入队列，由独立线程消费并调用比赛详情接口，结果发送 Kafka

---

## 關鍵設計決策

- - 采用队列（queue）+线程模式分离 ID 收集与数据处理，实现并发请求，提高抓取效率
- 赛中数据使用 Selenium 抓取整页 HTML 后按固定文本标记截取，以减小传输和存储的数据量
- 验证码通过模拟登录接口获取，从响应头直接提取，避免复杂的会话管理
- 赛果数据以统一的 JSON 结构包裹原始 HTML，并附加机器名和时间戳，便于下游服务识别与处理

## 注意事項

- ⚠️ - ⚠️ 验证码提取未指定 header 的具体字段名，需人工确认取自哪个响应头（例如 X-Request-Token 等）
- ⚠️ 赛中 HTML 截取依赖页面结构，若站点改版导致标记文本变化，可能失效
