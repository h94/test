## 摘要

本文件定義新運彩（金葡京）代幣（鑽石）系統的 API 與資料庫設計，涵蓋會員代幣錢包交易紀錄與彩池抽成紀錄。MemberService 提供新增及查詢代幣交易（T_Type 1~6,77），PaymentService 處理彩池抽成（ticket/sell），NewLotteryBackEndService 設定彩池群組資訊。資料儲存採用 MySQL（錢包與交易）與 Cassandra（彩池抽成），並參考球王Z幣設計。

---

## 關鍵業務規則

- - 代幣交易類型 T_Type=2（轉帳）時 T_UID 為必填，其他類型可為 null。
- 查詢特定帳號代幣交易紀錄時，僅返回最近 90 天內資料。
- 彩池抽成類型 CType='sell' 時，Source_Game 為必填，格式為 {lid}_{gdate}_{gameid}；CType='ticket' 時無此欄位。
- 彩池抽成紀錄的 betpool 格式為 {球種}-{彩池群組id}-{彩池種類}-{種類期數}。

---

## 關鍵設計決策

- - 代幣系統設計參照球王Z幣，使用 MySQL 作為交易持久化儲存。
- 錢包與交易記錄存於 MySQL，彩池抽成明細存於 Cassandra，分散儲存壓力。
- 彩池抽成表以 betpool 為 partition key，id 為 clustering，優化按彩池查詢效能。
- 取得交易紀錄 API 預設當日，支援日期範圍查詢，但單一帳號查詢強制限制 90 天範圍。

## 注意事項

- ⚠️ - ⚠️ T_Type=6 的格式為暫定，可能變更。
- ⚠️ DB schema 中 T_ID 欄位類型為 text 但標註 AUTO_INCREMENT，明顯有誤，需人工確認應為整數。
- ⚠️ 文件中標註「沒有做」代幣轉帳，但 API 包含 T_Type=2（轉帳），可能尚未實作或另有限制。
- ⚠️ API 範例中 Coin 正負未明確說明，需確認是否正數一律表示入帳，負數表示扣款。
