## 摘要

此文件定義了從 7M 網站爬取足球和籃球即時比賽數據的技術規格。足球需在比賽開始後第15、30、45、60、75、90分鐘時抓取並寫檔；籃球則在每節結束前及比賽剩餘第5、6分鐘時觸發寫檔。提供了對應的 API 端點和參數格式，並指定籃球僅需提取主客隊統計數據（h_stat_t、a_stat_t）。內容有助於實現定時爬蟲流程與資料儲存邏輯。

---

## 關鍵業務規則

- - 足球比賽開始後的第15、30、45、60、75、90分鐘時觸發抓取並寫檔。
- 籃球每一節結束前觸發寫檔（例如倒數至00:38左右），以及比賽剩餘時間為第5分鐘、第6分鐘時觸發寫檔。
- 足球的數據分析欄位並非每場比賽都有，多數比賽沒有，需處理缺失情況。
- 籃球僅需要抓取 h_stat_t 和 a_stat_t 兩個統計物件。
- 足球 API 格式：https://data.7mdt.com/goaldata/ft/{game_id前四碼}/{game_id}.js?nocache={13位時間戳}
- 籃球 API 格式：https://px-bdata.7mdt.com/stat_data/{game_id}/index_big.js?_={13位時間戳}

---

## 關鍵設計決策

- - 籃球部分僅取 h_stat_t 與 a_stat_t，忽略其他統計數據，以簡化資料儲存與處理。
- 使用 nocache 或 _ 參數帶入13位時間戳，避免 API 緩存影響即時性。
- 足球儘管多數場次無數據分析欄位，仍統一嘗試抓取，可能採取容錯機制跳過空數據。

---

## 注意事項

- ⚠️ - ⚠️ 足球的數據分析欄位「不是每場比賽都有 多數都沒有」，需在程式中有對應的缺失處理邏輯。
- ⚠️ 籃球寫檔時間點「每一節結束前」和「剩餘第5、6分時」具體時間定義模糊（例如Q1 00:38 僅為範例），需與需求方確認確切的觸發條件。
- ⚠️ 足球比賽開始後的時間點是否包含傷停補時或僅為常規時間，文件未說明。
- ⚠️ 足球 game_id 前四碼作為路徑，但 game_id 長度和規則需在實作時驗證。
