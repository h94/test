## 摘要

本文件規劃新運彩預測系統的資料儲存與 API 設計。定義了存於 Cassandra Predict 資料庫的動態表 newlottery_predictbets_{gameType}，用於記錄用戶對賽事的預測注單。提供三個 REST API：新增注單、查詢會員時間區段內注單（支援預設時間範圍與跨聯盟查詢）、更新注單結果。查詢接口包含靈活的預設時間邏輯，如未提供日期參數則預設近31天。整體為 predictservice 的核心功能設計。

---

## 關鍵業務規則

- - 注單表名稱格式為 newlottery_predictbets_{gameType}，gameType 由 API 路徑參數動態決定。
- 每筆注單由組合分區鍵 (lid, gdate, gid, uid, id) 唯一識別，lid 為聯盟ID，gdate 為賽事日期，gid 為賽事ID，uid 為會員ID，id 為注單ID。
- GET 查詢注單時，若 startdate 和 enddate 均未提供，預設查詢近31天（包含今日）的資料。
- GET 查詢注單時，若只缺 enddate，則 enddate 預設為當天日期。
- GET 查詢注單時，若只缺 startdate，則 startdate 預設為當天往前30天的日期。
- GET 查詢注單時，若需取得指定 gameType 下不分聯盟的所有注單，可將路徑參數 lid 設為 'all'。
- PUT 更新注單結果時，僅能更新 winloss、status、profitpoint 三個欄位，其它欄位不可透過此 API 修改。
- 新增注單時，路徑中的 gameType 決定注單歸屬的球種表，不可跨表移動。

---

## 關鍵設計決策

- - 選用 Cassandra 作為儲存資料庫，推測因其分散式特性以支援高寫入吞吐量（文件中未說明原因）。
- 按 gameType 動態建立資料表，隔離不同球種的注單資料，降低單表資料量並可能提升查詢效能（未說明原因）。
- 採用 (lid) 為 partition key，搭配 (gdate, gid, uid, id) 為 clustering columns，以支援依聯盟和日期範圍的常見查詢模式。
