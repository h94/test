## 摘要

此文件定義了賽事會員預測解鎖操作次數相關的 API，包含 POST 新增次數與 GET 獲取次數兩個端點。使用 Redis 記錄當日操作次數，資料保存 1 天後自動過期。非訂閱賽事會員解鎖預測有次數限制，但具體次數上限未明確，GET 回傳固定為 string 型別 '0' 或 '1'，可能表示當日是否還能解鎖。實作時需注意 Redis key 組成、authKey 參數驗證，以及每日次數重設邏輯僅依賴 TTL。

---

## 關鍵業務規則

- - 非訂閱賽事會員進行預測解鎖時有操作次數限制，超過限制當日不可再解鎖（具體限制次數需人工確認）
- 當日的解鎖操作次數記錄只在 Redis 中保存 1 天，隔天自動失效，次數重置

---

## 關鍵設計決策

- - 選用 Redis 作為記錄存儲，利用鍵過期機制（TTL 1 天）達到每日自動重置次數的目的，避免額外排程清理
- API 路由使用 authKey 作為路徑參數，應為會員識別或授權密鑰
- GET 回應設計為簡單字串 '0' 或 '1'，而非 JSON 結構，可能為簡化前端判斷邏輯或歷史包袱（需人工確認）
