## 摘要

本文件說明如何將官方站台的設定從站台層級（IsOffice）細化到球種層級（GameTypeIsOfficial），以滿足不同球種可指定不同官方站台的需求。核心變更是 AppSettings 中的站台設定格式，將原本的布林值 IsOffice 取代為陣列 GameTypeIsOfficial，用於列舉該站台作為官方站台的球種代碼（如 BS、BK、SC）。此變更影響多個自動合併流程（AutoCombineGame、AutoCombineTeams、AutoCombineLeague），需將內部邏輯從讀取 IsOffice 改為調用 getOfficeSites 函式來根據球種動態判斷官方站台，同時標記多個舊版 Function 和 API 為棄用。

---

## 關鍵業務規則

- - GameTypeIsOfficial 與 IsOffice 不相關，兩者邏輯獨立，不應混用。
- 若站台設定中包含 GameTypeIsOfficial 陣列，則該站台為陣列內指定球種的官方站台；若未設定 GameTypeIsOfficial，則該站台不是官方站台。
- IsOffice 欄位應拋棄不用，所有判斷官方站台的邏輯需改用 GameTypeIsOfficial。
- 官方站台資訊最終需透過 setOfficeData 函式寫入 odds Table。

---

## 關鍵設計決策

- - 新增 GameTypeIsOfficial 陣列而非沿用 IsOffice：為了支援按球種區分官方站台，且避免與舊有 IsOffice 邏輯混淆，因此引入新欄位並明確棄用舊欄位。
- 棄用多個舊版合併 Function（如 AutoCombineGame、setOfficeData、compareAndCombine）：這些 Function 以 Bet365 為中心進行合併，且僅支援站台層級的官方設定，無法滿足球種級別的需求，故需重構為新版（AutoCombineGameII 等）。
- 影響 UpdateMatch 中的 OfficeUpdate 策略：此策略負責更新官方賽事資料至資料庫，其餘策略不受影響。
