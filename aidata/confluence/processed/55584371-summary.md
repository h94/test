## 摘要

這是一份 Sprint 流程操作檢查清單，定義了從需求分析、開發、測試到上線回顧的標準步驟與檢查點。文件規範了像是 Story 確認、時程估算、JIRA Sprint 建立、Code Review、Swagger 文件更新、Release/Launch 負責人安排等流程。對 AI 開發而言，此文件提供了團隊如何協作與管理 Sprint 的參考，但與具體服務的功能開發無直接關係。

---

## 關鍵業務規則

- - Sprint 開始前 3 天，SM 須與需求方確認 Story、安排開發測試分析、請需求方講解需求、討論時程並公告。
- Story Point 為 13 時，須召開 Design Review。
- Release 時，若有新增 Service 或 API 接口，須檢查 Gateway 配置並修改對應的 swagger.json。
- Launch 後，須安排人員 Merge 主線、監控上線系統狀況，並請成員填寫回顧會議內容。
- 每日需確認 JIRA Work Log 填寫、進入測試階段確認 Bug 收斂、下班前確認 JIRA 問題與回覆，並對需要長期關注的線上問題於 JIRA 開 Task 監督。
