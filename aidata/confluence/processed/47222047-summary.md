## 關鍵設計決策

- - 將會員相關 API 路由從 auth/ 統整到 users/ 底下，以符合資源導向的 RESTful 設計，明確區分認證與用戶資源
- 部分更新操作（修改暱稱、重置密碼、修改密碼）的方法由 POST 改為 PUT，更貼近 HTTP 規範語義
- 註冊驗證 API 的參數名從無明確指定改為使用 Authkey 與 EMail，使輸入更明確
- 第三方登入加入 Site 與 SiteID 參數，支援 google、discord、line 三種外部登入
