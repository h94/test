## 摘要

本文件定義 MemberService 的九個 REST API 端點，包含註冊、註冊驗證、登入、忘記密碼、重設密碼、更改密碼、修改暱稱、取得會員資料等。每個端點列出路由、請求參數、回傳格式及前端對應的任務，並設想需要建立 member 與 logs DB。對 AI 開發會員服務時，可作為早期 API 設計的參考，了解參數命名、錯誤碼語意及服務依賴（如 Token 驗證、寄信功能）。

---

## 關鍵業務規則

- - 註冊：需提供 Finger（設備指紋）、Account（信箱）、Password、UserName；失敗案例包含格式錯誤或信箱已註冊。
- 註冊驗證：需提供 Finger、AuthKey、Account；失敗案例包含已驗證過或驗證碼錯誤。
- 登入：需提供 Account、Password、Finger；失敗案例包含格式錯誤或帳號密碼錯誤。
- 忘記密碼：需提供 Account、Finger；失敗案例包含信箱錯誤；成功後呼叫寄 Mail 功能。
- 重設密碼（forgetpassword）：需提供 AuthKey、Account、新密碼、Finger；失敗案例包含新密碼格式錯誤或資料過期需重新申請。
- 更改密碼（changepassword）：需提供 Account、OldPassword、新密碼、Finger；失敗案例包含新密碼格式錯誤。
- 修改暱稱：需提供 Account、UserName；失敗案例包含暱稱已重複或格式錯誤。
- 取得會員資料（GET /memberdata?account）：未定義失敗案例，回傳 MemberModel。
- 登出：此版本未實作，僅有前端畫面任務。

---

## 關鍵設計決策

- - 所有端點均使用 POST 方法，除了取得會員資料使用 GET。
- 請求與回傳均採用 JSON 格式，回傳統一包含 code 與 message 欄位（成功 code 2000）。
- 涉及身份驗證的流程（註冊、忘記密碼）需要外部 Token API 支援，前端需串接取得 Token API。
- 註冊與忘記密碼功能需要寄送郵件，後端需整合寄信服務。
- 前端需實作模糊訊息處理（如將後端錯誤訊息對應成對用戶友好的提示）。
