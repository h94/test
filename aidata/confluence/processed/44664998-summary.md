## 摘要

本文件定義了 TCZB 團隊從 Sprint 規劃、需求分析、開發、測試到上線的完整流程與每日檢查清單。涵蓋各階段（Day-3 至 Day+12）的具體任務，包括 Design Review 觸發條件（StoryPoint=13）、Code Review、Release 時對新 Service/API 的 Gateway 與 Swagger 確認，以及 Retro 回顧。對 AI 開發的幫助在於可據此設計 Sprint 輔助自動化流程（如日程提醒、品質閘門檢查），不直接影響服務業務邏輯。

---

## 關鍵業務規則

- - StoryPoint=13 的 Story 需召開 Design Review
- Release 階段若有新增 Service 或 API 接口，須檢查 Gateway 配置並更新對應 swagger.json
- 測試階段後期，成員必須補齊分析文件
- 上線後需安排人員 Merge 主線並監控系統狀況
- 每日站會要了解成員問題，若影響時程應盡速回報上級
- 每日確認所有人已填寫 JIRA Work Log，且 JIRA 問題與回覆均完成
