## 摘要

這份文件定義了 1xbet 賠率爬蟲的三步驟流程：呼叫 API 取得 JSON 賽事資料、將原始資料 Mapping 到內部標準化的賠率格式、最後以 Match.MATCH 格式寫入資料庫。文件核心價值在於提供完整的欄位對照表，包含各球種（足球、棒球、籃球、冰球、美足）的 GameInformation 結構、PlayMode 玩法代碼、以及 PreGame/InPlay 的賽事狀態分類，是開發 1xbet parser 的必要技術規格書。

## 關鍵設計決策

- - 採用三步驟流程：API 呼叫 → Mapping 標準格式 → 寫入 DB，將爬取與資料轉換分離
- 以 Match.MATCH 作為統一資料格式寫入資料庫，確保不同爬蟲來源的資料結構一致
- 使用 Code 對照表將 1xbet 原始欄位映射到內部標準化 Key（如 O1=主隊名稱、O2=客隊名稱、C=賠率、P=球頭、T=賠率KEY）
- 球種以 SE 欄位識別，支援 SC(足球)、BS(棒球)、BK(籃球)、FT(美足)、HL(冰球)
- PlayMode 分為 PreGame（賽前）和 InPlay（滾球）兩大類，各自有不同的玩法代碼組合（如 HA、OU、Correct Score 等）
- 局數使用 P 作為 Key，以數字編碼區分不同局/節/半場（如棒球 1-9 局用 1-9，1-2 局用 10102，籃球上半場用 11）
- 戰績資料(PBP)與賠率資料分開 Mapping，使用不同的 GameInformation Code 結構

## 注意事項

- ⚠️ - ⚠️ 文件最後更新於 2021-10-25，部分 PlayMode 標注為 'DONE' 但部分未標注狀態，需人工確認目前進度
- ⚠️ 賠率 Key 和 Code 的對照表中，H 對應多個 Code(1,7,3829)，O 對應多個 Code(9,11,3827,7778,13,7780)，需確認這些重複 Code 的使用場景差異
- ⚠️ 戰績資料中的棒球欄位（Hits1、Ball、Strike、Out、Base1-3）使用不同於其他球種的 Key 命名規則，需特別處理
- ⚠️ 文件中提到 '需要確認什麼是 TCZB-913'，需求編號與實際內容的對應關係不明確
- ⚠️ 籃球單節玩法標注 '只有籃球類,NBA冠軍賽才有'，此限制條件需在程式中實作
