## 摘要

定義了一個根據遊戲 ID 列表取得各站點讓分（spread）的 API，供 GameSetting Tools 檢查賽事合併資料使用。API 以 POST 方法調用 /pricecenter/api/frontend/sitegames/{gameType}，傳入 gids 陣列，回傳 GameSpread 列表，其中每個 GameSpread 包含 GID 與 SiteGameSpreads，SiteGame 則提供站點名稱與主讓分串（如 HA:-1.5,OU:2.5）。對 AI 開發而言，可據此取得特定賽事在不同站點合成的讓分概覽，並了解請求與回應的資料結構。

## 關鍵設計決策

- - 採用 POST 方法而非 GET，以便在請求體中傳遞 gids 列表。
- 路徑使用 {gameType} 參數區分不同球種，保持 API 路徑一致性。
- 回傳結構以 GID 為單位聚合各站點讓分，且將亞盤（HA）與大小球（OU）合併為單一字串，簡化前端解析。
