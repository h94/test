## 摘要

這份文件定義了 PriceBackEndService 中兩個和股票使用者操作記錄相關的 API：一個是取得所有有記錄的股票使用者帳號清單，另一個是根據帳號查詢其操作記錄。對 AI 開發的幫助在於：清楚說明查詢操作記錄時的查詢參數規則（startTime/endTime 的預設行為）、API 的回傳結構（包含 BrokerCondition 巢狀物件），以及 LogInfoDTO 的欄位定義。這些資訊可以直接用於 API 整合、測試案例設計和資料模型建立。

---

## 關鍵業務規則

- - 若 startTime 沒帶值，則取一天內的紀錄（從請求時間往回推一天）
- 若 startTime 有帶值但 endTime 沒帶值，則取 startTime + 一天的紀錄
- 若 startTime 和 endTime 都沒帶值，則取「現在時間 -1 天」到「現在時間」內的紀錄
- type 查詢參數可指定操作類型，文件中以「分點進出」為例（需人工確認：是否為必填參數，或還有哪些可用 type 值）

## 關鍵設計決策

- - API 1（取得股票使用者）先回傳有操作記錄的帳號清單，再由 API 2（取得操作記錄）根據帳號查詢明細，採用兩段式查詢而非一次回傳所有使用者的完整記錄，降低單次回應資料量
- 時間查詢採用 Unix Timestamp（long 型別），如 AddTime 為 1650008340，確保跨時區一致性
- LogInfoDTO 中包含 BrokerCondition 巢狀物件而非只存 Broker ID，這表示查詢操作記錄時會直接嵌入當時的市場條件設定（價格、券商、日期區間等），便於重現使用者操作脈絡
- StockStrategy 使用 List<string> 而非單一字串，支援多策略組合操作
