## 摘要

本文详细规划了 AI Review Server 的升级方案，核心目标是：1) 实现 Plan Review 功能，并限定仅审查 `_plans/` 第一层下的 `.md` 文件；2) 引入 Validation Spec 提取机制，将 Plan 检查规则与撰写模板分离；3) 实现语言感知的规则加载，对 C# 和 Python 项目分别加载对应的规则文件，并统一以 `general.mdc` 为基底；4) 增加 Git 帐号追溯（`triggered_by`）与多供应商 AI 备援机制。本文提供了明确的架构差异对照、分流逻辑、代码修改清单与实作步骤，是此次升级的完整技术蓝图，对开发人员理解新架构、实施代码迁移有直接帮助。

---

## 關鍵業務規則

- - Plan Review 仅检查 `_plans/` 目录下第一层的 `*.md` 文件，排除所有子目录（如 `_plans/_reference/`、`_plans/legacy/` 等）以及非 `.md` 文件
- Plan Review 的规则输入必须是 `generalrules/.cursor/rules/general.mdc`（通用规范）与 PLAN_SPEC.md 中「## Commit 前檢查規範（Validation Spec）」区块的合并结果，而不应包含整份 PLAN_SPEC.md 模板本体
- Code Review（C# 或 Python）的规则输入必须以 `generalrules/.cursor/rules/general.mdc` 为首段，然后再拼接语言专属规则
- C# 语言专属规则路径为 `csharp/.cursor_rules`；Python 语言专属规则为特定 bundle（包含 fastapi/flask/service/async-service 等规则文件）
- Python 的框架判定不由 Server 端实现，而是委托给 AI 根据 `generalrules/.cursor/rules/general.mdc` 和完整的规则内容自行判断
- Push/MR 事件发生时，若变更文件同时包含 `.cs` 和 `.py`，视为不支援场景，整次事件不进 AI 审查，仅记录 Kafka log
- 分流后若既无 Code 变更也无 Plan 变更，review_events 状态需结案为 'completed'（但不产生 review_runs），并记录 Kafka log，不发 Rocket.Chat 或 MR 评论
- MR Webhook 仅处理 action 为 'open'、'update' 或 'reopen' 的事件（白名单制）
- `review_runs.rules_version` 字段必须记录 aidata repo 当前的 commit SHA，不得使用硬编码
- 每次 AI 审查（Code/Plan）完成后，DB、Kafka、Rocket.Chat/MR 中必须能追溯本次所使用的规范来源清单
- 触發者（Git 帐号）必须写入 `review_events.triggered_by`，并在 Rocket.Chat 摘要和 MR 评论中显示；Push 事件来源为 `user_username`，MR 事件来源为 `user.username`
- 多供应商 AI 备援：依 `AppSettings:AI:Endpoints` 配置的数组顺序尝试，仅使用 ApiKey 与 ApiUrl 皆非空的端點；单一端點内失败后重试最多 `MaxRetries` 次才切换至下一个端點
- AI 回应中必须包含 `status`（pass/fail）和 `unresolved_count` 字段，并经过 schema 验证
- 对 GetMrChangedFilesAsync 的 rename 场景，若同时返回 old_path 和 new_path，路径列表需去重；若变更仅为删档且无其他符合分流规则的路径，则视为无该类变更

## 關鍵設計決策

- - 决定不保留旧的 `LoadConsolidatedRulesAsync` 方法，全面改用新的语言感知方法 `LoadMultiLanguageRulesAsync`，以实现规则加载的统一与语言感知
- 决定 Server 端不做 Python 框架判定，而是将判定逻辑委托给 AI。理由是避免 Server 端与框架细节耦合，通过更新 `general.mdc` 即可灵活调整规则，无需修改代码
- 决定引入 `generalrules/.cursor/rules/general.mdc` 作为所有审查（Code/Plan）的通用规范基底，以实现集中治理、统一维护，避免各审查线规则漂移
- 决定在无有效代码或 Plan 变更时，不创建 review_runs，但仍将 review_events 状态设为 'completed' 并记录 Kafka log。目的是为了可观测性，同时避免无意义的通知干扰
- 决定 `review_runs.rules_version` 记录 aidata repo commit SHA，以精确追溯审查时使用的规则版本，提高问题排查的可复现性
- 决定采用「规范来源全量提供 + AI 自报 + 白名单验证」策略，由 AI 声明其应用的规则，Server 端进行合法性校验，以解决规范来源的精确追溯问题
- 决定将语言检核（zh-TW）改为字段门槛制，并取消对简体字的严格禁止，以避免因技术术语中混用中英文字符而导致不合规的误判
- 手动 Trigger API 增加可选 `beforeCommitSha` 与 `afterCommitSha` 参数，用于开发/测试场景下的精确文件比对，其优先级低于 `mergeRequestIid`
