## 摘要

這份文件定義了從 NowScore 網站抓取足球與籃球走地即時統計資訊的技術規格。對 AI 開發的幫助在於：明確了資料獲取的觸發時間點（足球每15分鐘、籃球每節末及特定剩餘分鐘數）、API 端點與參數格式，以及最終要寫入的 JSON 輸出結構和 stats_mapping 對照表。開發人員可據此實作定時爬蟲與資料正規化邏輯。

---

## 關鍵業務規則

- - 足球走地數據應在比賽開始後的第 15、30、45、60、75 分鐘時觸發寫檔。
- 籃球走地數據應在每一節結束前（如 Q1 00:38）及該節剩餘第 5、6 分鐘時觸發寫檔。
- 足球數據的輸出 JSON 結構需包含 Time, stats（含 type, home, away）, at_time 欄位。
- 籃球數據的輸出 JSON 結構需包含 Time, stats（含 type, home, away）, at_time 欄位，其中 type 包含 '3分球進球數', '2分球進球數', '罰球進球數', '剩餘暫停數', '犯規數', '罰球命中率', '總暫停數', '總分'。
- 籃球數據需額外計算並加入 '2分球進球數', '2分球命中率', '3分球命中率', '罰球命中率', '總的籃板' 這些統計項。
- 足球 API 端點為 https://live.nowscore.com/football/GetDetailin?scheduleId={game_id}&_={timestamp}，需代入比賽ID和當前時間戳。
- 籃球 API 端點為 https://live.nowscore.com/data/bbschlive/detail/{game_id}.txt?t={timestamp}，需代入比賽ID和當前時間戳。
- 目前籃球 API 返回的數據不一定完整，文件註記以賽果比賽的數據作為替代範例（⚠️需確認此為暫時替代方案還是永久限制）。
- 使用 stats_mapping 將 API 返回的代碼轉換為中文 type 名稱（例如 SC.0 -> '角球', BK.1 -> '3分球進球數'）。

---

## 關鍵設計決策

- - 數據寫入採用定時觸發機制，而非事件驅動，根據比賽經過時間點來決定何時抓取。
- 足球和籃球使用不同的 API 端點獲取細節數據，但輸出格式統一為包含 Time, stats, at_time 的 JSON 結構。
- 籃球 API 數據結構與足球不同，需自行組合計算部分衍生數據（如命中率、總籃板），顯式定義了 BK 的 stats_mapping 及額外計算欄位。
- 文件採用範例數據展示 JSON 結構，作為開發時的規格參考。
