## 摘要


本文件為 newlotterytools 後台管理工具的功能規格，定義水桶名單與訊息中心（主題/文章）的維護頁面、API 串接方式、UI 互動流程與 E2E 測試腳本。透過 NewLotteryBackEndService 提供的 API 完成 CRUD，水桶新增時須搜尋玩家並帶入 account，訊息 icon 由固定選項選取且文章無 icon，刪除操作有軟刪除（主題停用）與硬刪除（文章）之分。這份設計文件直接提供可執行的前後端契約與測試案例，有助於 AI 快速生成符合規範的實作程式碼。

---

## 關鍵業務規則


- - 水桶新增時，userName 不由管理者輸入；必須以 account 或 userName 搜尋玩家，選取後帶入 account 與 userName（唯讀），管理者僅填 endTime 與 description。
- 搜尋玩家無結果時須顯示 Toast「找不到玩家」且禁止送出新增水桶。
- 主題 icon 欄位儲存 Material Symbols 名稱，管理者須從固定三選一（local_fire_department、timer、construction）選擇，禁止自由文字輸入。
- 訊息中心文章無 icon 欄位；前台展示的 icon 皆來自所屬主題。
- 主題刪除 = enabled=0（停用），文章刪除 = 硬刪除（呼叫 DELETE API）。
- 禁言後，前端 NewLotterySite 應針對被禁言使用者拒絕發文、留言、按讚、收回讚（HTTP 403, 'user is banned'），但此部分由 Site 實作，本 tools 僅維護水桶 CRUD。
- 日期格式統一為 'yyyy-MM-dd HH:mm:ss'。
- 側邊導覽列新增「水桶管理」於既有「會員」群組下，另新增「訊息管理」群組含「主題管理」與「文章管理」。

## 關鍵設計決策


- - 採用 Nuxt 3 + Vuetify，API 集中於 apis/index.ts，UI 模式參考既有 pages/user/list.vue 與 pages/transaction/rechargePlan.vue 的 CRUD 結構。
- E2E 測試採用 Playwright，locator 優先順序為 data-testid > id > role + name，並明確定義各頁面 test id 與 Toast/Dialog 文案對照表。
- 玩家搜尋調用 BackEnd GET /api/users/search?queryName= 代理 MemberService MeiliSearch，而不使用 GetAllUsers 全量載入，以確保精準匹配與「找不到玩家」的提示邏輯。
- 所有 API 只透過 NewLotteryBackEndService，不直接呼叫 MemberService，維持呼叫鏈一致性。
- TypeScript 型別命名不使用 DTO 後綴。
