## 摘要

這份文件定義了兩個籃球即時數據源的 API 端點與 JSON 結構：NBA官網提供英文的 play-by-play 數據，Naver 提供韓文的文字轉播數據。對 AI 開發而言，這份文件提供了事件(actionType/subType)的具體範例與欄位對照（例如比分、隊伍、時間格式），以及 Naver API 需要按節分頁請求再統整的技術限制。開發數據爬取或解析功能時，可以此文件作為欄位映射與事件分類的參考基礎。

## 關鍵設計決策

- - 選擇 NBA官網 的 API 端點：https://cdn.nba.com/static/json/liveData/playbyplay/playbyplay_{game_id}.json，以取得結構化的 play-by-play JSON 數據
- 選擇 Naver 的 API 端點：https://api-gw.sports.naver.com/schedule/games/{game_id}/relay?quarter={quarter}，需按各節分開請求後再統整為完整數據
- 事件結構採用統一的欄位格式，包含時間、比分、隊伍、事件類型(actionType)與子類型(subType)，以利跨數據源整合
- NBA官網範例顯示時間格式為倒數計時（12:00 開始倒數），Naver 範例顯示時間格式為順時記錄（00:00 開始），兩者時間方向不同，需注意轉換

## 注意事項

- ⚠️ - ⚠️ 文件僅提供部分事件類型的範例，完整的 actionType 與 subType 枚舉清單需人工確認
- ⚠️ Naver 的 API 需要針對每節(quarter)分別請求，需注意合併時的順序與去重處理
- ⚠️ 文件中的比分欄位 scoreHome/scoreAway 在特定事件（如失誤、一般犯規）中未提供，可能代表比分僅在得分事件後才更新，實際數據需以 API 回應為準
