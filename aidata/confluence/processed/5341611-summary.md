## 摘要

定義了 CrawlerAgent（Python）的日誌收集途徑：Python 封裝 Logger Function，以異步 HTTP 請求將結構化日誌（LogData JSON）發送至 Nginx（192.168.1.232/kafkalog/log.json），Nginx 經 Lua 轉發至 Kafka，最終由 applogxservice 寫入 Cassandra applogs 表。文件中提供了完整的 LogData 資料模型（C# 版本），包含 guid、appName、machineName、eventDate、eventTime、unixTime、logLevel、state、exception 等欄位，以及範例初始化邏輯，方便 AI 開發時理解並實作一致的日誌格式與傳輸流程。

---

## 關鍵業務規則

- - 日誌必須通過 HTTP 異步請求發送至 http://192.168.1.232/kafkalog/log.json
- 日誌 JSON 結構須符合 LogData 模型，包含必填欄位：guid（取 GUID 前10位）、appName（根據應用程式名決定）、machineName、eventDate（yyyy-MM-dd）、eventTime（yyyy-MM-dd HH:mm:ss.fff）、unixTime（毫秒）、logLevel、state（空時給空字串）、exception（空時給空字串）
- Nginx 使用 Lua 將接收到的日誌轉發到 Kafka
- applogxservice 負責將 Kafka 中的日誌寫入 Cassandra 的 applogs 表

---

## 關鍵設計決策

- - 採用 Nginx + Lua 作為日誌入口，統一收斂與轉發至 Kafka，避免 Python 直接寫 Kafka，降低耦合與複雜度
- 採用異步 HTTP 請求（async httprequest）發送日誌，避免阻塞主業務流程
- 日誌配置（Logger Server URL）放在 appsettings 中，提高可配置性與環境適應性
- 日誌模型以 C# 類別定義並給出 Python 可複刻的欄位與初始化範例，確保跨語言一致性
