## 摘要

文件詳述了針對 ESPN 和 Covers 網站設計的爬蟲流程，用於抓取 MLB 比賽的先發投手、預測及戰前分析。對 AI 開發的幫助在於：了解定時爬取（約每 20 分鐘）的觸發機制、HTML 解析策略（如直接從 JS 擷取 JSON、用 BeautifulSoup 切片區塊）、異常狀況判斷（如未產出內容時跳過、投手未確定時跳過），以及最終資料的儲存位置與欄位對應。

## 關鍵設計決策

- - 定時爬取頻率設為約 20 分鐘一次，平衡資料即時性與系統負載。
- Covers 戰前分析頁面：若 HTML 含「Check back shortly for a full preview.」則跳過該次爬取，避免儲存未完成的預覽內容。
- Covers 先發投手：只擷取 <section id='matchupHub-last5-section'> 區塊，減少不必要的 HTML 解析開銷，並用 BeautifulSoup 處理表格。
- Covers 投手資料：若顯示「starter TBD」表示先發投手尚未公布，則略過該場次。
- ESPN 頁面：不透過額外 API，而是從 HTML 內的 JavaScript 變數 window['__espnfitt__'] 提取 JSON，直接取得預測與球員資料。
- ESPN JSON 路徑設計：預測資料位於 ['page']['content']['gamepackage']['mtchpPrdctr']['teams']，先發投手位於 ['page']['content']['gamepackage']['prbblPtchrs']['stttcs']。
- Covers 戰前分析完成後，將 game id 加入已完成列表，避免重複抓取（因分析內容不會更新）。
