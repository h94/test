## 摘要

本文件定義如何透過轟天雷（MegaTime）的 HTTP API 取得特定券商分點的歷史進出資料。內容包含完整的 API URL 模板、參數說明（股票代號、券商代號、分行代號、日期區間）與必要的 Request Headers 設定。回傳格式為一個 JavaScript 函式包裝的 JSON 物件，內含該分點每日的買賣張數、成交均價等資料。此外，文件記錄了轟天雷與證券交易所的券商分行名稱對應問題（Name Mapping），指出了部分分行代號在兩個系統中名稱不一致的情況，這對後續資料解析與正規化至關重要。

## 關鍵設計決策

- - API 端點：採用 GET 請求 http://broker.megatime.com.tw/BrokerData.aspx，透過 Query String 參數指定查詢條件。
- 參數設計：以 `SD` 和 `ED` 指定查詢的起迄日期（格式 YYYYMMDD），並支援預設以 `{year}0101` 和 `{year}1231` 查詢整年資料。`BrokerID` 和 `SubBrokerID` 可設為相同值以查詢總公司。
- 請求偽裝：必須設定特定的 `User-Agent`（模擬 IE 瀏覽器）和 `Referer` Header 才能正常存取 API，否則可能被阻擋。
- 資料格式：API 回傳的內容為 HTML 頁面內嵌的 JavaScript 程式碼，須透過解析 `GetData()` 函數回傳的物件來提取 `RowData` 陣列中的結構化資料。
- 名稱映射：文件中記錄了多筆轟天雷與證券交易所名稱不同的案例（例如 9A9W 轟天雷-永豐南台 vs 證券交易所-永豐金-市政），暗示需建立靜態映射表或特定解析邏輯來處理名稱不一致的問題。
