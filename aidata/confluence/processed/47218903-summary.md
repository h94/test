## 摘要

这份文件详细说明如何解析 SofaScore 赛事 JSON 数据，包含联盟、队伍、比赛状态、比分、即时事件及球员统计资料的完整字段路径与格式转换规则。提供丰富的游戏状态代码对照表与不同球种（篮球、足球、板球等）局数、比分结构的差异处理逻辑。对 AI 开发来说，此文件是实作 SofaScore Parser 的直接参照依据，能快速理解原始数据如何映射至系统内部使用的字段名称与资料格式。

---

## 關鍵業務規則

- - 联盟名称 league 的组成规则：用连字符组合「国家-联盟名称」，若联盟名称已包含国家则避免重复。例如 'USA-NBA'。
- 比赛时间 game_date/game_time 的来源为 data['startTimestamp']，需自行转换 Unix timestamp。注意 SofaScore API 提供的 timestamp 单位是「秒」，而系统内部使用的是「毫秒」，转换时需乘以 1000。
- game_id 从 API 取出的类型为 int，必须强制转换为 string 类型再使用。
- 比分 score_home/score_away 应优先使用 data['homeScore']['current'] 与 data['awayScore']['current']，而不是 normaltime 字段。
- 针对板球 (CK) 比赛，其 scores 结构为嵌套阵列，表示不同局的分数（如 [[169, 0],[300, 259]]），需要特殊解析逻辑，不能直接用一般球种的 period 比分处理。
- playbyplay (即时事件) 主要资料来源为 html_data['incidents']['incidents'][1]，但有例外：若遇到中场休息 (HT)，该笔资料会是休息事件而非球员事件，Parser 需识别此种情况并以休息事件作结。
- 篮球 playbyplay 中的 event_time 应使用 reversedPeriodTimeSeconds 计算倒数时间，而非直接取用单一时间栏位。
- 新版本 API 中 data['status'] 已无 description 栏位，实作时必须自行依据文档中提供的 status_code 对照表（字典）产生相对应的 description 文字（如 0: 'Not started', 6: '1st half' 等），并透过正规表达式从 description 中提取局数数字。
- playbyplay 输出的局数英文标识需依球种决定，例如：篮球/冰球/板球用 'Q1', 'Q2'...，足球用 '1H', '2H'，网球/桌球/排球用 'set 1', 'set 2'，棒球用 'Top 1'/'Bottom 1'（但文件指出棒球尚无比赛无法确认上下半局判定方式）。
- 足球的统计数据（如角球、黄红牌）需要特别计算「上半场」的数据，不能只取全场总计；球员统计数据从 statistics 取，具体事件（含分数）从 incidents 取，且都需要分上下半场。
- 球员统计资料中 secondsPlayed 栏位需将秒数除以 60 转换为分钟，且不取余数（如 88 秒转换为 1 分钟）。

## 關鍵設計決策

- - gametype 不自行从原始 data['tournament']['category']['sport']['name']（如 'Basketball'）转换，原因是 SofaProvider 爬取时已经会转换，Parser 直接取用其转换后的值。
- 比分来源从原本的 normaltime 字段改为使用 current 字段，此设计是因应赛况进行中分数变化的需求，normaltime 可能不含即时的最新分数。
- 处理足球比分时，发现 period 比分（如上半场结束才会上半场分数）会有资料延迟的问题，因此决定额外使用 score_home 与 score_away 这两个即时的总分栏位来处理上下半场分数拆分的需求。
- 选择从原始码提取 game_status code 对照表，并将还在观察中、尚未确定的行为（不在官方 code 表上的）透过 Trace 纪录持续追踪，显示此部分代码对例外状况采取「持续监控并扩充字典」的防御性设计。

## 注意事項

- ⚠️ - ⚠️ 过时或已变更的规则： 文件中 gametype、score_home/score_away、playbyplay 的 period 取得方式均有删除线标记，表示基于早期 API 版本的解析方式已失效或变更，开发时务必使用最新描述的 current 字段与自行建立 status 字典的方式。
- ⚠️ 容易误判的点： 文件中球队数据图片显示的数据访问路径（如 data['homeTeam']['name']）与其上方的代码注释（队伍比赛data['homeTeam']['name']）可能让阅读者混淆「整个 JSON 的回传根节点结构」，实际上 data 指的是已经从 event[0] 取出的赛事物件，而非 API 最外层。
- ⚠️ 待确认的项目： 棒球的局数区分（Top/Bottom）因缺乏即时比赛数据，无法验证判断方式，文件中标记为「没办法判断如何分 B/T」，此逻辑可能尚未实作或存在瑕疵，需人工确认。
- ⚠️ 与现有系统行为不一致之处： 手写的 status_description 字典键值 97 对应的是 'HomeDefaulted'，但在同一个字典内的 later 版本注释中，98 被记载为 'AwayDefaulted'，而同文件的前一套字典中 97 和 98 分别对应 'HomeDefaulted' 和 'Defaulted'，存在字典版本不一致的问题，需确认哪一份为最终实作版本。
- ⚠️ 外部工具依赖： 提及建议在浏览器中使用 jsonviewer.stack.hu 观察 JSON 结构，此为开发辅助说明，非程式逻辑，但在分析时容易被误认为是实作规则。
