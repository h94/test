## 摘要

本文件提供 Sprint 期間的流程指引與檢查清單，涵蓋需求分析、JIRA Sprint 建立、程式碼審查、測試、發布及回顧等階段。重點在於確保 Sprint 各項活動依序進行，例如 Story 分析、Code Review、Gateway 配置檢查和 Swagger 文件更新。對 AI 開發的幫助：了解團隊開發流程，可協助自動化提醒或檢查步驟是否完成，例如確認 Git 分支建立、Sonarqube 掃描、Release 時檢查 Gateway 和 Swagger 等。

---

## 關鍵業務規則

- - Sprint 開始前（Day(-3)），SM 需與需求方確認 Story、安排開發測試分析、請需求方講解需求、和需求方及成員討論時程、公告時程
- Day(-2) 需建立 JIRA Sprint / Story / SubTask、建立 Confluence 需求分析 Page、建立 Git 分支、執行 Sonarqube 取得警告數和 UT 覆蓋率
- Story 項目較大時（StoryPoint=13）需召開 Design Review
- Kickoff Meeting（Day(0)）需進行 StoryPoint 估算、安排 Release / Launch 負責人、安排 Code Review 人員
- Code Review 階段（Day(4)）需檢查 Code Review 內容都有被修改或紀錄
- Release 階段（Day(9)）如有新增 Service / API 接口，需檢查 Gateway 是否配置，並修改對應的 swagger.json
- Launch 後（Day(10)）需安排人員 Merge 主線、監控上線系統狀況，並請成員填寫回顧會議內容
- Sprint Close（Day(12)）需結束 JIRA Sprint 並回報 PRD 監控結果
