## 摘要

本文件定義了兩個 REST API 端點：一為提供機器人賽事預測提交（POST mechanic/predict/bets/{gameType}/{account}），另一為查詢指定球種、聯盟與日期的賽事賠率（GET games/odds/{gtype}/{lid}/{date}）。賠率查詢結果包含主客隊資訊、多語系名稱、以及讓分（HA）與大小（OU）的詳細賠率與讓分數組合。此外，文件說明了各球種的賠率資料來源站台（如 BK→au8, SC→188bet 等），作為後端取值配置的依據。對 AI 開發者而言，這份文件可直接作為相關 API 的呼叫規格、資料模型設計與外部系統整合的實作參考。

---

## 關鍵業務規則

- - 機器人預測請求為陣列，單筆預測需包含 GDate（比賽日期）、GID（賽事編號）、LID（聯盟編號）、Mode（玩法，如 '1X2' 或 'OU'）、Spread（讓分數，當 Mode='1X2' 時值為 '1X2'，Mode='OU' 時為具體讓分字串）、OddType（'H'/'A' 或 'O'/'U'）、Odd（賠率數字，可為整數或小數）、Point（點數/金額）。
- 賠率查詢回應的 odds 物件包含 HA 和 OU 兩大區塊，HA 為讓分盤，其 key 為讓分數（如 '1-15'、'1+55'、'1X2'），OU 為大小盤，其 key 為總分線（如 '235'、'8+75'）。每組盤口下再以 'A'/'H' 或 'O'/'U' 表示主客或大小賠率，值為字串型態的數字。
- 賽事可能沒有賠率（HA 或 OU 為空物件），需設計容錯處理。
- 隊伍名稱支援多語系，透過 teamA_Map 和 teamH_Map 提供，語言代碼包含 de-DE, en-US, es-ES, fr-FR, ja-JP, ko-KR, pt-PT, th-TH, vi-VN, zh-CN, zh-TW。
- 各球種的賠率資料來源需根據以下對應向外部系統索取：BK → au8, SC → 188bet, BS → au8, HL → au8, FL → au8, ES → au8, 其他 → zba。

## 注意事項

- ⚠️ - ⚠️ 請求參數中 Mode='1X2' 時 Spread 仍須設定為 '1X2'，與一般讓分玩法用法不同，需人工確認此設計是否正確。
- ⚠️ OddType 的取值（'H','A','O','U'）在主客場的對應關係（H=主場, A=客場？）需從其他文件或業務訪談確認。
- ⚠️ 範例中看到部分賽事的 odds 為空物件，代表可能尚未開盤或賠率尚未產生，調用方需有預設行為（例如跳過該場賽事）。
