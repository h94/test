## 摘要

本文定義了在 MemberService 中新增「最多追蹤賽事會員」功能的設計，包含定時任務每小時生成資料存入 Redis、提供兩個 API（生成與查詢），以及修改賽事會員註冊、登入及第三方登入的流程。同時將發送註冊信與忘記密碼信機制轉移到 PriceCenterSite 服務，達成郵件發送的中介層統一。對於 AI 開發，本文說明了 Redis 資料結構、排序與篩選規則，以及 API 的責任邊界變更。

---

## 關鍵業務規則

- - 最多追蹤賽事會員的資料範圍為當日與明日兩天未開賽預測，依據追蹤人數與會員等級排序，取前20筆。
- 賽事會員註冊時，發送註冊信的機制已從 MemberService 移轉至 PriceCenterSite Service。
- 賽事會員忘記密碼請求機制同樣移轉至 PriceCenterSite Service 處理。

---

## 關鍵設計決策

- - 使用 xxl-job 每小時定時調用生成 API，將結果寫入 Redis，兼顧資料新鮮度與系統負載。
- 資料存放於 Redis 而不使用資料庫，以提高前端查詢效能。
- 生成 API（/system/...）與查詢 API 分離，前者僅供內部 job 調用，後者供外部站台使用。
- 將郵件發送邏輯從 MemberService 抽離至 PriceCenterSite，統一處理註冊信與忘記密碼信，並與機器人機制保持一致。
