## 摘要

本文定義了 Scrum Sprint 的標準作業流程，包含 Sprint 排程表、每日檢查清單及從需求分析到 Sprint 關閉的 14 個步驟。對 AI 開發者的幫助在於了解團隊的專案管理慣例，例如 Git 分支建立、Code Review、Swagger 文件更新等發布前檢查事項，但文件中沒有具體的業務邏輯或 API 規格。

---

## 關鍵業務規則

- - Sprint 開始前需與需求方確認 Story、安排分析並估算時程（Estimate Schedule）。
- Sprint 開始前需建立 JIRA Sprint/Story/SubTask、Confluence 需求分析頁面、Git 分支，並執行 Sonarqube 取得警告數和 UT 覆蓋率。
- 需求分析階段，若 StoryPoint = 13 需召開 Design Review。
- Kickoff Meeting 需進行 StoryPoint 估算，並安排 Release/Launch 負責人及 Code Review 人員。
- Code Review 時需檢查所有 Code Review 內容都有被修改或記錄。
- Release 時如有新增 Service/API 接口，需檢查 Gateway 配置並修改對應的 swagger.json。
- Launch 時需安排人員 Merge 主線、監控上線系統狀況，並請成員填寫回顧會議內容。
- Sprint 結束時需關閉 JIRA Sprint 並回報 PRD 監控結果。
