## 摘要

本文件定義在 PriceBackendService 新增 Z幣排行榜功能，透過既有的會員錢包交易紀錄 API 取得全體用戶正收入交易（排除測試帳號與小編），根據 Type 與 TypeInfo 將交易合併為 predict（競猜）、community（社群）與 membership（身份）三大類，並按月（前30天不含今天）、週（前7天不含今天）、日（昨天）分別計算排名，最終生成 JSON 檔案存放於 downloads/leaderboard/sportsite/zcoin，供前端顯示排行榜。這份設計說明了分類規則、時間範圍定義與輸出格式，有助於後續開發與測試。

---

## 關鍵業務規則

- - 只統計正收入（正收益）的交易紀錄，負值不列入排名。
- 必須排除測試帳號與小編的交易紀錄。
- 月排名計算過去30天（不含今天）的累積正收入；週排名計算過去7天（不含今天）；日排名計算昨天的累積正收入。
- 交易類型分類規則：Type 1 下的 predict profit、profit correction（正收入才計入）、betpool profit、包含 'sell' 字串的 TypeInfo、包含 'reset' 字串且為正收入的 TypeInfo，合併歸類為「predict」（競猜賽事）。其中 profit correction 歸入 predict profit，reset 正收入歸入 sell 賽事交易所獲利。
- Type 2 下的 article bonus、comment bonus、click like bonus 合併為「community」（社群獎勵）。
- Type 2 下的 killer bonus、supreme winner bonus、share bonus 合併為「membership」（身份獎勵）。
- 排行榜結果以 JSON 檔案輸出，檔名格式為 last{period}_{category}.json，例如月預測排行榜為 last30_predict.json，存放於 downloads/leaderboard/sportsite/zcoin 目錄。
- JSON 檔案中每個用戶包含 Account、UserName、Rank、Total 及各分類獎勵金額欄位。

---

## 關鍵設計決策

- - 採用靜態 JSON 檔案預先計算排行榜，而非即時 API 查詢，推測是為了降低查詢延遲並提供固定檔案供前端或外部系統使用。
- 直接複用既有「取得會員錢包交易紀錄」API 作為資料來源，避免重複實作資料擷取邏輯。
- 將多個相關的 TypeInfo 合併到三大類群組（predict / community / membership），簡化前端顯示並符合業務歸類（例如 profit correction 歸於 predict profit，reset 正收入歸於賽事交易所獲利）。
