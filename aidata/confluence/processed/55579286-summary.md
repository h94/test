## 摘要

本文件定義從 betsapi 爬取 pregame 比賽資料時，三種玩法（獲勝者、讓分、大小）的 API 回應欄位與內部資料結構的對應方式。內容包含 team_to_win 對應 1X2、Match Handicap(1.5) 對應讓分盤、Total_maps(2.5) 對應大小盤，並指定使用的 api key 與輸出至 match_lines 的備註。

---

## 關鍵業務規則

- - betsapi 的 team_to_win 欄位（1:home, 2:away）對應內部獲勝者玩法，主客賠率分別對應 HA 中的 H 和 A
- Match Handicap(1.5) 中的 1:home, 2:away 對應讓分盤，讓分數值需從 api key 名稱中解析（例如 1.5 表示主隊讓 1.5 分）
- Total_maps(2.5) 的 O 和 U 分別對應大小盤的 Over 和 Under，盤口數值從 api key 名稱中解析（例如 2.5）
- 三種玩法的數據最終皆輸出至 match_lines 結構

---

## 關鍵設計決策

- - 採用 betsapi 的 match_lines 作為標準輸出格式，維持爬蟲產出的一致性
- 利用 api key 名稱（如 team_to_win, Match Handicap(1.5), Total_maps(2.5)）直接辨識玩法與盤口數值，避免額外查表
- pregame 階段僅處理上述三種核心玩法，簡化初期開發範圍
