這是一份 Sprint 155 的流程管理文件，定義了從衝刺規劃、需求分析、開發、測試、發布到回顧會議的完整檢查清單與操作步驟。內容主要用於指導團隊按標準流程執行，對特定服務的業務邏輯或技術實作無直接參考價值。

## 關鍵業務規則

- - Sprint 開始前 3 天需完成：SM 與需求方確認 Story、安排分析、請需求方講解需求、討論並公告時程。
- Day(-2) 需建立 JIRA Sprint / Story / SubTask、Confluence 需求分析頁面、Git 分支，並執行 Sonarqube 取得警告數和 UT 覆蓋率。
- 需求分析時，若 StoryPoint = 13 則需召開 Design Review。
- Kickoff Meeting 需由開發測試人員講解需求、估算 StoryPoint、安排 Release/Launch 負責人及 Code Review 人員。
- Release 時，如有新增 Service / API 接口，必須檢查 Gateway 配置，並修改對應的 swagger.json（步驟參考建立/修改 Swagger API 文件頁面）。
- Launch 前需安排人員 Merge 主線、監控上線系統狀況，並請成員填寫回顧會議內容。
- 每日 Checklist：Daily Meeting 了解成員問題並影響時程時盡快回報上級；確認成員填寫 JIRA Work Log；測試階段注意 Bug 收斂；測試後期補齊分析文件；下班前確認 JIRA 問題與回覆；長期關注的線上問題需在 JIRA 開 Task 監督。
