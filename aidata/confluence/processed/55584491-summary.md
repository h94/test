## 摘要

本文件規範球王會員 Z 幣錢包系統的 API 與資料模型。提供 5 支 API：批次/單一新增交易紀錄、查詢會員餘額、查詢交易紀錄（支援日期範圍，預設當日，且限制 90 天內資料）。DB 使用 MySQL（GameUsers_Wallet 與 gameusers_wallet_Transactions 兩表），快取用 Redis，新增交易時一併更新錢包餘額。TypeInfo 欄位以序列化 JSON 字串儲存，依交易 Type（1 預測、2 獎勵、3 商品）對應不同結構，並定義各子欄位語意。此文件提供 API 規格與資料結構，幫助 AI 了解如何與 Z 幣錢包互動並正確建構請求/解析回應。

## 關鍵設計決策

- - 持久層使用 MySQL，快取使用 Redis。
- 新增交易紀錄時，同時更新 GameUsers_Wallet 中的 Balance 與 LastUpdateTime。
- 交易紀錄查詢僅提供 90 天內資料；API #4 若未指定日期區間，預設查詢當天。
- TypeInfo 以序列化 JSON 字串儲存，不同 Type 對應不同 JSON 結構：Type=1 預測相關（GameType, LID, GDate 等），Type=2 獎勵相關（BType, BMessage），Type=3 商品相關（PType, PMessage）。
- API 設計同時支援批次（#1）與單一會員（#2）新增交易，以及全域（#4）與單一會員（#5）交易紀錄查詢。
