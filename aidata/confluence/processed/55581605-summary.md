## 摘要

本文定義了從 ladbrokes 取得賽前資料的爬蟲實作設計：先以球種 ID 請求聯盟清單，再依聯盟 ID 與時間、玩法等過濾條件取得比賽簡易資訊，最後針對單場比賽請求完整詳細資料並發布至 Kafka。對 AI 開發而言，可清楚掌握 ladbrokes provider 的請求串接方式、參數規則及最終資料輸出格式。

---

## 關鍵業務規則

- - 僅抓取賽前（pre-match）資料，不包含滾球
- 需先取得特定球種的所有聯盟 ID，才能進行後續比賽查詢
- 比賽清單 API 必須傳入多個聯盟 ID（以逗號分隔），並限制 startTime 範圍、isStarted=false、且 market.templateMarketName 需包含該球種指定的玩法名稱
- 單場詳細資料 API 取得後以原始 JSON 格式送至 Kafka，不需再進行轉換

---

## 關鍵設計決策

- - 選用 OpenBet Drilldown API 2.31 版本作為資料來源，統一透過 simpleFilter 進行過濾
- 分三層請求：Class（聯盟） → EventToOutcomeForClass（比賽清單） → EventToOutcomeForEvent（單場詳情），以降低單次請求資料量並對應不同用途
- 多個聯盟 ID 於比賽清單請求中直接用逗號拼接，減少 HTTP 請求數
- 使用 Kafka 發布單場完整資料，實現爬蟲與下游資料處理服務的解耦
