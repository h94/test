本文件為 Sprint 118 的管理手冊，定義了從需求分析到上線回顧的標準化 Sprint 週期流程（共 14 個環節，為期約 12 天）。包含每日檢查清單（如確認工時填寫、Bug 收斂）以及每個環節的具體操作步驟（如建立 JIRA Sprint、安排 Code Review、Release 時檢查 Gateway 與 Swagger 等）。對於 AI 開發者而言，可以了解團隊在版本交付、測試發佈與文件更新上的標準作業程序。

## 關鍵業務規則

- - StoryPoint=13 的較大需求，必須在需求分析階段召開 Design Review。
- Release 階段若新增 Service 或 API 接口，必須檢查 Gateway 是否有對應配置。
- 新增 Service 或 API 接口時，必須修改對應的 swagger.json 文件（修改步驟參見另一頁面）。
- Launch 階段需安排人員 Merge 主線，並監控上線系統狀況。
- Sprint 結束時需結束 JIRA Sprint，並回報 PRD 監控結果。
