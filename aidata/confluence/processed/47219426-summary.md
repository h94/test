## 摘要

本文件定義了 Sprint 從估算、分析、開發、測試、發布到回顧的標準流程及每日檢查項目，包含 JIRA Sprint 建立、Sonarqube 檢查、Code Review、Swagger 更新等具體步驟。對 AI 開發有助於自動化 Sprint 流程的監控與提醒，確保每個階段的工作能被正確執行。

---

## 關鍵業務規則

- - Sprint 開始前需與需求方確認 Story、安排分析、討論時程，並公告時程。
- 建立 JIRA Sprint / Story / SubTask 以及 Confluence 需求分析頁面；建立 Git 分支，執行 Sonarqube 取得警告數和 UT 覆蓋率。
- StoryPoint 為 13 時必須召開 Design Review。
- Kickoff Meeting 中需估算 StoryPoint，安排 Release / Launch 負責人及 Code Review 人員。
- Code Review 後須確認相關內容已被修改或記錄。
- 在 Release 時，若有新增 Service / API 接口，需檢查 Gateway 配置並修改對應的 swagger.json。
- 每日需確認成員填寫 JIRA Work Log，測試階段注意 Bug 收斂情況。
- Sprint 結束時需關閉 JIRA Sprint，監控上線系統並回報 PRD 監控結果。
