## 摘要

此文件定義了 PredictService 中用於解鎖賽事預測的兩個 RESTful API 端點：GET 用於查詢特定球種、聯盟和日期範圍內鎖定的賽事預測；PUT 用於更新會員的解鎖記錄。並說明了依遊戲類型與年份分區的資料表 predictgames_{gameType}_lock_yyyy 的 schema，包括分區鍵、聚簇鍵及 map 欄位的設計。對 AI 開發預測服務時，可參考 API 規範與資料存取層實作。

---

## 關鍵業務規則

- - 查詢鎖定賽事預測時，必須提供 gameType（球種）、lid（聯盟）、startDate、endDate 和 account 參數
- 更新解鎖記錄時，需傳入完整的 PredictUnlockGame 物件，包括 lid、gdate、account、gid 及解鎖帳號

---

## 關鍵設計決策

- - 採用分年表設計（predictgames_{gameType}_lock_yyyy），以聯盟ID (lid) 作為分區鍵，並用賽事日期、帳號、賽事ID作為聚簇鍵，提升查詢效能並便於管理歷史數據
- 解鎖會員資訊使用 map<text, text> 類型儲存，每個鍵值對代表一個會員帳號與其解鎖日期，支援多個會員對同一賽事的解鎖記錄
- API 路徑使用路徑參數傳遞 gameType 和 lid，日期範圍與帳號透過查詢字串傳遞，符合 REST 風格
