## 摘要

本文件描述了在 MemberService 中新增廣告來源欄位 (adsource) 來區分會員來源，並提供一個刪除閒置會員的 API (DELETE /memberservice/api/game/users/idle)。閒置會員定義為：一個月未驗證（具體驗證方式未明確）、且六個月內無活動（lastactiontime 超過六個月），同時排除有成功交易紀錄、版主及 admin 帳號。這些規則將用於自動化清理資料，但需注意驗證條件與權限控制尚未詳細定義。

---

## 關鍵業務規則

- - 遊戲會員 table (gameusers) 新增 adsource text 欄位，記錄會員經由哪個廣告加入。
- GameUserLoginForSite 與 RegisterGameUser 流程需檢查 adsource 欄位（檢查規則待確認）。
- 刪除閒置會員條件：一個月未驗證（需確認驗證類型）、六個月內無預測（lastactiontime 超過六個月），且有成功交易紀錄者不刪、版主不刪、admin 不刪。
- 刪除操作透過 DELETE /memberservice/api/game/users/idle 批量執行。

---

## 關鍵設計決策

- - 選擇直接在 gameusers table 增加 adsource 欄位，而非另建關聯表，簡化查詢與讀取。
- GameUser 與 GameUserThirdPartyLogin model 均加入 AdSource 屬性，以支援第三方登入與一般註冊場景的廣告來源追蹤。
- 刪除閒置會員的 API 設計為批量操作，由排程定時觸發，避免人工介入。
- 排除有成功交易、版主、admin 的會員，確保重要帳號不會被誤刪。

## 注意事項

- ⚠️ - ⚠️ 「一個月未驗證」的驗證方式未定義，可能是 email 驗證或手機驗證，需人工確認。
- ⚠️ 「六個月內無預測 (lastactiontime 超過六個月)」中的 lastactiontime 是否等同於最後活動時間？若為預測服務相關，可能需與 predictservice 對齊定義。
- ⚠️ 刪除閒置會員 API 未說明權限控制，批量刪除可能需管理員權限，但文件中未提到。
- ⚠️ GameUserLoginForSite 與 RegisterGameUser 中 adsource 的檢查規則（如必填、格式）未定義。
