## 摘要

此為 PaymentService 的早期功能規劃與設計決策記錄，定義了儲值與消費 API 的輸入參數、查詢紀錄的分表策略，以及 log 存放位置。文章來源為審核過的 ForumService 專家文章，價格欄位設定在 MySQL，會員錢包於註冊驗證後建立。當時決定暫時不考慮支付方式，僅使用 authkey 與 point。部分設計如支付方式查詢被標注「目前用不到」，儲值與消費紀錄依日期分表用於報表。

---

## 關鍵業務規則

- - 儲值 API 需要參數 authkey 與 point，暫時不考慮支付方式
- 點數消費 API 需要參數 authkey、購買的文章、需花費的 point
- 查詢儲值紀錄 API 分為個人查詢、全部查詢，另有支付方式查詢但目前未實作
- 查詢消費紀錄 API 僅分為個人查詢與全部查詢
- 儲值紀錄 DB 與消費紀錄 DB 依日期分表，供報表查詢使用
- 系統 log 存放於 logs 資料庫
- 付費文章來源為經審核的 ForumService 專家文章，文章價格在 MySQL 新增欄位設定
- 付費文章的處理流程：專家於專用 Forum 發文，再由後台工具審核
- 會員錢包：會員註冊驗證完成後，系統自動新增錢包資料（新增錢包表）

---

## 關鍵設計決策

- - 儲值 API 暫不處理支付方式，僅用 authkey 與 point，以簡化初期開發
- 儲值與消費紀錄採用依日期分表設計，目的為支援報表查詢
- 支付方式查詢 API 雖規劃但標注「目前用不到」，留待日後擴充
- 系統 log 統一寫入 logs 資料庫，集中管理
- 文章價格欄位直接於 MySQL 加欄位，不另建價格服務
- 付費文章審核流程：專家於專用 Forum 發文 → 後台工具審核，確保內容品質
- 會員錢包在註冊驗證後自動建立，綁定會員生命週期
