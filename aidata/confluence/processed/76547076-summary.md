## 摘要

本文件定義了 BetCity 網站的爬蟲資料映射規則。包含比賽基本資訊（聯盟、球種、比賽 ID、時間、隊伍）如何從原始 JSON 提取並轉換為內部欄位名稱（如 name_ch、id_ch、date_ev）。詳細列出了不同球種（SC、TN、BK 等）下的盤口 ID 與賠率類型、顯示名稱、處理邏輯的對應關係，例如使用 define: 1X2 定義全場勝負、show 控制顯示章節、replace 做比分格式標準化。對 AI 開發者而言，這是實現 CrawlerAgentBetCity 資料標準化邏輯的核心配置說明。

---

## 關鍵業務規則

- - 比賽時間需使用 date_ev 欄位，該時間戳為台北時區；str 欄位是其他時區，不可用於顯示
- 聯盟名稱（league）對應原始欄位 name_ch，聯盟 ID（league_id）對應 id_ch
- 球種（game_type）對應 name_sp，比賽 ID（game_id）對應 id_ev
- 全場勝負盤（如 ID 69）透過 define: 1X2 定義，並歸類為 HA 類型
- 讓分/大小盤使用定義：HA 對應讓分，OU 對應大小，並搭配 0/RB 前綴控制走地版本
- 部分比分盤（如 Correct Score）需要對原始值執行 .replace(':', '-') 將比分分隔符改為 '-' 以統一格式
- 使用 mapping 欄位進行特定映射（如 DC = Double Chance）
- 對於半場/節/局等分段盤口，透過 show 欄位（如 F1, Tot）控制顯示層級，並定義對應的原始盤口名稱（如 HalfHA、1st SetGameHA）

## 關鍵設計決策

- - 採用多層巢狀結構組織盤口配置：第一層按球種（SC, TN, BK...）分類，第二層按原始盤口 ID，第三層可再按子 ID（如 26_W）細分，以處理同一盤口下多種玩法
- 時區處理明確選擇 date_ev 時間戳而捨棄 str 字串，避免時區轉換錯誤
- 對動態內容（如隊伍名稱、地圖字串）使用 {team}、{map_string} 等佔位符，爬蟲運行時動態替換，保持配置靈活性
- 走地標記採用 0 為走地盤 (RBHA, RBOU)，無 0 為賽前盤，透過前綴區分
- 統一使用三種輸出類型：HA（讓分）、OU（大小）、SCORE（比分）、YN（是否）、Value（直接值），方便下游消費
