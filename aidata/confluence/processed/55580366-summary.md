## 摘要

本文件定義 PredictService 中設定預測篩選報表的 API（POST /predictservice/api/reports/predictfilterreports）與對應的 Cassandra DB 結構。請求接受多筆報表物件，包含報表日期、球種、聯盟、篩選類型（all/HA/main 及其連勝變體）、會員帳號、勝率、預測次數／勝次、獲利點數與勝負明細等。DB 設計以 reportdate 為 partition key，gametype、lid、filtertype、startdate、enddate、account 為 clustering 欄位，收錄 seq_score（Python 計算）與 seq_score_fix（後台設定）供排序使用。此為報表寫入功能的合約，對 AI 開發 PredictService 的資料接收與儲存提供明確欄位規範。

---

## 關鍵業務規則

- - filtertype 列舉值：all 為不分玩法主推；HA 為讓分；main 為主推；all_winstreak、HA_winstreak、main_winstreak 分別為對應類型的連勝篩選。
- seq_score 由 Python 計算得出，用於排序。
- seq_score_fix 由後台設定，可用來調整排序。
- winlose_detail 為 list<text>，儲存勝負明細，如 ['W','-','L','W','W']，僅供後台檢視。
- partition key 固定為 reportdate，clustering key 依序為 gametype、lid、filtertype、startdate、enddate、account。

---

## 關鍵設計決策

- - 所有日期（reportdate、startdate、enddate）均以 text 型別儲存，可能為簡化資料交換或匹配前端的字串格式。
- API 採用陣列一次寫入多筆報表，提升批次處理效率。
- 排序分數拆分為 seq_score 與 seq_score_fix，區隔系統計算值與人工調整值。
