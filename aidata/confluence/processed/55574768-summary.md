## 摘要

本文件定義了 PriceBackendService 須新增的廣告與賽事 API，包含廣告的新增、查詢、更新，以及賽事的查詢與比分狀態更新。這些 API 將支援後台廣告管理與賽事資料整合，並規定更新比分時同步更新 zba 系統。對 AI 開發而言，提供了精確的 API 規範與參數格式，可直接作為實作依據。

---

## 關鍵業務規則

- - 更新比賽比分和狀態時，必須同步更新 zba 系統中對應遊戲的比分和狀態。
- 廣告圖片上傳後透過絕對路徑 https://inplayz.com/{imgPath} 存取。
- 廣告分類（adClass）欄位僅允許 'self'（自家廣告）或 'sponsor'（贊助廣告）。
- 更新廣告時，若未變更圖片則請求中不須傳遞 imgPath 參數。
- 廣告區域（adArea）目前包含 'banner' 類型，可依需求擴充其他區域。
- 賽事查詢 API 支援依球種（gameType）及日期過濾，回傳該日所有合併後的賽事清單。

---

## 關鍵設計決策

- - 廣告圖片使用絕對路徑儲存，前端可直接透過 URL 顯示，減少圖片代理轉發成本。
- 賽事合併站台資訊以 JSON 字串儲存在 siteIDMaps 欄位，保留各站台原始識別碼與隊名對應。
- 更新比分狀態採用 PUT /pricebackendservice/api/pricecenter/games/{gameType}/score-status，需傳遞完整比賽識別欄位（ID, LID, GDate, match_A, match_H, status）。
- 廣告 API 的 Path 參數使用 {adArea} 動態對應不同廣告區域，保持路由彈性。

## 注意事項

- ⚠️ - ⚠️ 文件提到「目前只有 PRD 可以讀到圖片」，可能代表廣告圖片存取有權限控制，AI 服務若需讀取圖片須確認權限機制。
- 賽事回傳中的 siteIDMaps 是 JSON 字串而非結構化物件，解析時需額外進行反序列化。
- 更新比分 API 的 Request Body 範例中只包含單一物件，但未說明是否支援批次更新，需人工確認。
- 文件未提供廣告圖片上傳的實際實作方式（如上傳 endpoint），僅說明最終圖片路徑格式。
