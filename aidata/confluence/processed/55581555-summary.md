## 摘要

本文件定義 PaymentService 中運動站台活動商品功能的 API 設計，包含新增、更新、查詢活動商品以及兌換紀錄。使用 Cassandra 儲存商品資料（products_activity, products_activity_redeem_logs），查詢商品時支援 Redis 快取（預設從快取讀取，可指定 cache=false 直接讀取資料庫）。對 AI 開發 paymentservice 提供了明確的端點、參數結構與 DB schema，有助於實作活動商品模組。

## 關鍵設計決策

- - 採用 Redis 快取活動商品列表，預設 cache=true 從 Redis 讀取，可藉由 cache=false 強制讀取 Cassandra，以平衡讀取效能與資料一致性。
- 活動商品與兌換紀錄儲存於 Cassandra，以 site 為 partition key，activityevent 與 id 為 clustering key，支援按站台/活動快速查詢。
- API 遵循 RESTful 設計，資源路徑分別為 /activity/products 與 /activity/productredeemlogs，實現 CRUD 操作。
