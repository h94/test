## 摘要

這份文件定義了 PriceCenterService 的 NameMap 系列 API，提供針對聯盟(League)與隊伍(Team)在不同站台(Site)的名稱翻譯對照。核心價值在於提供一個結構化的資料字典，讓前端或其他服務可以根據 GameType、Date、LeagueId 等條件查詢合併或原始的翻譯名稱。對 AI 開發而言，這份文件釐清了名稱翻譯資料的來源、回傳格式與查詢端點，有助於理解資料串接邏輯。

---

## 關鍵業務規則

- - API 1 根據 gameType 和 date 取得當日合併翻譯資料，回傳 List<NameMapsDto>。
- API 2 根據 gameType 和 lid (聯盟ID) 取得合併翻譯資料，回傳單一 NameMapsDto。
- API 3 根據 gameType、site 和 date 取得當日原始翻譯資料，回傳 List<SiteNameMapsDto>。
- API 4 根據 gameType、site 和 sitelid 取得原始翻譯資料，回傳單一 SiteNameMapsDto。
- NameMap 資料分為「合併翻譯」與「原始翻譯」兩種類型，經由不同 API 端點區分存取。

---

## 關鍵設計決策

- - 使用 Name_Map 欄位（Dict<String,String>）而非固定結構，以彈性容納多語系或不同站台的名稱對應關係，避免為每個語系或站台建立新欄位。
- 將合併翻譯資料（跨站台統整）與原始翻譯資料（特定站台）分開設計成不同 DTO 和 API，明確區分資料來源與用途。
