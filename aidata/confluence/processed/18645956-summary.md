## 摘要

此文檔定義前端賠率比分頁面的功能需求，說明透過 API 取得初始賽事與賠率資料，並藉由 WebSocket 即時更新比分與賠率變動。根據球種（BK/SC/BS）和比賽狀態（PreGame/InProgress/Final），頁面需切割顯示不同賽況資訊，且賠率欄位 HA/OU 有特定的取值邏輯（Main 與 Spread 條件）。同時規範熱門比賽 Top9 的展示方式與資料模型。對 AI 開發服務可澄清資料介面與前端呈現規則。

---

## 關鍵業務規則

- - 進入頁面時，球種預設為 BK。
- 當使用者切換球種時，必須中斷當前 WebSocket 連線，並使用新球種重新建立連線。
- 賠率 HA 數值來源規則：比賽進行中（InProgress）時，從 Odds 陣列中選取 PlayMode 為 'RBHA'、Spread 不等於 '1X2'、Main 屬性為 true 的項目；若無，則顯示 '-'。賽前（PreGame）時，從 Odds 陣列中選取 PlayMode 為 'HA'、Spread 不等於 '1X2'、Main 為 true 的項目。
- 賠率 OU 數值來源規則：比賽進行中時，選取 PlayMode 為 'RBOU'、Spread 不等於 '1X2'、Main 為 true 的項目；賽前時，選取 PlayMode 為 'OU'、Spread 不等於 '1X2'、Main 為 true 的項目。若無，則顯示 '-'。
- 針對球種 BK，Status 欄位需顯示剩餘時間（Time）、事件（Event）、隊伍（Team），以及 Home Foles、Home 2 Pts、Home 3 Pts、Away Foles 等統計（詳細清單參照文件）。
- 足球 SC 的 Status 欄位包含 HYC（主隊黃牌）、HRC（主隊紅牌）、AYC（客隊黃牌）、ARC（客隊紅牌）、時間、事件等，且需區分 Team1 與 Team2 的數據。
- 棒球 BS 的 Status 欄位包含 Balls（好球）、Strikes（壞球）、Out（出局）、Time（上下半局）、Event（事件）、Bases（上壘人數）等。
- 比賽狀態為 Final 時，時間欄位直接顯示字串 'Final'，無賽況。
- 比分 Score1/Score2 在任何狀態下均直接使用 WebSocket 的 Score1/Score2。
- 熱門比賽透過 API /api/hotgame 獲取，固定返回 Top9 筆資料，資料結構包含 league, team1, team2, score, gameID。
- API /api/gamedata 需傳入 gameType 參數（string），返回 GameDataRes，內含 GameType 與 GameData 列表。GameData 包含 League、Time、Team1、Team2、Score1、Score2、Status、GameID、Site（內含 Odds）。Site 中的 Odds 包含 OddType 和 Spread。
