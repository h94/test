## 摘要

這篇文件提供了 StockSite 的完整 API 列表，涵蓋使用者認證（註冊、登入、第三方登入、密碼重置等）和股票相關功能（自選股、策略、卷商篩選、回測等）。API 定義了請求路由、方法、參數和回應模型，並透過 Rank 與 Token 實現權限控制。對 AI 開發來說，可據此實作後端 API 端點、理解會員等級如何影響功能開放，並注意模型已從使用者帳號遷移至 Token 的設計變更。

---

## 關鍵業務規則

- - 用戶註冊需提供 Account、Password、Email，註冊後須透過 validate 端點完成驗證，未驗證前無法正常使用。可重新發送驗證信（/auth/register/vaildate/resend）。
- 登入成功後回傳 Token 與 Rank 欄位，Rank 用於判斷會員權限，開放相應付費功能。
- 取得策略選單（/stock/options）與策略規則（/stock/rules）時，系統根據用戶等級回傳不同資料；TargetIndex 結構中新增 LeastRank 欄位，低於該等級的選項不會出現。
- 忘記密碼採用兩階段流程：先以帳號請求（POST /auth/user/forgetpwd/req/{account}），系統處理後，用戶以收到的 Token 呼叫 PUT /auth/user/forgetpwd/reset/{token} 設定新密碼。
- 自動回測可透過 /stock/backtesting/auto 設定開關（Status = 1 開 / 0 關），回測結果以 HashKey 與 addTime 作為查詢過濾條件。
- 多數 API 使用 Token 進行身份驗證（位於 URL path 或 query string），部分舊有以 Account 為識別的端點已在 Model 變更中轉換為 Token。

---

## 關鍵設計決策

- - 認證標識從使用者帳號（User/Account）改為 Token，提升安全性並支援無狀態分散式架構。
- API 設計遵循 REST 風格，使用 POST、GET、PUT、DELETE 對應 CRUD 操作，並將業務狀態碼封裝於 MsgCode Model 中。
- 為支援會員等級權限控制，於策略相關回應模型中新增 LeastRank 欄位，實現不同等級看到不同功能清單。
- 回測資料透過 addTime 與 hashKey 組合進行快取區分，允許使用者建立多次回測並管理歷史數據。
