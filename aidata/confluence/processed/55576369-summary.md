## 摘要

本文件定義球王站台交易交握紀錄機制，在 paymentservice 新增一個 DELETE API 用於清除運動站台交握記錄，並在 pricecentersite 的用戶註冊與第三方登入 API 中增加 ShowCode 參數。交握記錄透過過水層直接寫入 DB，保留 1 週並由 xxl-job 定時任務每天清除。資料表採用日期分區，以 account 和 addtime 作為群集鍵，區分站點端（shakehandlogs_site_sport）與服務端（shakehandlogs_service_sport）記錄。對 AI 開發 paymentservice 與 pricecentersite 時，理解需要實現的端點與儲存結構至關重要。

---

## 關鍵業務規則

- - 交握記錄保存期限為 1 週，超過時間由每天執行的 xxl-job 定時任務清除。
- paymentservice DELETE /api/system/sport/shakehandlogs 僅針對運動站台交握記錄，需傳入 deleteDate 參數指定刪除日期。
- pricecentersite 的 users/register 與 users/login/thirdparty 接口新增必填欄位 ShowCode，用於傳遞展示碼（具體業務用途需人工確認）。

---

## 關鍵設計決策

- - 採用過水層直接寫 DB 儲存交握記錄，避免多層調用延遲，確保交易歷程快速持久化。
- 記錄保存 1 週並由 xxl-job 定時清除，以控制資料成長並符合業務需求。
- 使用 Cassandra 分區表，分區鍵 date，群集欄位 account 與 addtime，支援按日期和會員的快速查詢與清除。
- 拆分成 shakehandlogs_site_sport（站點端）與 shakehandlogs_service_sport（服務端）兩張表，分離不同層面的記錄，方便維護與清理。
- 在現有 pricecentersite API 上新增 ShowCode 參數，而非建立新端點，減少契約變更的影響範圍。
- DELETE API 設計為對外暴露的路徑 /paymentservice/api/system/sport/shakehandlogs，表示此功能由 paymentservice 統一提供清理入口。
