## 摘要

定義在 CloseFinalGame API 中新增一個站台賽事（Sitegame）同步策略：以 game_{gameType} 的基底賽事為來源，當賽事 status=1 且結束超過 1 小時後，對於其他站台同場賽事中 status≠1 的記錄進行覆蓋。覆蓋時會寫入來源的 gtime、match_a、match_h，若目標記錄 swap=1 則對調主客場；覆蓋後將目標記錄 status 設為 1。若所有其他站台同場賽事 status 皆為 1，則略過不更新。對 AI 開發的幫助是釐清 pricecenterservice 在結算後如何確保各站點賽事資料一致性。

---

## 關鍵業務規則

- - 觸發條件：來源賽事（game_{gameType}）status 必須為 1，且結束時間已超過 1 小時。
- 檢查範圍：只針對其他站台（非來源站台）中與來源賽事同場（同一賽事 ID）的 sitegames_{gameType} 記錄。
- 更新判斷：若目標 sitegames_{gameType} 記錄的 status ≠ 1，則判定為需要覆蓋。
- 覆蓋欄位：將來源的 gtime、match_a、match_h 寫入目標記錄。
- swap 處理：當目標記錄的 swap 欄位為 1 時，需先將 match_a、match_h 對調後再寫入（即最終 match_a = 來源 match_h，match_h = 來源 match_a）。
- 狀態更新：覆蓋完成後，將目標記錄的 status 更新為 1。
- 略過條件：若所有其他站台同場賽事的 sitegames_{gameType} 記錄 status 均已為 1，則完全不進行任何更新（不覆蓋也不修改 status）。
- 更新操作應在 CloseFinalGame 軌道內執行，不改變原有 API 的其他結算邏輯。
