## 摘要

此文件定義 LiveChatService 中 Quick Message（罐頭訊息）與 HelloMessage 的管理規則。業務上，Quick Message 的增刪修必須根據請求中的 X-Company 限制該公司資料，且所有寫入操作需同時更新 Redis；查詢則直接從 Redis 讀取，以 GroupType 為必填參數並隱含 CompanyCode，不需要分頁。HelloMessage 每個 Company 僅有一筆，僅允許更新，新增需手動於 DB 操作。這些規則可作為自動化開發的明確邊界。

---

## 關鍵業務規則

- - QuickMessage 增刪修只能依據請求 Header 中的 X-Company 對該 Company 的 QuickMessage 進行管理
- QuickMessage 增刪修必須同時更新 Redis 中的對應資料
- QuickMessage 查詢的資料來源為 Redis，查詢時需傳入 GroupType（必填）來區分回傳資料，並隱含 CompanyCode（Header），不回傳分頁，直接全撈
- HelloMessage 僅支援 update 功能，因為一個 Company 只存在一筆資料
- HelloMessage 的 Insert 需要手動進 DB 新增，不提供 API

---

## 關鍵設計決策

- - QuickMessage 查詢採用 Redis 作為單一資料源，推測是為了即時回應效能；寫入時強制同步 Redis 與 DB，確保存取一致性
- HelloMessage 限制為一公司一筆並僅開放更新，簡化前端操作與後端邏輯，避免無謂的刪除或重複建立
