## 摘要

本文件記錄了針對 CPBL 官網和 CBSSport 網站的新聞與數據爬蟲技術設計。對 AI 開發有幫助的點在於：它詳細說明了如何透過逆向工程 API 與 HTML 解析來獲取結構化資料（如比賽、球員成績），並定義了標準化的 JSON 輸出格式與 DB 儲存規格。這份知識可以直接用於相關數據服務的故障排查、功能擴充或新爬蟲開發。

## 關鍵設計決策

- - CPBL 團隊成績需先請求靜態頁面以獲取動態的 __RequestVerificationToken，再以此 Token 請求 API，這是網站的反爬蟲機制。
- CBSProvider 負責從網站原始 HTML 解析出所有資訊（如投手姓名、id），並將初步解析結果推送到 Kafka，供 CrawlerAgentCBS 訂閱並進行二次處理。
- CPBL 的比賽資料透過兩個 API 獲取：先用固定 payload 獲取全年比賽清單，再根據篩選條件請求單場比賽的即時數據 API。
- 為避免請求過於頻繁，2025/10/01 的更新將原先由兩個執行緒各別獲取整季比賽清單並篩選的機制，改為由一個獨立執行緒專門獲取整季清單。
- CBSSport 的資料抓取設計為整合式爬蟲，透過統一的 CBSProvider 處理多個聯賽（MLB, NBA, WNBA, NFL, NHL），並使用聯賽代碼（如 BS, BK）進行路由。
- CPBL 官方網站的回應在 Docker 環境中為 Brotli 壓縮格式，需要使用 `brotlicffi.decompress` 進行解壓，這是因應部署環境的特定實作。
- 投手資訊的獲取被拆分為多個請求：CBSSport 中分為基本資料、本季成績(career-stats)、逐場成績(game-log)三個獨立 API；CPBL 則分為本季成績(getpitchscore)和逐場成績(getfollowscore)兩個 API。
