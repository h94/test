## 摘要

這份技術設計文件主要針對預測系統進行調整：新增預測時需檢查玩家當日是否有最新的球種聯盟 report，若有則無法預測（上鎖）；此規則套用於會員預測、機器人預測及更新預測注單鎖定狀態等既有 API，版主預測與解鎖 API 不受影響。另外新增冥燈排行榜 API，返回指定球種聯盟中表現最差的玩家列表，無資料時回傳空陣列。同時修改取得會員預測資訊 API 的 filter report 輸出規則，確保每個聯盟最多顯示一個 report，並優先選擇與玩家預測同玩法的 report。對 AI 開發的幫助在於明確預測業務中 report 檢查的時機、上鎖條件，以及新冥燈功能的 API 行為與回傳格式。

---

## 關鍵業務規則

- - 預測時（會員預測、機器人預測），若玩家當下擁有該球種聯盟的最新 report，則預測的 Enabled 應設為 0（上鎖），禁止預測。
- 版主預測與解鎖會員鎖定預測賽事兩支 API 不檢查玩家是否持有最新 report，維持原有行為。
- 更新會員預測注單鎖定狀態時，需再次檢查玩家當下是否有最新 report，若不滿足條件則不可將 Enabled 設為 1（解鎖）。
- 取得會員帳號和預測相關資訊時，filter report 的輸出規則為：每個聯盟最多只回傳一個 report；若玩家在該聯盟沒有任何預測，則不輸出 report；預設輸出玩家在此聯盟中最好或最爛的 report（定義需人工確認）；若有多個 report 符合條件，優先回傳與玩家當次預測相同玩法的 report。
- 高手頁球種聯盟冥燈排行榜（predict/leaderboard/master/{gameType}/{lid}/worst）若無符合條件的玩家資料，leaderboardDetails 必須回傳空陣列。

---

## 關鍵設計決策

- - 為阻止已持有最新 report 的玩家重複預測，在預測相關 API 中統一加入 report 檢查，而非僅靠前端限制，以確保資料一致性。
- 冥燈排行榜以球種聯盟為區分，並設定獨立路由，避免與其他排行榜混淆，且當無資料時明確回傳空陣列而非 null 或錯誤，簡化前端的邊界處理。
- filter report 規則調整為優先選擇與預測同玩法的 report，以提升個人預測頁的關聯性展示。

- ⚠️ 冥燈排行榜的排序依據與計算方式僅從文件中的範例回應可推測，但未詳細記載，實作前需與規格確認。
