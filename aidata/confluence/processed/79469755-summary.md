## 摘要

記錄在 MergeSite 功能中因 API 調用不正確及效能瓶頸進行的調整過程。核心內容包括：用更高效的 v1/games/{GameType}/{gid} API 取代直接調用 sitesinglegames，透過 GameDTO.SiteIDMaps 反序列化獲取關聯資料；合併賽事時需補齊 MainSiteGame 完整欄位，並在調用 merge/sitegames/{GameType} 時將 MainSiteGame 歸入 SiteGames 清單且附上 gDate；前端展示規則如聯盟名稱優先取 en-US，主客隊改用 Team_A/Team_H，以及 UI 樣式調整。對 AI 開發 mergesite 與 pricecenterservice 整合功能有參考價值，尤其注意 API 呼叫順序與必要資料結構。

---

## 關鍵業務規則

- - 合併賽事呼叫 merge/sitegames/{gameType} 時，SiteGames 清單必須包含 MainSiteGame 的完整資料，且每個物件需提供 gDate
- 查詢結果的「聯盟」欄位顯示優先使用 en-US 語言代碼對應值，若無則改用 zh-TW
- 遊戲的主隊與客隊顯示應使用 Game.Team_A 與 Game.Team_H 欄位
- 查詢結果區塊樣式：背景灰白、字體黑色，操作按鈕黑底白字，不同 game 之間有明顯區隔
- 查詢結果的 GID、開賽時間、聯盟名稱、主客隊等欄位內容一律靠上置中對齊

---

## 關鍵設計決策

- - GetOpenClawMerge 回傳增加 MainSiteGame 前，先透過 v1/games/{GameType}/{gid} 取得 GameDTO.SiteIDMaps，以 key=game.datum 反序列化取出第一筆的 Sitelid 與 SiteGid，再用 sitesinglegame/{GameType}/{site}/{sitelid}/{sitegid} 補齊完整 SiteGame 欄位，以解決直接調用 sitesinglegames 的效能問題
- 合併 API 要求 SiteGames 列表必須包含 MainSiteGame 自身，並補上 gDate，因此前端需在調用前將 MainSiteGame 加入 SiteGames 集合
- 前端查詢時需記錄 Game.MainSiteGame 以供後續操作按鈕使用，並改為調用 merge/sitegames/{gameType} 而非舊有的不正確 API

---

## 注意事項

- ⚠️ - ⚠️ 調用 v1/games/{GameType}/{gid} 時，回傳的 SiteIDMaps 中 value 需進行 JSON 反序列化為 SiteGame 清單，並僅取第一筆，需注意資料結構的穩定性
- ⚠️ 合併時要求 MainSiteGame 所有欄位完整，若後續 pricecenterservice 介面異動，可能影響補齊邏輯
