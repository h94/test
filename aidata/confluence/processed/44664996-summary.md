## 摘要


本文件定義了一個標準 Sprint 從前期準備到關閉的完整流程，包含各階段的日期排程、每日檢查清單與步驟細節。對 AI 開發的幫助在於可掌握團隊的工作節奏與交付程序，例如：需求確認與估算的時間點、JIRA 任務與分支的建立時機、Code Review 與 Release 前對 Gateway 和 Swagger 的檢查要求，以及上線後的主線合併與系統監控安排。這些規則可輔助自動化任務分配、進度追蹤與合規檢查。

## 關鍵業務規則


- - Day(-3) 需與需求方確認 Story，安排開發與測試分析，並請需求方講解需求後討論時程並公告
- 建立 JIRA Sprint 時需一併建立 Story/SubTask、Confluence 需求分析 Page、Git 分支，並執行 Sonarqube 獲得警告數與 UT 覆蓋率
- StoryPoint 為 13 的 Story 必須召開 Design Review
- Kickoff Meeting 中需完成 StoryPoint 估算、安排 Release/Launch 負責人及 Code Review 人員
- Code Review 階段須檢查所有 Code Review 內容均已被修改或記錄
- Release 前如有新增 Service/API 接口，必須檢查 Gateway 是否已配置，並修改對應的 swagger.json
- Launch 需安排人員進行主線合併、監控上線系統狀況，並要求成員填寫回顧會議內容
