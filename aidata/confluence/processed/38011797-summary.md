## 摘要

此文件定義一項業務規則：當任何 API 更新 league 或 team 資料（如改名、合併）時，必須將受影響且比賽日期從操作日前一天（含）開始的所有 game 記錄的 addtime 欄位更新，以觸發後續同步或緩存刷新。若刪除 league/team，則需一併刪除對應 game 及關聯的 sitegame 記錄。文件列出 17 個已實作此規則的 API。對 AI 開發的幫助是理解數據一致性維護的觸發時機與範圍。

---

## 關鍵業務規則

- - 任何更新 league_xx 或 team_xx 表的操作（例如改名、合併），必須找出比賽日期大於等於操作日前一天的所有相關 game 記錄，更新其 addtime 欄位。
- 更新 league 時，查詢條件：SELECT * FROM games_XX WHERE lid = {受影響league id} AND gdate >= {操作日期 - 1 天}。
- 更新 team 時，需分別查詢 teamid_a 和 teamid_h 等於該 team id 的 game，條件同上。
- 刪除 league/team 時，需刪除符合相同日期範圍（gdate >= today-1）的對應 game，並連帶刪除這些 game 相關聯的 sitegame 記錄。

## 注意事項

- ⚠️ - ⚠️ 文件中使用「前天開始」描述日期範圍，但實例中 7/21 更新時使用 gdate >= '2022-07-20'，實際為前一天，可能用詞有誤。規則實際定義為「從操作日前一天開始」。建議人工確認是否應為昨天（即操作日-1）或前天（-2）。
- ⚠️ 文件未說明 addtime 更新後的具體觸發機制（例如是否觸發快取失效、是否重新計算賠率），僅知此為必要步驟，需搭配其他文件理解。
