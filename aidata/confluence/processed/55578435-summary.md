## 摘要

本文件定義了為期十二天的 Sprint 執行流程與各階段的檢查清單，包含從排程、需求分析、開發、測試到發布的標準步驟。對 AI 開發的幫助在於可將這些流程規則整合至自動化工具中，例如自動提醒建立 JIRA Sprint、Code Review 時間點、Release 時檢查 Gateway 與 Swagger 更新等，確保團隊依循統一流程。

## 關鍵業務規則

- - Sprint 開始前三天 (Day-3) 需完成以下事項：SM 與需求方確認 Story、安排開發與測試分析、請需求方講解需求、討論時程、公告時程。
- Sprint 開始前兩天 (Day-2) 需建立 JIRA Sprint / Story / SubTask、建立 Confluence 需求分析頁面、建立 Git 分支、執行 Sonarqube 取得警告數與 UT 覆蓋率。
- StoryPoint 為 13 的 Story 必須召開 Design Review。
- Kickoff Meeting (Day 0) 中應由開發測試人員講解需求、進行 StoryPoint 估算、安排 Release/Launch 負責人及 Code Review 人員。
- Release 階段 (Day 9) 若有新增 Service 或 API 接口，須檢查 Gateway 配置，並修改對應的 swagger.json。
- Launch 當天 (Day 10) 需安排人員合併主線、監控上線系統狀況，並請成員填寫回顧會議內容。
