## 摘要

這份文件定義了一套前端 JavaScript 套件 (InplayzThirdPartyLogin) 的規格，用於讓第三方合作夥伴透過廣告圖片將使用者導向 inplayz 並自動登入。文件說明了如何配置廣告圖片的位置與樣式，以及登入時需要傳遞的參數（authKey, thirdPartyID, thirdPartyNickName）。核心的後端驗證是透過 GET /partner/verify API 來確認第三方身份並回傳使用者資料。這個功能主要供外部廣告商整合使用，對 AI 開發來說，可以了解外部使用者透過特定參數自動登入的資料交換格式。

---

## 關鍵業務規則

- - 第三方登入必須提供三個參數給 InplayzThirdPartyLogin 的 loginObj：key (authKey), id (thirdPartyID), name (thirdPartyNickName)。
- 廣告圖片配置的 advObj 中若 nodeID 為 null，則依照 posType (top/left/right/bottom) 自動放置圖片；若 nodeID 不為 null，則在該指定 id 的 DOM 節點內生成廣告。
- 登入驗證成功後，API (GET /partner/verify) 會回傳 Code:10200 並包含帳號 (account)、使用者名稱 (userName)、Rank (rank)、站台 (site)、Email 等使用者資料。

---

## 關鍵設計決策

- - 選擇以純前端 JavaScript 套件 (3rd.js) 的方式提供給第三方整合，降低第三方整合複雜度，只需引入 JS/CSS 與設定參數即可。
- 廣告圖片採用固定 URL Pattern：https://inplayz.com/sport/advertising/3rd/{imgType}.png，方便第三方直接置換圖片類型而無需上傳。
