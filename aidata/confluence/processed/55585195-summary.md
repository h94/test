## 摘要

本文件定義了 PriceBackendService 中社群管理後台的 API 規格，包含身分標籤與聯盟標籤的 CRUD 操作。關鍵規則包括：聯盟標籤只能建立在可預測球種下，且建立時會從 PriceCenterProvider 獲取聯盟語系資料；身分標籤僅限五種預定義身分（admin/moderator/vlsport/killer/superkiller），更新時 zh-TW 語系為必填。所有標籤的多語系支援遵循既定的 Country Code 表（共七種語系），無資料時以 zh-TW 作為預設備援值。標籤資料最終儲存在 Meilisearch 中。

---

## 關鍵業務規則

- - 聯盟標籤只能建立在 GetGamePretictSetting 回傳的可預測球種下，不可對不可預測球種建立聯盟標籤
- 創建聯盟標籤時，系統會根據傳入的 LID 自動獲取該聯盟的語系資料，語系種類需符合用戶交互設計中定義的 Country Code 表（zh-CN, en-US, ja-JP, ko-KR, th-TH, zh-TW, vi-VN）
- 創建聯盟標籤時，若某語系沒有對應資料，則預設使用 zh-TW 語系的資料作為備援值
- 更新身分標籤時，請求中的 id（標籤代號）欄位不得為空，且只能是系統預定義的五種身分之一（admin, moderator, vlsport, killer, superkiller）
- 更新身分標籤時，data 中的 zh-TW 語系欄位不得為空；若 en-US 語系為空，則預設為 zh-TW 的值
- 更新身分標籤時，data 中的語系僅限 zh-TW 和 en-US 兩種
- 更新聯盟標籤時，id 和 data 中的 zh-TW 欄位不得為空
- 更新聯盟標籤時，若非 zh-TW 語系的資料為空，預設使用 zh-TW 的資料
- 聯盟標籤更新支援 Country Code 表中所有七種語系，身分標籤更新僅支援 zh-TW 和 en-US
- 標籤資料儲存於 Meilisearch（http://192.168.55.90:7700/）

---

## 關鍵設計決策

- - 選擇以 gameType 作為取得全部標籤的查詢維度，而非其他維度（如聯盟），讓前端可以一次獲取某球種下所有聯盟標籤和身分標籤
- 設計以 zh-TW 作為所有語系的預設備援值，確保至少有一個可用的顯示名稱
- 身分標籤和聯盟標籤採用不同的更新端點設計（/memberships vs /leagues/{gameType}），表示兩者被視為不同的資源
- 刪除操作僅需傳入 ID，不需要傳入完整資料，設計上較為簡潔
