## 摘要

本文件定義莊殺會員預測解鎖機制的修改內容。鎖定與解鎖以「聯盟+日期」為單位，同一會員對同一莊殺會員在同一聯盟日期內多次解鎖只計數一次。提供 PriceCenterSite 及 PredictService 共 4 個 API 端點的規格，以及支援此機制的 Cassandra 表 predictgames_{gameType}_lock_{yyyy} 的 schema。開發時可據此實作解鎖計數邏輯與 API 互動。

---

## 關鍵業務規則

- - 鎖定與解鎖的粒度為「某聯盟某日」的賽事預測，而非單場賽事。
- 莊殺會員解鎖次數統計以「聯盟+日期」為單位，同一解鎖會員對同一莊殺會員在同一聯盟日期內，無論解鎖多少場賽事，只增加一次解鎖計數。
- 解鎖行為由單一解鎖會員發起（一次解鎖一個預測），解鎖資訊記錄於 unlock_accounts map，包含帳號與時間。
- 解鎖次數統計須根據 unlock_accounts 中同一聯盟日期的「不重複解鎖會員數」計算，而非總解鎖次數。

---

## 關鍵設計決策

- - DB 採用分年分表（predictgames_{gameType}_lock_{yyyy}），推測為隔離歷史資料，提升查詢效率。
- unlock_accounts 使用 Map<text, text> 結構，直接以解鎖會員帳號為 key 存放解鎖時間，便於快速去重與查詢。
- 解鎖更新 API 一次僅處理一個 UnlockAccount，而非批次，保持操作單一性，簡化並發控制。
