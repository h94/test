## 摘要

此文件為 TCZB 團隊的 Sprint 作業手冊，定義了從前期規劃、Daily Check、各階段程序到 Release 與 Launch 的標準步驟與檢查清單。對 AI 開發最有用的部分是 Release 階段強制規定：新增 Service/API 須確認 Gateway 配置並更新 swagger.json，並提供 Swagger 修改指引頁面連結，可在自動化部署或 API 文件生成時作為流程基準。

## 關鍵業務規則

- - 若新增 Service 或 API 接口，Release 時必須檢查 Gateway 是否已配置該服務
- 若新增 Service 或 API 接口，必須修改對應的 swagger.json（修改步驟參考頁面：/pages/viewpage.action?pageId=5341691）
- StoryPoint 評估為 13 的 Story 必須召開 Design Review
- 每日下班前須確認 JIRA 問題與回覆都已填寫
- 進入測試階段後須關注 Bug 數是否收斂
- 測試後期須要求成員補齊分析文件
- 線上問題需要長期追蹤時，應在 JIRA 開立 Task 監督
