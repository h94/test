## 摘要

本文件記錄了指紋辨識（fingerprinting）的初步研究與設計決策。重點包括：前端取得 appname/pagename 的方式（JS 自取或第三方給定）、指紋 API 應獨立部署於與 BI 網站不同網段的機器並透過 Kafka 轉送資料、以及 bicontent 僅針對特定關鍵頁面收集必要欄位。這些決策為後續建置使用者行為追蹤系統提供基礎架構，AI 開發時可參考此設計來規劃資料流與部署拓樸。

---

## 關鍵業務規則

- - bicontent 收集規則：僅部分頁面需要傳送資料，不需每個 request 和 page 都送，只關注需要的頁面
- 不同 page 需組成對應的欄位和資料，以 PHP 來說可在 server 端生成並直接打印

---

## 關鍵設計決策

- - appname, pagename 取得方案：可選擇 JS 自行取得或由第三方給定
- finger API 部署位置：必須與 BI 網站不同機器，擁有獨立 domain 和對外 IP，且 IP 最好與 55.63 網段不同；與 55.63 的 Kafka 打通以傳輸資料；系統只需運行 OpenResty，因為功能僅是轉送資料到 Kafka，RAM/HD 需求不高
- 參考技術選型：前端指紋庫 fingerprintjs、資料壓縮庫 lz-string（含 C# 實現）
