## 摘要

本文件定義了從 SBL 後端 GraphQL API 擷取資料的完整流程，包含三個步驟：取得聯盟 ID與事件/組別列表、根據組別 ID 取得比賽列表與比賽 ID、再根據比賽 ID 取得單場詳細資料。文件中提供了每個請求的 payload 結構，並詳細說明從回應 JSON 中提取關鍵欄位的規則，例如比賽狀態對應碼、主客隊資訊、比分、逐節分數組合方式，以及 game_id 的編碼格式（SBL_年份_比賽ID）。另外說明了時間需從 UTC 轉換為本地時區(GMT+8)。適合 AI 開發 SBL 爬蟲 Agent 時直接引用。

---

## 關鍵業務規則

- - 比賽狀態對應：NOT_STARTED → 2，COMPLETED → 1，IN_PROGRESS → 0。
- 比賽日期時間取自 matchedAt 欄位，需從 UTC 時區轉換為 GMT+8。
- 比賽 ID 的儲存格式為 'SBL_年份_比賽ID'，例如 'SBL_2025_4785'，年份需從 matchedAt 或外部邏輯提取。
- 比賽各節分數由 homeSquadRoundScores 與 awaySquadRoundScores 兩個列表配對產生，最終結構為 [[主隊節分, 客隊節分], …]，需確保 round 順序正確。
- 聯盟名稱由 '超級籃球聯賽_第X季_例行賽' 格式組成，需從 API 回傳資料中組合。

---

## 關鍵設計決策

- - 採用單一 GraphQL 端點（https://xcelleratesports.com/graphql），透過不同 operationName 區分查詢類型，簡化多端點管理。
- 資料擷取分三階段進行：先取得聯盟與組別 ID，再取得比賽列表，最後取得單場詳細資料，可降低單次請求的耦合度，並符合爬蟲常見的分層策略。
