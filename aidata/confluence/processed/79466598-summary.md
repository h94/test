此文件定義了 TCZB 團隊 Sprint 的標準操作流程，包含從需求確認、分支建立、開發、測試到發布的各階段檢查清單，以及 Scrum Master 的每日檢查項目。對 AI 開發的幫助在於，可作為自動化 Sprint 管理代理的觸發條件和行動指南，例如自動提醒建立 JIRA 任務、檢查 Gateway 配置、提醒執行 Sonarqube 掃描或補齊文件。

## 關鍵業務規則

- - Sprint Day(-2) 必須建立 JIRA Sprint / Story / SubTask、Confluence 需求分析頁面、Git 分支，並執行 Sonarqube 取得警告數和 UT 覆蓋率。
- 若 Story Point 為 13，需在需求分析階段召開 Design Review。
- Release 階段如有新增 Service / API 接口，必須檢查 Gateway 配置，並修改對應的 swagger.json（修改步驟參考指定頁面）。
- 進入測試階段後，每日需注意 Bug 數是否收斂，測試後期需請成員補齊分析文件。
- 每日會議需了解成員問題，判斷是否影響時程並盡快回報上級；下班前確認 JIRA 問題和回覆都有填寫。
