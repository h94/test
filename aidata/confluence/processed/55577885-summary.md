## 摘要

本文件說明如何透過 1xbet.com 的 Service-API 取得賽果資料，包含兩個端點（取得聯盟列表、取得賽果），以及對應的查詢參數（如日期區間、球種/聯盟 ID 逗號分隔）和固定參數。提供球種 ID 對照表，並詳列從 game_data 萃取各欄位（聯盟、隊伍、日期時間、比分等）的鍵值與處理方式，例如 game_id 需由 self.get_game_id 函式取得、game_status 一律設為 Final，得分格式為巢狀列表。這對開發或維護 1xBET 賽果爬蟲的資料擷取與轉換邏輯有直接參考價值。

---

## 關鍵業務規則

- - dateFrom 參數須設為六小時前，dateTo 為現在時間，以查詢近期賽果。
- sportIds 及 champId 參數支援多個 ID 以逗號分隔。
- 爬取的賽果狀態（game_status）一律視為 Final，不區分進行中或取消。
- game_id 不可直接取用 game_data['id']，須透過 self.get_game_id 函式產生。
- 分數欄位 scores 的格式為巢狀列表，如 [[1,1],[1,0]]。

---

## 關鍵設計決策

- - 採用 1xbet Service-API 取得結構化 JSON 資料，而非解析網頁 HTML。
- 查詢中加入固定參數 presenceOfVideoBroadcast=false, lng=en, ref=1, gr=70, country=179，確保回傳內容一致。
- 不保留遊戲原始狀態，統一設為 Final，簡化後續資料處理（可能因為只抓已結束比賽）。
- 自定義 get_game_id 取代直接使用 API 回傳的 id，推測是為了套用內部統一的遊戲 ID 編碼規則。

## 注意事項

- ⚠️ - ⚠️ game_data['id'] 被劃去，表示曾為舊版做法，開發時應避免直接取用。
- ⚠️ scores 的巢狀格式需正確解析，可能包含多組子分數（如各局比分）。
- ⚠️ 外部 API 端點與參數可能隨時變動，需監控爬蟲運作。
