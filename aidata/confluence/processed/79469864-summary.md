## 摘要

本文件說明如何在 WidgetApi 中新增 CrawlerFlow Controller，透過 Dashboard 的 parser 工作表新增欄位來控制 CrawlerFlow 是否將特定站台資料轉換為 processedgamedata。控制訊號透過 Redis (192.168.55.80:db13, key: crawlerflow_controller) 傳遞，值為 1 表示解析中，值為 0 表示停止/暫停解析（停止超過 2 天會刪除 Redis key）。部署位置在 Local Docker Swarm 的 WidgetApi 服務中。

## 關鍵設計決策

- - 使用 Redis 作為 CrawlerFlow 控制訊號的傳遞媒介，而非直接呼叫 API 或使用資料庫，推測是為了降低耦合度並支援即時狀態查詢
- 控制欄位新增在 Dashboard 的 parser 工作表中，表示營運人員可透過 Google Sheets 介面管理各站台的轉換開關，不需動態開發後台
- 停止轉換超過 2 天會自動清除 Redis key，推測是為了避免 Redis 中累積過多閒置 key，需人工確認此清理機制是否由排程或 TTL 實作

## 注意事項

- ⚠️ - ⚠️ Redis 位址 192.168.55.80 為內網 IP，若環境遷移或 Redis 重整，此設定可能過期，需人工確認目前是否仍使用此位址
- ⚠️ 文件中提到 '停止/暫停解析(停止會將key值移除)'，此描述可能容易誤解：key 移除是停止後 2 天自動移除，還是停止時立即移除？需人工確認具體行為
