這份文件定義了 TCZB 團隊 Sprint 的標準作業流程，從估算時程、建立 JIRA Sprint、需求分析到上線監控與回顧會議的完整步驟。對 AI 開發的幫助是：了解每次 Sprint 中需要完成的檢查點，特別是 Release 階段必須確認 Gateway 配置和 Swagger 文件更新，確保 API 正確對外發布。可作為自動化流程或開發提醒的參考依據。

## 關鍵業務規則

- - Release 時如有新增 Service 或 API 接口，必須檢查 Gateway 是否已配置對應路由。
- 新增 Service 或 API 接口後，必須同步修改對應的 swagger.json，並依循 [建立/修改 Swagger API 文件] 的步驟進行。
- Sprint 開始前（Day -2）須執行 Sonarqube 取得警告數和 UT 覆蓋率作為基準。
- Story 點數較大（StoryPoint=13）時，需額外召開 Design Review 會議。
- Kickoff Meeting 中須估算 StoryPoint 並安排 Release／Launch 負責人及 Code Review 人員。
