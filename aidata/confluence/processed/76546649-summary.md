## 摘要

這是一份 CloudProviderV2 爬蟲的程式碼審查記錄，列出了多項實作改進要點，包括：統一使用框架的 format 參數處理 JSON 請求、簡化空值與空列表的判斷、避免使用 Python 關鍵字命名變數、在大量建立 thread 前加入短暫延遲、根據比賽狀態（pre-game / inplay）設定不同的抓取間隔，以及移除不需使用的 selenium 清理程式碼。這些建議有助於提高爬蟲穩定性與程式碼可讀性。

---

## 關鍵業務規則

- - 框架發出 HTTP 請求時，若 API 為 JSON 格式，應傳入 format='json()'，eval 方法會自動解析，service 層不需再對回應進行 load 動作。
- 檢查 data 為 None 或空 list 時，直接使用 `if not data: continue` 簡化，不可使用冗餘的 else 區塊。
- 變數名稱不可使用 Python 關鍵字（如 id），即使不報錯也應避免。
- 一次性開啟大量 thread（例如 100 個以上）前，必須加入 0.1 秒的 time.sleep 來避免潛在的執行緒問題。
- 爬蟲的 sleep 間隔應根據比賽狀態調整：pre-game 階段每 60 秒抓取一次，inplay 階段每 5 秒抓取一次（以單一爬蟲平均速率為準）。
- call dashboard 的迴圈內的 sleep 必須固定為 60 秒。
- 檔案命名必須加上 V2 後綴。
- 記錄 PC 與 IC 數值時，格式必須為 'PC:XXX,IC:YYY'（加上冒號）。

---

## 關鍵設計決策

- - 採用框架的 eval 方法統一處理 JSON 反序列化，避免在 service 層重複解析，減少冗餘程式碼與潛在錯誤。
- 基於開發經驗，在大量 thread 啟動前加入 0.1 秒延遲，預防因瞬間大量排程導致的奇怪異常（決策原因為經驗法則，非強制技術限制）。
- 依比賽狀態區分抓取頻率，是考量資源利用率與資料即時性的平衡，並非所有階段都需要高頻率抓取。
- 移除 selenium driver 清理程式碼，因該爬蟲不使用 selenium，避免引入非必要的依賴與可能殘留的 driver 程序。
