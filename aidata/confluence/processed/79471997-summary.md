## 摘要


本文件記錄針對 Widget API 的三項優化項目：1) 在 Kafka 表上加環境忽略選單，提供橘色（暫時停止監控）與紅色（永久停止監控）兩種模式，且橘色模式與左側監控設定連動；2) 將 group 名稱帶有 zbxx 的項目從 Dashboard 與警報中排除，因為已知這類群組觸發警報後只會手動關閉監控，無實際處理價值；3) 為防止 Google API 回傳異常導致暫停時間被錯誤設定過長，增加暫停時間的資料驗證及失敗紀錄機制，以便追蹤根本原因。

---

## 關鍵業務規則


- - 環境忽略功能：Kafka 表可多選環境，選中後該環境掛掉不會觸發警報。
- 橘色忽略環境按鈕：代表暫時停止監控，暫停時間長度與左側監控模式設定相同（例如暫停 N 小時），暫停結束後服務會自動取消所有橘色勾選，並將監控模式恢復為監控中。
- 若左側模式為暫停監控，且右側忽略特定環境（橘色），則僅對選取的環境暫停 N 小時，其他環境仍維持監控。
- 紅色按鈕：無視左側監控模式設定，選取後即永久停止該環境的監控。
- 針對 group 名稱包含 zbxx 的項目，系統不會將其顯示在 Dashboard 上，也不會發出 group id stop 或 too many lag 等相關警報。
- 暫停時間計算後必須通過資料驗證，若驗證失敗則記錄 log（含錯誤資訊），以利後續排查（目前不直接修正時間）。

---

## 關鍵設計決策


- - 對於 zbxx 群組直接過濾，而非保留但抑制警報，理由是經驗顯示此類警報僅引出人工作業停止監控，無實際修復價值，直接隱藏可減少雜訊。
- 暫停時間異常問題先採用觀測式處理（增加驗證與 log），不直接修正，因為原因不明且可能源自 Google API 回傳錯誤資料。
