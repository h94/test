## 關鍵業務規則

- - 每日會議應了解成員問題，判斷是否影響時程，並盡快回報上級
- 成員必須確實填寫 JIRA Work Log
- 測試階段需注意 Bug 數量是否收斂
- 測試後期要補齊分析文件
- 下班前確認 JIRA 問題和回覆都已填寫
- 線上問題若需長期關注，需在 JIRA 開 Task 監督
- Sprint 過程中，若 StoryPoint = 13 則須召開 Design Review
- 新增 Service / API 接口時，必須檢查 Gateway 配置，並修改對應的 swagger.json
