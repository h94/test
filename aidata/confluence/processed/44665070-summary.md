## 摘要

本文件定義了一個用於前台取得賽事賠率的 API 端點 `/game/odd/{gtype}/{gdate}`，採用 POST 方法。請求須帶 `modes` 查詢參數控制玩法（HA/OU/兩者），並在請求體中傳入多個外部站點的識別資訊（site, sitelid, sitegid）。回應為一個以站點 domain 為 key 的物件，每個站點內包含 `ha`（讓分）、`ou`（大小）、`oxt`（獨贏）三種玩法的 `spread` 與 `odds`。此 API 透過 Python 後端聚合多家賠率供應商資料，對 AI 開發者理解資料格式與參數使用規則很有幫助。

## 關鍵設計決策

- - 使用 POST 而非 GET，可能因為請求體需攜帶較多站點資料，更適合用 JSON 傳輸。
- 回應結構以站點 domain 為鍵直接對應，便於前端快速查找特定站點的賠率。
- 透過 modes 查詢參數動態控制回傳的玩法資料，減少不需要的資料傳輸。
