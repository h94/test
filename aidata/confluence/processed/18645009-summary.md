## 摘要

這份文件定義了 SportKing 會員系統的核心業務流程，涵蓋註冊、登入、第三方登入、登出、忘記密碼、更改密碼及修改基本資料等操作。對 AI 開發而言，此文件的最大價值在於說明了各流程中前端、MemberService、TokenService 與 Redis 之間的資料傳遞與驗證順序。此文件為理解會員服務的業務邊界與資料流提供了清晰的基礎。

---

## 關鍵業務規則

- - 註冊/第三方登入時，前端必須檢查 Cookie 是否重複，作為防禦機制的一部分。
- 註冊成功後，由 MemberService 生成 Mail 內容，並透過 MQService 非同步發送驗證郵件。
- 忘記密碼流程中，TokenService 會將重設密碼的 Token 存入 Redis，並設定 1 小時的有效期限。
- 更改密碼或修改基本資料（如暱稱）前，前端需驗證資料格式，Web 端需驗證登入狀態（Cookie），最後由 MemberService 負責業務驗證與 DB 更新。
- 登入成功時，MemberService 需在 DB 中記錄 logintrack, usertrack, fingerlog, accountlog，並將登入狀態存入 Redis 快取。
- 登出時，MemberService 需清除 Redis 中的登入快取，並由 Web 端清除 Cookie。
- 更新會員等級是透過獨立的 Tools 呼叫 MemberService，更新 DB 的帳號 rank 後，必須同步呼叫 ForumService 更新論壇的 rank。
