## 摘要

本文檔描述 WidgetApi 新增透過 Redis 控制爬蟲 Parser 停止/暫停解析的功能。當用戶於 Google 試算表設定停止或暫停監控時，WidgetApi 將狀態寫入 Redis（key: parser_controller），爬蟲 Parser 定期讀取並據此停止發送數據。同時說明了因停止送數據會觸發 Dashboard 中的 SiteInfo 警報，需手動關閉。文中提供程式碼片段展示如何在 TCZB 套件新增 Redis 連線、配置 Appsetting 參數，並在 CrawlerService 中建立監聽執行緒，以供開發參考。

---

## 關鍵業務規則

- - 停止/暫停監控時，將停止信號寫入 Redis hash `parser_controller`，值為 0 代表停止/暫停（或移除 key 表示停止），值為 1 代表解析中。
- 停止解析狀態若持續超過 2 天，對應的 Redis key 值將被自動刪除（清理機制）。
- WidgetApi 會自動從 Crawler Server Site Info 表格抓取所有站台，若 Google 表單中不存在則自動新增至 Dashboard 的 SiteInfo 與 Parser 工作表。
- 因 Parser 停止送數據導致 Dashboard 的 SiteInfo 變為紅字時，會觸發 ErrorSiteInfo 警報，需手動關閉該警報。

---

## 關鍵設計決策

- - 選用 Redis (192.168.55.80 db13) 作為控制信號的傳遞媒介，利用 hash 結構 `parser_controller` 儲存各站點的解析狀態。
- WidgetApi 的每個站點必須設定與 SiteInfo 相同的 Redis key，以確保對應關係（在 Appsetting.py 中配置）。
- 在 WidgetApi 服務中建立監聽執行緒（listen_status），持續檢查 Redis 狀態，以便即時反映解析器控制狀態（或為其他用途）。
- 舊專案需在安裝 TCZB 套件時使用 `--upgrade` 參數，以取得包含 Redis 相關功能的版本。

## 注意事項

- ⚠️ - ⚠️ Redis 狀態值的定義與移除規則有模糊：文件指出「0: *停止/暫停解析(停止會將key值移除)」以及「停止解析超過2天會將 Redis 對應的值刪除」，實際行為需確認：停止時是將值設為 0 還是直接移除 key？可能為設為 0 然後定時清理。
- ⚠️ 文中提到「停止/暫停監控」但未明確區分「停止」和「暫停」的 Redis 信號差異，兩者可能共用同一狀態 0。
- ⚠️ WidgetApi 監聽執行緒的目的未詳細說明，若只為爬蟲讀取，為何需要 widget 端主動監聽？推測用於前端顯示狀態或觸發後續動作。
