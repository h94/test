## 摘要

這是一份 Sprint 流程的標準操作手冊，從 Day -3 的需求確認到 Day 12 的 Sprint 結束，詳細列出各階段（估計排程、建立 JIRA、需求分析、Kickoff、開發、Code Review、測試、Demo、Release、Launch、回顧）的檢查事項。對於 AI 開發，此文件提供了團隊在一個 Sprint 中的例行工作項目與時間點，可作為自動化流程檢查或提醒的參考依據，但內容不涉及具體服務的業務邏輯或技術實作細節。

## 關鍵業務規則

- - Day(-3) 前需與需求方確認 Story、安排開發與測試分析、討論時程並公告。
- Day(-2) 需建立 JIRA Sprint / Story / SubTask、Confluence 需求分析頁面、Git 分支，並執行 Sonarqube 取得警告數與 UT 覆蓋率。
- 當 Story 點數為 13 時，需召開 Design Review。
- Kickoff Meeting (Day 0) 由開發測試人員講解需求，並估算 StoryPoint，安排 Release / Launch 負責人及 Code Review 人員。
- Release 階段 (Day 9) 若有新增 Service / API 接口，必須檢查 Gateway 配置，並修改對應的 swagger.json。
- Launch 階段 (Day 10) 需安排人員合併主線、監控上線系統狀況，並請成員填寫回顧會議內容。
