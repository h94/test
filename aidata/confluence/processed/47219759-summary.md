## 摘要

本文件為 CrawlerAgent 的技術設計記錄，目標是將框架改成 TCZB 解析框架並從 betsapi 爬取賽前賠率。爬取採逐一場次呼叫 API 的方式，目前僅實作全場讓分(HA)與大小分(OU)兩種玩法。後續還規劃了速度測試、單元測試與雙機部署測試。對於 AI 開發來說，這份文件明確了 CrawlerAgent 在此階段的資料來源(betsapi)、爬取模式(逐場呼叫)與實作範圍(僅 HA/OU)。

## 關鍵設計決策

- - 採用 TCZB 解析框架進行重構，取代原有框架以統一系統架構。
- 爬取賽前賠率採逐一場次呼叫 API 的方式，而非批次處理。
- 第一階段只實作 HA(Handicap，讓分) 與 OU(Over/Under，大小分) 兩種賠率玩法，其他玩法暫不處理。
- 開發流程設計為：先改框架 → 解析賠率 → 測試速度 → 寫單元測試 → 測試雙機部署的可行性。
