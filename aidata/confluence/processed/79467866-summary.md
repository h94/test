## 摘要

本文件定義台灣 Yahoo 運動賽事與新聞的爬蟲技術方案。賽事透過 Scoreboard API 獲取 NBA、足球等聯盟的比賽資訊（比分、隊伍、各節分數），足球需額外請求足球頁面以取得動態的聯盟列表。新聞則從 HTML 中提取文章 URL、發布時間與 ID，僅抓取當日文章並限制單次 20 篇，需提高抓取頻率；評論透過另一 API 取得。專欄新聞使用獨立列表 API 與 list_id。整體設計提供明確的 API 端點、參數與響應解析規則，對開發者實現自動化數據採集非常有幫助。

---

## 關鍵業務規則

- - 賽事 API 的 date 參數需涵蓋昨天、今天、明天三天的比賽，可能需分三次請求（文件示例僅指定單一日期，需人工確認實際請求方式）
- 足球聯盟需先請求 https://tw.sports.yahoo.com/soccer/ 頁面，從中提取可用的聯盟 ID 列表，再將各 league_id 帶入 scoreboard API 獲取賽事
- API 回傳的比賽時間（start_time）需進行時區/格式轉換後使用
- 主客隊名稱由 team_id 透過回傳物件中的 teams 集合查找 full_name 賦值，而非直接從比賽物件取得
- 比賽各節分數取自 game_periods 陣列中的 home_points 與 away_points
- 文章抓取時僅保留發布時間（pubtime）為當日的文章，非當日者跳過
- 單次文章抓取最多 20 篇，因此爬蟲頻率需加快以覆蓋所有新文章
- 文章的 article_id 用於呼叫評論 API 獲取評論內容
- 專欄新聞（經典賽、日職、籃球、中職）使用不同的 list_id 與列表 API，需帶入正確的 list_id
- 檔案輸出命名規則為 TW_Yahoo_{自定網頁名}.html.txt，例如 TW_Yahoo_030724376.html.txt

## 關鍵設計決策

- - 優先使用結構化 API（Scoreboard API、List API）而非網頁解析來獲取賽事與新聞數據，以確保數據一致性與穩定性
- 透過 date 參數指定日期範圍，使爬蟲可靈活回溯歷史賽事或僅擷取近三日比賽
- 文章僅抓取當日發布的內容，避免累積過期資訊，同時透過提高抓取頻率彌補單次請求筆數限制（20 篇）
- 足球聯盟列表動態變化，因此不硬編碼聯盟 ID，而是從足球入口頁面即時獲取，讓系統具備適應性
