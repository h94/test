## 摘要

此任務定期（每24小時）從資料庫查詢明日足球比賽，擷取聯盟與隊伍名稱後，透過固定 prompt 模板呼叫 GPT API 生成繁體中文介紹（開頭固定為中英文名稱）。產生的內容經 opencc 簡繁轉換後寫入 192.168.9.233 的 info，每個聯盟或隊伍僅寫入一次。開發過程中發現 GPT 輸出常含有不精確的數據（如成立時間、球隊數量等），且 API 無連網能力，未訓練過的實體資料錯誤率高。經評估後決定不刻意過濾數據，接受「看起來有模有樣」的介紹，並記錄此取捨以供後續 AI 開發參考。

---

## 關鍵業務規則

- - 每24小時執行一次，從 DB 查詢明天的足球比賽，提取聯盟與隊伍名稱後呼叫 GPT API。
- 生成的介紹開頭固定為聯盟/隊伍名稱的中英文（或原文），英文/原文放在括號內。
- GPT 輸出雖在 prompt 中指定繁體中文，但仍可能包含簡體，因此一律使用 opencc 進行簡轉繁處理。
- 每筆聯盟或隊伍的介紹僅寫入一次至 192.168.9.233 的 info，避免重複寫入。

---

## 關鍵設計決策

- - 選擇無視 GPT 輸出中的數據不準確問題（方案3），原因是若要求不輸出數據會使內容空洞，而餵入正確資料（如 wiki）則失去使用 GPT 的意義；最終取捨為接受近似內容。
- 採用 opencc 進行簡體轉繁體，而不是完全依賴 prompt 控制，因為 GPT 仍容易產出簡體。
- 寫入目標為內部 info（192.168.9.233），且限制每筆僅寫一次，推測是為了節省儲存或避免更新衝突。

---

## 注意事項

- ⚠️ - ⚠️ GPT 產出的數據（如成立時間、球隊數、英文翻譯等）準確度粗估不到50%，使用者需認知此為近似內容。
- ⚠️ GPT API 不具連網能力，若聯盟/隊伍資訊未包含在訓練資料中，生成的介紹基本是錯誤的。
- ⚠️ 輸出示例中包含非足球的「加拿大超級聯賽」及「美國國家足球超級聯賽」等，需確認是否為預期內的聯盟範圍。
