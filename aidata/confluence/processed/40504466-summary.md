## 關鍵業務規則

- - 建立 JIRA Sprint 時需同步建立 Confluence 需求分析頁面、Git 分支，並執行 Sonarqube 取得警告數與 UT 覆蓋率。
- Story 估算為 13 點（含）以上時，必須召開 Design Review。
- 測試後期（進入測試階段）應要求成員補齊分析文件。
- Code Review 結束後，需確認所有審查內容都已修改或記錄。
- Release 階段若有新增 Service 或 API 接口，必須檢查 Gateway 配置。
- 新增 Service 或 API 接口時，需修改對應的 swagger.json（參考特定 Confluence 頁面步驟）。
- 線上問題若需長期關注，應於 JIRA 開立 Task 持續監督。
