## 摘要

這份 Sprint 199 的 code review 記錄指出 productservice 相關程式碼的多項實作問題與修正方向，包括：新增、更新、刪除操作不應回傳訊息；SQL 語句格式需遵守 SELECT 後空一格；Cassandra 更新語句應完整指定所有 primary key 條件；型態宣告應使用 VARCHAR 而非 TEXT；對於屬於 clustering key 的欄位（如商品種類）無需驗證；未使用的路由參數應移除以精簡路由；domain service 中無特殊需求的內部清單變數應宣告為 private。這些規範直接影響 productservice 的開發與維護。

---

## 關鍵業務規則

- - 新增、更新、刪除類型的 API 操作不回傳訊息（如不回傳實體內容或成功訊息）
- 若資料表欄位為 Cassandra 的 clustering key，該欄位不可更新，前端或服務層不應對其進行任何驗證
- domain service 中若無特殊需求，內部使用的清單變數（如 ProductClassTypes）必須宣告為 private，不可設為 public
- 未在路由邏輯中使用的路由參數必須移除以保持路由簡潔

---

## 關鍵設計決策

- - Cassandra 的 UPDATE 陳述式必須包含所有 partition key 與 clustering key 條件，否則操作無法正確執行
- 資料型態統一使用 VARCHAR 取代 TEXT，以符合 Cassandra 的型別定義習慣（可能避免不必要的外部定義或查詢差異）
- 對於 clustering key 欄位，因其禁止更新，直接省略相關驗證邏輯，減少不必要的程式碼
- API 路由參數若未被使用即應移除，可簡化 API 簽名並避免維護困惑
