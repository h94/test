## 摘要

此文件定義 MemberService 的API端點與規格，包括會員註冊、登入、密碼管理、資料查詢與後台管理等功能。對 AI 開發提供路由、請求參數與回應格式的明確參考，有助於實作服務介面與模擬用戶行為。

---

## 關鍵業務規則

- - 會員註冊須提供 Finger、Account、Password、UserName、Address；註冊後需通過 AuthKey 驗證。
- 登入需要 Account、Password、Finger、Address；第三方登入使用獨立路由 /memberservice/api/loginforsite。
- 賽事站台訂閱者與管理員有獨立的註冊與登入路由，參數僅需 Account、Password、UserName（無 Finger/Address）。
- 忘記密碼流程：先請求 /memberservice/api/requestpassword（提供Account、Finger、Address），獲得 AuthKey 後再呼叫 /memberservice/api/forgetpassword 設定新密碼。
- 更改密碼（已知舊密碼）使用 /memberservice/api/changepassword，需提供 OldPassword。
- 後台工具操作需提供 AuthKey 以識別會員，可更新會員基本資料、層級或重設密碼。

---

## 關鍵設計決策

- - API 回應統一使用 { code, message } 結構，便於前端統一處理。
- 不同登入場景（一般、第三方、賽事訂閱者/管理者）分離為獨立路由，避免業務耦合。
- 登出功能路由標記為「暫無」，可能尚未實作，保留佔位。
- 後台管理相關 API 集中於 /backendtools/ 路徑下，使用 AuthKey 而非直接以 Account 操作，透過 AuthKey 取得對應會員，可能與權限控制相關。
