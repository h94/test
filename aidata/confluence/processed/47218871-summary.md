## 摘要

說明以 Nuxt3 為基礎的前端專案目錄架構與設計慣例。文件定義各目錄用途，包括 `api/`（useFetch 封裝）、`components/`（依路徑自動命名）、`pages/`（自動路由）、`server/`（後端 API）、`stores/`（Pinia 狀態管理）等，並規範 TypeScript 型別命名（interface 大寫 I 開頭、type 大寫 T 開頭）。這份文件可幫助 AI 理解現有前端專案的程式組織方式與自動化機制。

## 關鍵設計決策

- - 選擇 Nuxt3 作為前端框架，以 App.vue 為進入點，打包後由 server 端解析 JS 並回傳給網頁。
- 不使用 axios，採用 Nuxt 內建的 useFetch 進行 API 呼叫。
- 元件依資料夾路徑自動產生組件名稱（如 `components/Header/Drop.vue` → `<HeaderDrop>`），並按頁面 / 功能劃分子目錄。
- 頁面路由透過 `pages/` 資料夾結構自動生成，支援動態路由（[param]）。
- server 端 API 同樣以資料夾路徑和檔案後綴區分 HTTP 方法（如 `server/api/test.get.ts` 對應 GET）。
- 狀態管理選用 Pinia 而非 Vuex，寫法接近 Vue component 風格，使用時直接引入 store 即可。
- 共用的設定檔放在 `config/`，不受環境影響；環境相關配置則放在 `.env`。
- 共用方法放在 `utils/`，以 global 及頁面功能分類。
- middleware 分為頁面用（存放於 `middleware/`，類似 vue-router 的 beforeEach）與 server API 用（存放於 `server/middleware/`）。
- TypeScript 命名規範：interface 以大寫 I 開頭，type 以大寫 T 開頭。
