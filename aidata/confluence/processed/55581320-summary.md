## 摘要

本文件定義了從 PS3838 體育搏彩供應商抓取賽事賠率的 API 規格，包括端點、請求頻率限制（每 2 秒 1 次）、game_type 與數值對應表，以及兩個關鍵 payload 設計（btg=1 用於一般盤口，btg=100 用於總分盤口）。文件中說明了 mk 參數控制早盤、今日、賽中等情境，與 v 參數用於取得實時逐球資料（pbp）。對 AI 開發 crawler 服務而言，可據此正確構建請求並解讀回傳結構。

## 關鍵設計決策

- - 採用兩個獨立 payload 請求一般盤口（btg=1）與總分盤口（btg=100），以區分不同市場類型。
- 透過 mk 參數（0=早盤, 1=今天, 2=賽中）控制獲取不同時間區段的盤口資料。
- v 參數設為空或 '0' 時返回比賽基礎資訊，傳入 13 位時間戳則返回特定時間點的賽況（pbp），實現即時資料更新。
- sp 參數設為 '4' 代表棒球（需人工確認對應關係是否僅適用於此需求）。

## 注意事項

- ⚠️ - ⚠️ API 有嚴格速率限制（每 2 秒 1 次），但文件未說明應對 429 狀態碼的重試機制或退避策略。
- ⚠️ game_type 字典中部分條目被註解（如 VBTotal, ESMap 系列），可能已廢棄或暫未使用，實作時需確認完整性。
- ⚠️ 'sp' 參數註解為「球種」，實際值為 '4'，推測為棒球，但未提供完整球種代碼表，需人工確認。
- ⚠️ v 值的行為描述（空或 0 輸出比賽資料，13 位時間戳為 pbp）可能與實際 API 測試有出入，宜以實測為準。
