## 摘要


文件定義 PriceCenterSite 與 PriceBackendService 在反饋系統與 Z 幣排行榜的 API 技術設計。新反饋 API 支援一次上傳訊息與最多 3 張圖片，原有反饋 API 停用；歷史反饋查詢增加圖片路徑輸出。Z 幣排行榜 API 提供日、月排名，排序邏輯由純正收入改為正負收入相加後排名；回傳前 10 名，若查詢用戶非前 10 名則附加其排名資訊於列表末端。PriceBackendService 的排行榜批次計算 API 同步調整至正負收入加總。

---

## 關鍵業務規則


- - 新增反饋訊息與圖片時，feedback.Account 為用戶 authkey，feedback.Email、feedback.TID、feedback.Problem 為必填，不可為空值。
- 使用者上傳圖片數量限制最多 3 張，超過 3 張或圖片檔案異常將報錯。
- 既有反饋訊息 API（/api/feedback/questions 舊版）將不再使用，取代為新的 POST /api/feedback/questions。
- 取得歷史反饋資訊時，回應 JSON 中增加 imgPaths 陣列，包含圖片完整 URL 路徑。
- Z 幣排行榜統計由原先僅計算正收入（TypeName 正獲利）改為正負收入相加後的總和再進行排名。
- 排行榜 API 的 zcointype 提供三個選項：predict、community、membership。
- 查詢排行榜時，若傳入 account 參數且該用戶不在前 10 名，則將該用戶的排名資訊追加在第 10 名之後（顯示於第 11 位）；若 account 為空則僅回傳前 10 名。
- 排行榜資料來源為位於 nginx 空間的 9 個統計檔案，需過濾用戶機密資訊後依 zcointype 輸出對應的日、月排名。

---

## 關鍵設計決策


- - 新反饋 API 採用與社群水桶 Z 幣回收機制（TCZB-4306）相同的圖片上傳方式，傳輸圖片與反饋訊息至 FeedbackService，以維持前後端傳輸一致性。
- 排行榜收入統計由純正收入改為正負收入相加，原因為正確反映用戶總獲利，而非僅看正向交易。
- 排行榜 API 不直接查詢資料庫，而是讀取已產出的統計檔案（存放於 nginx），以提升回應速度並降低即時計算負擔。
- 排行榜結果需過濾非統計資訊與用戶隱密欄位，避免機敏資料外洩。

## 注意事項


- ⚠️ - ⚠️ 文件提及「原本的反饋訊息 API 不繼續使用」，開發時須確認舊版 API 是否已完全下線或仍需共存過度期。
- ⚠️ 表格中「取得賽事站台會員反饋」標記為紅色既有 API，但其回應範例中 imgPaths 欄位為 null，須對照實作確認是否舊版回應會缺少此欄位，避免新舊版相容性問題。
- ⚠️ 排行榜統計檔案位於 nginx，需確保檔案產生排程與 API 讀取權限正確；若統計檔案未及時更新，可能導致排名資訊不準確。
