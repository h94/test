## 摘要

本文件記錄了排行榜管理工具在 Sprint 69 期間的測試缺陷與修正過程，涵蓋 UI 調整、輸入驗證規則、錯誤提示邏輯、按鈕行為、排名計算規則等。對 AI 開發而言，可從中擷取排行榜後台的預期互動行為與邊界條件，例如：API 驗證時機、非 API 資料來源的限制、排名相同時的處理方式、輸入值強制範圍、錯誤訊息顯示位置等，有助於設計自動化測試或模擬使用者操作。

---

## 關鍵業務規則

- - 更新頻率欄位輸入值強制大於等於 0（即時監聽並修正）。
- API 網址輸入僅在前端驗證格式是否正確，API 實際回傳正確性於按下「確定」後才檢查。
- 當兩筆資料排名相同時，系統應正確顯示並列排名或順延（文件描述問題為相同排名會導致往後一名，需人工確認正確業務規則）。
- 未選擇模板時按下「確認」應在模板選擇欄位旁顯示錯誤提示，且不可關閉視窗。
- 資料來源為非 API 者，按下「強制刷新」時顯示禁止圖標並提示需編輯資料，不可執行刷新。
- 密碼錯誤時須顯示明確提示訊息。
- 上傳檔案時未選擇檔案應阻擋「確認」按鈕，或提供沿用舊資料選項。
- 所有輸入驗證錯誤訊息必須顯示在對應欄位附近，並持續顯示直到使用者修正，不可顯示在右上角且自動消失。
- 輸入檢查時機：離開輸入框不應立即跳錯誤，應在按下「確認」前才進行整體檢查（例如自訂 API 網址欄位）。
- 手動新增排行時，排名根據累積量自動排序，每次按下「確認」後重新計算。
- 資料來源非 API 的排行榜不可自動更新，後台應阻擋並給予提示訊息。
- 第一次新增資料時若未填妥，阻擋「確認」按鈕；但若已通過確認後再次編輯且資料有誤，阻擋功能仍應生效（修正後需根據各資料來源判斷是否填妥）。

## 關鍵設計決策

- - 排行榜設定提示（Toast/彈窗）新增關閉按鈕，避免遮蔽下方「新增排行榜」按鈕。
- 排行榜預覽畫面移除左側功能欄位，簡化預覽。
- 新增/刪除欄位時，加號固定在第一欄位置，視窗高度僅向下延伸，不影響上方佈局。
- 手動新增與上傳檔案按鈕位置調整以改善操作動線。
- 多個問號幫助圖示都導向同一頁面同一位置，改為只保留一個，或導向後自動捲動至對應說明區塊。
- 所有錯誤訊息改為在對應畫面欄位旁顯示，且不自動消失，取代原本右上角的短暫提示。
- API 文件中的程式碼說明以底線或顏色強調，提高可讀性。
- 編輯模板時，前端引入配置檔處理標籤中英文對照，若找不到對應則降級顯示 className。
- 輸入驗證通過時，於欄位旁顯示打勾圖示作為即時回饋。
