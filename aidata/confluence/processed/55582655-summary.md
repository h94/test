## 摘要

本文件定義 ProductService 中商城商品的 CRUD 功能設計，包含 Cassandra 與 Redis 的資料結構、API 路由與參數、以及管理員操作商品的完整流程。對 AI 開發而言，重點在於理解商品資料的儲存策略（Cassandra 為持久層，Redis 為快取層並儲存剩餘數量）、快取查詢參數 cache 的預設行為、以及更新與刪除商品時對 Redis 快取的連動操作。文件也明確規範了商品狀態流轉與資料驗證規則，是實作商品服務代理的關鍵參考。

---

## 關鍵業務規則

- - 新增或更新商品時，商品名稱（語系：zh-TW）不得為空
- 新增或更新商品時，商品類別（PClass）不得為空
- 新增或更新商品時，商品圖片路徑（Image_Path）不得為空
- 新增或更新商品時，商品價格（Price）必須大於 0（不得小於等於 0）
- 新增或更新商品時，商品數量（Initial_Quantity）不得小於 1
- 新增或更新商品時，商品狀態（Status）只能是「上架中」或「已停售」
- 更新商品時，若商品狀態為「已停售」，需刪除 Redis 中的對應快取
- 刪除商品時，需同步刪除 Redis 中的對應快取
- 查詢商品時，快取參數 cache 預設為 true（從 Redis 讀取），設為 false 時才從 Cassandra 讀取

---

## 關鍵設計決策

- - 選擇 Cassandra 作為主要資料庫，Redis 作為快取層：Cassandra 儲存完整商品資料（含初始數量），Redis 儲存快取資料並以「剩餘數量」取代「初始數量」，推測是因應高頻讀取與庫存查詢的效能需求
- Redis Key 設計為 Store_{class}_Products，以商品種類作為快取分群，支援依分類查詢的快取策略
- 時序圖顯示更新商品時會先檢查商品是否存在及狀態是否為已停售，再決定是否更新及操作快取，確保資料一致性
- API 設計採用 RESTful 風格，以 pclass 和 pid 作為路徑參數進行資源定位
