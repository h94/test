## 摘要

本文件定義錦標賽投注功能的 API 規格，包含三大端點：新增注單、取得賽事列表、查詢錢包餘額。關鍵業務前提是取得賽事前必須驗證會員是否已購買門票，未購買者無法取得賽事資料；關盤後只回傳賽事資料不允許投注。對 AI 開發而言，此文件提供了請求參數結構、賠率資料巢狀格式（Mode/OddType/Odd/Spread）的具體定義，以及後台管理員派發鑽石的操作方式，可用於建立 API Mock 和撰寫整合測試。

---

## 關鍵業務規則

- - 取得錦標賽賽事 API（GET championships/{gameType}/{id}/games）必須驗證會員是否已購買門票，未購買者無法取得賽事資料
- 錦標賽賽事若超過關盤時間，API 只回傳賽事資料，不可進行投注
- 會員錦標賽錢包餘額決定可投注金額，餘額不足時需人工確認是否允許投注

---

## 關鍵設計決策

- - 錦標賽投注採用獨立錢包（championshipwallets），與一般會員錢包分離，需透過專屬 API 查詢餘額
- 賠率結構採用巢狀格式：Mode（HA/HalfHA/HalfOU/OU）→ Spread/1X2/分數 → A/H/O/U，支援讓分、大小、半場等多種玩法
- 後台派發鑽石使用固定 T_Type=77，統一由 BackendService 處理
