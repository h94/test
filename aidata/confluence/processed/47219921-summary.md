## 關鍵設計決策

- - 建議將過長的 Method（13~153行）拆分成多個職責單一的 Function。
- 建議使用 mapping 方式取值，而不是直接處理 result、inplay、pregame（需人工確認：前提是 result 一定是 event）。
- 空值檢查應同時涵蓋所有必要欄位（如 team_home, team_away），使用 all() 進行判斷，而非只檢查單一欄位。
- Function 報錯時應確保有回傳值（return 應放在錯誤處理之後）。
- 錯誤訊息應具體，例如直接指出不支援的 game_type，而非僅提示檢查 sport_code。
- 迴圈內應使用 append 新增資料，而非一直覆蓋 matches 變數。
- NameMap 不需要 game_date, game_time, game_id, game_status，但需要 site 欄位。
- 重複或類似的程式碼應合併成一個 Function。
- 某些不必要的 if 判斷可以省略以簡化程式碼。
