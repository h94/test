## 摘要

本文件定義了 PlayMode（球種玩法模式）的系統預設值管理功能，包含對 GameSettingService 和 PriceBackendService 兩服務的 API 設計。核心功能為：新增/修改/刪除球種的 PlayMode，以及為 PlayMode 新增支援站台（區分全新站台和既有站台）。對 AI 開發的幫助是：理解 PlayMode、球種（GameType）、支援站台（Site）之間的關係，以及操作時的 API 介面規範和資料傳遞格式。

---

## 關鍵業務規則

- - PlayMode 新增（API #3, #5）時需傳入 PlayModeSettings Model 的列表，針對指定球種（gameType）進行批次新增
- PlayMode 修改（API #4, #6）時需傳入 ChangePlayMode Model 列表，包含舊名稱（OldName）、新名稱（NewName）和完整的 PlayModeSettings
- PlayMode 刪除（API #5, #7）時僅需傳入要刪除的 PlayMode 名稱字串列表（List<string>），例如 ["az", "aa"]
- PlayMode 新增支援站台（API #6 of GameSettingService, API #8 of PriceBackendService）透過 ?action 參數區分兩種模式：new（新增全新站台，需更新站台開通紀錄）和 old（新增既有站台）
- 針對 PriceBackendService，取得全部球種 PlayMode（API #2）和取得全部球種支援站台（API #4）的備註明確標示「不需要對接 gamesettingservice」，暗示 PriceBackendService 有自己的資料來源或實作邏輯

---

## 關鍵設計決策

- - 採用雙服務架構（GameSettingService 和 PriceBackendService），兩者提供幾乎相同的設定功能，但 PriceBackendService 的部分查詢端點備註「不需要對接 gamesettingservice」，可能是為了減低服務間耦合
- 操作區分「新增新的支援站台」和「新增既有支援站台」兩種情境，對應不同的後端處理邏輯（是否需要更新站台開通紀錄）
- PlayMode 操作以球種（gameType）為維度進行批次處理，而非逐筆操作
