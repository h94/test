## 摘要

这份文件是台湾运彩爬虫的 parser 技术规范，详细记录了如何从 API 返回的 HTML 中提取比赛基本资料和各类玩法的赔率数据。文件按运动类别（棒球BS、篮球BK、足球SC、网球TN、冰球HL、排球VB、羽毛球BM、桌球TB、手球HB、电竞ES、马拉松MA、板球CK）分别列出每个玩法的 idefmarkettype 对应关系和 JSON key 命名规则。对 AI 开发而言，这是爬虫数据结构的完整映射字典，可以直接用于自动化解析和数据标准化处理。

## 關鍵設計決策

- - 赛前与赛后使用不同的数据来源路径：赛前直接从 data 字段取值，赛后需进入 html['settledevents'][0] 再取值
- 比赛ID统一从 data['externalreference'] 中提取数字部分
- 赛前比赛时间使用 data['tsstart']，赛后则使用 html['tsrealstart']（实际开始时间）
- 主客队名称在赛前与赛后使用不同的字段名（赛前: participantname_home/away，赛后: participanthome/participantaway）
- time_stamp 字段需要额外转换后才能作为当前时间使用
- 每种运动的每个玩法通过 idefmarkettype 数值进行唯一识别，如棒球不讓分=354、篮球不讓分=288、足球不讓分=1
- JSON 输出的 key 命名规则按玩法类别区分：HA（讓分/不讓分）、OU（大小）、Others-XXX（特殊玩法）
- 上半场玩法统一使用 Half 前缀、第一节使用 1st Quarter/1Inn 前缀、第一局使用 1st Map 前缀
- 若某玩法盤口已关闭（如篮球上半场大小109.5），则直接跳过不处理
- 电竞类(ES)区分 CS2 和 LOL，两者使用不同的 idefmarkettype 对应关系（如第1局不讓分: CS2=526, LOL=803）
- 足球的半/全場賽果(Half Time/Full Time)使用斜线分隔的玩法结构如 A/A, A/D, D/H 等表示上半场/全场结果组合
