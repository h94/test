## 摘要

本文件記錄 CommunityService 新增文章/留言隱藏與批次刪除功能，並進行程式碼重構，將邏輯層從 resources 抽至 Services 資料夾。隱藏功能提供批次與單筆 API，被隱藏內容的 hot_score 清零，且超過 4 天自動刪除；取得文章列表 API 新增 show_hidden 參數以控制顯示。後半段補述新運彩相關的 Meilisearch 索引結構及按讚 API 設計。對 AI 開發而言，可了解隱藏機制、資料庫 schema 變更及重構後的服務分層方式。

---

## 關鍵業務規則

- - 隱藏（mute）文章或留言時，hot_score 立即清零，hidden 欄位設為 true，並記錄 hidden_timestamp（被隱藏的時間戳）。
- 隱藏超過 4 天的文章與留言將被排程自動刪除，計算基準為 hidden_timestamp（被隱藏的時間點），而非原始建立時間。
- 批次隱藏 API（/communityservice/api/community/mute）：參數 start 與 end 是依照「文章或留言所在文章的建立時間」篩選，非使用者留言時間，end 必須大於等於 start，且 start、end 為 13 位時間戳。
- 單筆隱藏 API（/communityservice/api/community/mute_single）：可僅指定 article_id，或同時指定 comment_id 隱藏單一留言。
- 取得文章列表與回文分頁時，新增 show_hidden 參數，設為 true 時才回傳被隱藏的內容；若無此參數或為 false，則不顯示。
- 後台 API 不受 hidden 影響，始終回傳所有文章與留言。
- 新運彩討論按讚：同一使用者對同一討論或留言僅能按讚一次，重複按讚回傳 409；收回讚時若無按讚紀錄回傳 404。

## 關鍵設計決策

- - 邏輯層從 resources 抽至 Service 資料夾（如 report_services.py），資源層僅保留 API 入口與參數驗證，目的是分離關注點（SoC），提高可測試性與維護性。
- 為隱藏功能新增 hidden 與 hidden_timestamp 兩個資料欄位，而非直接刪除記錄，以便支援復原（unmute）及追溯。
- 刪除策略採用「隱藏超過 4 天自動清除」，而非立即刪除，給予緩衝時間處理誤判或申訴。
- 取得文章列表加入 show_hidden 參數，由呼叫端控制是否顯示隱藏內容，兼顧一般前台與後台需求。
- 新運彩採用 Meilisearch 儲存討論與留言，並以 status (1/0) 控制顯示，取代直接過濾，使搜尋引擎能統一管理索引。

## 注意事項

- ⚠️ - ⚠️ 批次隱藏的 start/end 是依據文章建立時間而非留言時間，容易與直覺混淆，需特別注意文件中的舉例說明。
- ⚠️ 新運彩部分的 Meilisearch 索引名稱區分正式（newlottery_*）與測試（test_newlottery_*），部署時須確認環境對應。
- ⚠️ 文件中 API route 混用 community 與 newlottery 路徑，應確認服務拆分後的實際路由歸屬（可能由 communityservice 或獨立的 newlotterysite 提供）。
