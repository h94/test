## 摘要

文件說明賽事頁與賽事內頁的效能優化設計，將取得賽事 API 由撈取七天改為一天，調整刷新頻率與觸發時機，並將日期賽事數量計算轉移至賽事數量 API；賽事內頁透過 LocalStorage 記錄賽事狀態，對進行中賽事以 query temp=NOW 避開快取，並結合 WS 推送即時更新比分，旨在降低傳輸量並確保即時性。

---

## 關鍵業務規則

- - 進行中賽事必須避開快取以取得最新比分，非進行中賽事可使用正常快取
- 賽事內頁每次調用賽事資料 API 後需將狀態與日期存入 LocalStorage

---

## 關鍵設計決策

- - 取得賽事 API 改為只撈取一天資料，單次傳輸量從 300kb~2mb 降至 60kb~500kb，切換日期時觸發調用，每 5 分鐘重新整理，不再因 ws 狀態不符重新調用
- 日期賽事數量計算從取得賽事 API 移至賽事數量 API，避免重複撈取賽事資料計算數量
- 賽事內頁使用 LocalStorage 儲存賽事狀態，非進行中時走正常快取，進行中時加 query temp=NOW 避開快取，以平衡即時性與快取效率
- ws 推送的賽事資料直接更新畫面上比分，不必等待定時輪詢
- 賽事資料 API 已有 2 分鐘快取，可透過 query temp=NOW 繞過快取取得最新資料
