本文件定義了 Sprint 從需求分析到上線回顧的標準流程與每日檢查清單，包含各階段負責事項、時間排程與注意事項。對 AI 開發的幫助在於了解 Sprint 管理常規，例如：StoryPoint=13 需召開 Design Review、Release 時要檢查 Gateway 與 Swagger 設定、測試後期應補齊分析文件等，可作為自動化提醒或流程稽核的依據。

## 關鍵業務規則

- - 若 Story 項目較大（StoryPoint=13），必須召開 Design Review。
- Release 時如有新增 Service 或 API 接口，必須檢查 Gateway 是否有配置。
- 新增 Service 或 API 接口時，必須修改對應的 swagger.json。
- 測試後期需請成員補齊分析文件。
- Code Review 後需確認所有內容都已修改或記錄。
- 上線後需安排人員監控系統狀況。
- 每日需確認 Members 確實填寫 JIRA Work Log。
- 下班前確認 JIRA 問題和回覆都有填寫。
- 若線上問題需長期關注，應在 JIRA 上開 Task 監督狀況。
