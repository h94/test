## 摘要

此文件定義了 TCZB 團隊在一個 Sprint 中的標準作業流程，包含從需求估算、JIRA 建立、開發、測試到發布、回顧的完整步驟與每日檢查清單。重點規定了 Release 時必須檢查 Gateway 配置與更新 Swagger 文件，以及 Code Review 內容須被確實修改或紀錄。這些流程可輔助 AI 自動化 DevOps 檢查（如自動驗證 Swagger 更新、監控 Sprint 進度等）。

---

## 關鍵業務規則

- - 新增 Service 或 API 接口時，必須檢查 Gateway 是否有配置，並修改對應的 swagger.json
- Sprint 開始前需執行 Sonarqube 取得警告數與單元測試覆蓋率
- Story 點數為 13 時，需召開 Design Review 會議
- Code Review 內容必須全部被修改或紀錄，不可忽略
- 線上問題需長期關注時，應在 JIRA 上建立 Task 監督狀況
