# 查询版本

## 1. 场景目的
获取 LiveChatService 当前部署版本信息，供运维监控或客户端相容性检查使用。此版本号通常由构建流程写入，不涉及动态数据读取。

---

## 2. 入口 API

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/version` | 返回服务版本字串 |

---

## 3. 流程总览

1. 接收 GET 请求
2. 从服务配置或编译常数取出当前版本字串
3. 回传版本字串（HTTP 200）

---

## 4. 程式流程

| 顺​序 | Layer | Class / Method | 动作 |
|---|---|---|---|
| 1 | Controller | LiveChatVersionController.Get | 读取静态版本信息，直接返回 string |

*注：因项目结构不一，实际 Controller/Method 名称需人工确认；上述名称为推断。*

---

## 5. DB / Cache / Queue 使用

| 类型 | 资源 | 操作 | 用途 |
|---|---|---|---|
| 无 | - | - | 此端点无任何持久化资源操作 |

---

## 6. 重要规则

- 无需认证/授权
- 返回格式为 `text/plain` 或 `application/json`（依 Accept 标头自动协商）
- 版本信息不得暴露任何内部构建细节（如 commit SHA, build time 等），应为语义化版本字串（例：`1.0.2`）
- 版本号应在部署时写入，运行时不可变更

---

## 7. 错误情境

| 情境 | 预期结果 |
|---|---|
| 服务正常启动 | HTTP 200，回传版本字串 |
| 服务未配置版本信息 | 可能回传空字串或默认占位符，不抛出异常 |

*需人工确认：若版本信息缺失，是否应有预设值。*

---

---

## 9. 高風險區域

- 无明显高风险，因此端点极为轻量且无副作用。

---

## 10. 常見錯誤

- 误以为需读取数据库或配置文件动态生成版本号 → 实际应为编译时注入常量
- 在版本字串中暴露构建环境信息（如 CI 流水线 ID），导致潜在安全风险
