# 上傳圖片

## 1. 場景目的
提供後台管理員通用圖片上傳功能，將圖片檔案保存至存儲系統並回傳圖片存取 URL，用於廣告、公告、客服訊息等需要圖片欄位的場景。本服務不直接操作資料庫，所有資料寫入由下游服務完成。

---

## 2. 入口 API

| Method | Path | 說明 |
|--------|------|------|
| POST | `/api/v1/system/upload/img` | 上傳圖片檔案（支援多張） |

需要驗證：✅（後台管理員權限）

---

## 3. 流程總覽
1. 後台管理員選擇圖片，透過 multipart/form-data 發送請求。
2. Controller 驗證請求合法性（檔案非空、格式允許）。
3. 檢查當前請求者的管理員身分與權限。
4. 若圖片需要處理（如壓縮、調整尺寸），使用影像處理函式庫（如 SixLabors.ImageSharp）進行轉換。
5. 將圖片二進位內容上傳至檔案存儲服務或 CDN 儲存空間。
6. 取得該圖片的公開存取 URL（或相對路徑）。
7. 回傳圖片路徑（完整 URL）給前端，供後續業務使用。

---

## 4. 程式流程

| 順序 | Layer       | Class / Method                        | 動作                                           |
|------|-------------|---------------------------------------|------------------------------------------------|
| 1    | Controller  | `SystemController.UploadImg`          | 接收上傳請求，提取 `IFormFile` 集合             |
| 2    | Validator   | `ImageUploadValidator`（推測）         | 驗證檔案擴展名、大小、內容型態                  |
| 3    | Service     | `ImageService.Process`（推測）         | 圖片壓縮、格式轉換、旋轉修正（EXIF）            |
| 4    | Provider    | `StorageProvider.Upload`（推測）       | 將圖片二進位流寫入 CDN 或物件存儲，返回檔案 key |
| 5    | Service     | `ImageService.BuildUrl`（推測）        | 將 key 組合成可公開訪問的 URL                   |
| 6    | Controller  | `SystemController.UploadImg`          | 回傳 URL 集合                                   |

> 需人工確認：實際類別、方法名稱及流程細節。

## 6. 重要規則

- **權限限制**：僅限後台管理員（需通過 `ECFramework.ECService` 驗證），禁止一般使用者呼叫。
- **檔案限制**：
  - 支援格式：JPEG、PNG、WebP 等（確切清單需人工確認）
  - 單檔大小上限：預設 5 MB（可透過 Zookeeper 配置調整）
  - 像素上限：可能會強制縮小至 2000 px 以內，防止 OOM
- **不可暴露資料**：
  - 回傳的 URL 應為 CDN 公開域名，不可回傳內部儲存絕對路徑（如 `/mnt/data/img/...`）
- **安全防護**：
  - 嚴格校驗檔案魔術字節，避免腳本或偽裝檔案上傳
  - 上傳後移除所有 EXIF 資訊（相機、地理位置等）
- **回傳格式**：一律回傳完整的 `https://cdn.example.com/xxx.jpg`，不含協定的相對路徑需由前端補全。

## 7. 錯誤情境

| 情境                     | 預期結果                                      |
|--------------------------|-----------------------------------------------|
| 未攜帶 Token 或 Token 無效 | 401 Unauthorized                              |
| Token 對應帳號無管理角色   | 403 Forbidden                                 |
| 請求中未包含任何檔案       | 400 Bad Request，訊息「請選取圖片檔案」         |
| 檔案格式不允許             | 400 Bad Request，訊息「不支援的圖片格式」       |
| 檔案大小超過限制           | 413 Payload Too Large 或 400 附錯誤說明        |
| 圖片處理失敗（損壞檔案）   | 400 Bad Request，訊息「圖片損壞或無法讀取」     |
| 存儲服務連線逾時           | 500 Internal Server Error，記錄錯誤日誌          |
| 同時上傳超過允許數量       | 400 Bad Request，訊息「單次上傳不能超過 N 張」    |

## 9. 高風險區域

- **檔案類型偽造**：若只信賴副檔名，攻擊者可上傳含有惡意程式碼的偽裝檔。必須檢查檔案 head magic bytes。
- **資源耗盡**：處理大尺寸圖片可能造成記憶體不足，需限制解析度並強制壓縮。
- **CDN 快取問題**：若同名圖片被更新（少見），舊快取可能仍存在，影響新圖片顯示。建議每次上傳生成唯一檔名。
- **存儲費用膨脹**：若無檔案生命週期管理，歷史圖片永遠保留，可能導致成本攀升。

---

## 10. 常見錯誤

- 前端誤用相對路徑組合，忘記補上 CDN 域名，導致圖片無法顯示。
- 未移除 EXIF，暴露拍攝者 GPS 位置等隱私資訊。
- 記憶體管理不當：一次載入過多圖片進記憶體，引發 OutOfMemory。
- 未檢查管理員權限，使所有登入者均可上傳圖片，遭濫用。
