## 跨頁面的共用規則

<!--
整個專案共用的 UI 規則，不屬於特定頁面。
-->

- **全域 Loading**：任何進行中的 API 請求，都會觸發全螢幕的半透明 loading 遮罩，防止使用者重複操作。
- **操作回饋**：絕大部分操作成功或失敗，都會透過右上角的 Toast 通知 (vue3-toastify) 給予提示。成功為綠色，警告為黃色，錯誤為紅色。格式為 `標題` + `詳細訊息`。
- **登入驗證**：所有非 `/login` 頁面都需要驗證。`router` 中介層會檢查 cookie 中是否有 `user` 值，若無則強制導向 `/login`。
- **資料表格共用規則**:
  - 多數表格支援排序、搜尋。
  - 搜尋時可能提供下拉建議 (combobox)，方便快速查找特定狀態或類型。
  - 若有大量資料，會採用分頁或虛擬滾動。
- **時間格式**：
  - 大部分列表和表單中的時間顯示為 `YYYY-MM-DD HH:mm:ss` 格式 (例如 `2024-05-24 16:30:00`)。
  - 部分 Unix 時間戳會在前端乘以 1000 轉換。
- **金額與數字格式**：所有較大的數字 (如金額、人數) 都使用 `toLocaleString()` (或類似 `FormatterLibrary.NumeberWithCommas`) 顯示千分位逗號。
- **表單驗證**：表單提交時，必填欄位為空或格式錯誤時，欄位下方會顯示紅色錯誤提示文字，且「送出」按鈕可能為 disabled 狀態。
- **側邊欄**：左側側邊欄可手動開關或固定 (lock)，偏好設定會儲存在 `localStorage`。

## 權限控制邏輯

<!--
前端的權限控制方式，特別是：
- 哪些頁面需要登入
- 哪些功能依角色顯示或隱藏
- 前端權限和後端權限的關係

- **認證機制**：
  - `router` 中介層 (`middleware/auth.global.ts`) 會檢查名為 `user` 的 cookie 是否存在，作為是否登入的依據。
  - 登入邏輯在 `pages/login.vue`，比對硬編碼 (hardcoded) 或設定檔 (`config/user/Auth`) 中的帳號密碼。驗證成功後設置 `user` cookie。
- **未登入限制**：存取任何非 `/login` 的頁面，都會被導向 `/login`。
- **角色權限**：
  - **需人工確認**：目前未發現前端有針對不同角色的功能展示或頁面限制。登入後的所有使用者似乎看到完全相同的介面與功能。權限控制應完全依賴後端 API 的驗證。

## 常見錯誤（此前端專屬）

<!--
從 bug 記錄和 code review 累積的真實錯誤。
重點描述和後端不同的前端特有問題。
-->

- ❌ **README 與實際功能不符**：README 描述為「價格管理與工具操作平台」，但實際頁面與程式碼顯示為「運動賽事後臺工具」，功能圍繞會員、預測、社群管理等。應更新 README 以符合實際情況。
- ❌ **認證邏輯過於簡化**：`/login` 頁面直接在前端比對帳密，未呼叫後端 API 進行驗證，安全性不足。
- ❌ **缺少角色權限控制**：所有登入者皆可存取所有頁面，若未來有分權需求 (如客服、營運)，需要大量重構。
- ❌ **全域錯誤處理不明確**：部分頁面有針對單一 API 的錯誤處理 (`v-alert`)，但許多元件僅依賴全域 toast 通知，且未發現 Axios 攔截器 (interceptor)，可能導致部分錯誤 (如網路錯誤) 無提示。
- ❌ **狀態管理混亂**：`predcitStore` 用於快取 `PredictSettings`，但多個頁面 (`predict/editGame`, `predict/predictBet`) 又各自重複呼叫 `GetPredictSettings` API，快取機制不一致。

## 與其他前端專案的關係

<!--
