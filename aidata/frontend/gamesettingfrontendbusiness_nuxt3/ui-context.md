### 站台啟用設定 `/site-setting`

**路由**：`/site-setting`
**對應 API**：
- `GET /setting/site/{businessCode}/{gameType}/{uid}` → 取得各站台啟用狀態
- `PUT /setting/site` → 更新站台啟用清單

**這個頁面能做什麼**：
- 依球種查看所有站台的啟用/停用狀態
- 透過開關切換各站台狀態（front-end only，尚未儲存）
- 點擊「送出」按鈕將變更寫入後端
- 查看該球種的站台啟用歷史紀錄

**功能限制**：

| 限制條件 | 使用者看到的行為 |
|---------|---------------|
| 未登入 | 導向登入頁 |
| 未選擇球種（預設為訂閱的第一個球種） | 列表顯示該球種的站台狀態 |
| 切換球種時 | 重新載入該球種資料，未儲存的變更會遺失 |
| 使用者無權限寫入（後端判定） | 按下送出後顯示後端錯誤訊息（例如「權限不足」） |

**狀態說明**：

| 資料狀態 | 前端顯示行為 |
|---------|------------|
| `item.enabled` = true | 開關為開啟，標籤顯示「啟用」 |
| `item.enabled` = false | 開關為關閉，標籤顯示「停用」 |

**錯誤處理**：

| 錯誤情境 | 使用者看到的行為 |
|---------|---------------|
| 取得站台列表失敗 | Toast 顯示錯誤訊息（系統異常或後端訊息），列表為空 |
| 送出更新失敗 | Toast 顯示「更新失敗」或後端錯誤訊息；資料回復為原始狀態（重新讀取） |

### 球種設定值維護 `/gameType-setting/config`

**路由**：`/gameType-setting/config`
**對應 API**：
- `GET /setting/gameTypeConfig/detail/{businessCode}/{gameType}/{uid}` → 取得球種設定值明細
- `PUT /setting/gameTypeConfig` → 更新球種設定值
- 另有取得支援站台列表、同步排程等 API

**這個頁面能做什麼**：
- 選擇球種，編輯該球種的「基本設定」及各玩法的詳細參數（模式、點位、小數位數、站台權重等）
- 停用/啟用特定玩法
- 隱藏已停用的玩法（切換顯示）
- 同步所有玩法的「排程設定」（告警的時間與型態）
- 同步所有玩法的「站台設定」（將第一個玩法的站台設定複製到其他玩法）
- 儲存變更
- 查看該球種的設定值修改歷史

**功能限制**：

| 限制條件 | 使用者看到的行為 |
|---------|---------------|
| 未登入 | 導向登入頁 |
| 沒有選擇球種（預設第一個） | 顯示該球種的設定值 |
| 切換球種時未儲存 | 變更會遺失（無確認對話框，需人工確認） |
| 同步排程或同步站台 | 先跳出確認對話框，說明影響範圍 |
| 停用玩法 | 跳出多選對話框，列出所有玩法供勾選，確認後將對應玩法設為停用 |

**狀態說明**：

| 資料狀態 | 前端顯示行為 |
|---------|------------|
| `configDetail.settings[].enabled` (隱含) | 若停用且「隱藏停用」開啟，則不在面板中顯示 |
| `configDetail.showStopPlayMode` = true | 面板顯示所有玩法（含停用） |
| `configDetail.enabled` = 1 | 基本設定中「狀態」開關為啟用 |
| `configDetail.swap` = true | 「對調」開關為開啟 |

**錯誤處理**：

| 錯誤情境 | 使用者看到的行為 |
|---------|---------------|
| 讀取設定值失敗 | Toast 顯示「系統異常」或後端訊息，頁面無法顯示編輯器 |
| 儲存失敗 | Toast 顯示錯誤訊息，不離開頁面 |

## 跨頁面的共用規則

- **身份驗證**：所有頁面（除 `/login`）未登入時自動跳轉至 `/login`；已登入狀態下進入 `/login` 則跳回 `/home`（middleware `auth.global.ts`）。
- **全域載入中**：當 `SetLoading(true)` 時，頁面會覆蓋半透明 loading 動畫，阻擋操作（由 `VLoading` 元件實現，監聽 `SystemStore().GetLoading()`）。
- **日期與時間顯示**：
  - 所有時間均轉換為 **台北時間 (UTC+8)**，使用 `DateLibrary.dateToUtc8String`，格式多為 `YYYY-MM-DD HH:mm`。
  - 日期選擇組件使用 Vuetify 的 `v-date-input`，其值為 JavaScript Date 物件。
- **貨幣與數字**：目前無金額顯示；賠率（Odds）以原始數字展示，無千分位格式。
- **錯誤處理**：
  - API 回應中的錯誤訊息透過 `checkError` 解析，若為「Login information does not exist」則自動清除登入狀態並導向登入頁。
  - 其他錯誤由各頁面自行 `SetToast` 顯示。
  - 全域 HTTP 錯誤攔截器（在 `apis/index.ts` 的 `$fetch` 中自訂 `onResponseError`）會將後端錯誤物件拋出，由各函式捕捉。
- **Toast 通知**：統一使用 `useGlobal().SetToast(message, type)`，訊息支援 HTML。
- **麵包屑 (Breadcrumbs)**：每個頁面在 `onActivated` 或 `onMounted` 中設定 `SetBreadcrumbs`，顯示當前路徑階層。
- **多國語系**：
  - 支援 `zh-TW`、`en-US`，語言切換儲存於 Cookie，重啟後保留。
  - 所有靜態文字使用 i18n 的 `t()` 函式，球種、狀態等枚舉值也透過翻譯檔對應。
- **表格組件**：共用 `Table` 元件，支援虛擬滾動、排序、固定表頭、展開行、多選、載入中狀態、無資料提示。
- **即時通訊**：`HubService` 在應用啟動後依訂閱資訊連接 SignalR Hub，即時接收賽事賠率更新，並透過回呼更新 `Hub` 頁面資料。
- **主題切換**：深色/淺色模式儲存在 `localStorage` 的 `user-preferences` 中，全域可用。

---

## 權限控制邏輯

- **路由守衛**：`middleware/auth.global.ts` 僅驗證 `UserStore().GetUser()` 是否存在，無角色檢查。因此所有登入使用者均可訪問所有頁面。
- **角色顯示控制**：僅在 `/user` 頁面透過 `v-if="User.role === 'admin'"` 顯示「帳號管理」區塊，其他頁面無角色區分。
- **功能限制**：前端沒有針對不同角色隱藏導航項目或頁面內的寫入按鈕。真正的權限控制完全依賴後端 API；若使用者無權限，後端回傳錯誤，前端以 Toast 顯示錯誤訊息。

## 與其他前端專案的關係

- 此為後台管理前端（營運人員使用），無直接相關的前台。
- 使用相同的 API 服務 (`gamesettingfrontendbusiness_nuxt3`)，但無其他前端共用此專案。

## 常見錯誤（此前端專屬）

- ❌ **權限不足操作**：前端未根據角色隱藏按鈕（如 `/site-setting` 的送出按鈕所有人都看得到），若後端拒絕，僅顯示錯誤 Toast，沒有事先阻擋。→ 應在前端根據 `User.role` 或 `UserSubscribeInfo` 隱藏無權限的操作入口，提升使用者體驗。
- ❌ **未儲存切換頁面**：許多編輯頁面（如 `/league-setting/league`, `/gameType-setting/config`）在切換球種或離開時不會提示儲存，已修改的資料會直接遺失。→ 應加入離開守衛（beforeRouteLeave）或監聽未儲存變更。
- ❌ **站台狀態逾時判斷**：前端用 `checkTimeout` 比較本地時間與最後更新時間，但本地時間可能與伺服器不同步。→ 應統一使用伺服器時間（API 回傳的 `serverTime`）或改用時間戳比較，避免誤判。
- ❌ **SignalR 斷線無提示**：`/hub` 頁面依賴 SignalR 即時推送，但斷線時無明顯 UI 提示，使用者可能看到過時資料而未察覺。→ 應在連線狀態變更時顯示「連線中斷」提示，並在恢復時自動重整。
- ❌ **日期選擇器 disabled 狀態誤導**：`/login-history` 的日期選擇器設為 `disabled` 卻顯示在搜尋欄，使用者可能以為可以篩選。→ 應移除或改為純文字顯示。
