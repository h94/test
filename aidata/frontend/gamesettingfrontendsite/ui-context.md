## 頁面功能描述

### 儀表板（/dashboard）

**路由**：`/dashboard`
**對應 API**：
- `GET /api/v1/games/dashboard`（推測） → 取得所有站台狀態與更新時間

**這個頁面能做什麼**：
- 查看所有遊戲類型在各站台的即時數據更新狀態（PreGame / InPlay）
- 展開／收合所有遊戲狀態的詳細列表
- 自點擊「搜尋」後每 30 秒自動更新一次

**功能限制**：

| 限制條件 | 使用者看到的行為 |
|---------|---------------|
| 某站台更新時間逾 3 分鐘 | lastUpdateTime 欄位顯示為紅色（timeOut 樣式） |
| isLive = 0（非即時） | 狀態文字顯示為紅色 |
| 未點擊搜尋按鈕 | 表格無數據 |

**狀態說明**：

| 資料狀態 | 前端顯示行為 |
|---------|------------|
| isLive = 1 | 顯示當前狀態文字（PreGame / InPlay）正常顏色 |
| isLive = 0 | 顯示對應狀態文字，但為紅色 |
| lastUpdateTime 距離現在 < 3 分鐘 | 顯示時間，正常顏色 |
| lastUpdateTime 距離現在 >= 3 分鐘 | 顯示時間，但為紅色（timeOut 樣式） |

**錯誤處理**：

| 錯誤情境 | 使用者看到的行為 |
|---------|---------------|
| API 錯誤（response != undefined）或 Network Error | 重新載入資料（reloadData），清除控制台錯誤，不顯示錯誤訊息 |

### Hub（/hub）

**路由**：`/hub`
**對應 API**：
- WebSocket (SignalR) → 即時接收各站台的賠率數據
- 多個後端 API 提供 Game/League/Team 詳細資料和 Log 數據

**這個頁面能做什麼**：
- 即時監看各站台的賽事賠率變化
- 篩選遊戲類型、站台、賽事狀態（PreGame / InProgress / Final）
- 切換 PreGame 模式的時間區間
- 查看各玩法的詳細賠率（HA、OU、Half、Quarter 等）
- 點擊 GID 查看比賽詳細資訊和新分頁連結
- 點擊 Log 查看該場比賽的操作記錄
- 檢視免責聲明（數據警告提示）

**功能限制**：

| 限制條件 | 使用者看到的行為 |
|---------|---------------|
| PreGame 狀態以外的比賽 | 時間篩選下拉選單 disabled 無法使用 |
| 賽事狀態為 Final（已結束） | 不顯示賠率數據，顯示賽果（需人工確認） |
| SignalR 連線中斷 | 頁面連結圖示變為斷線圖示（link-slash） |

**狀態說明**：

| 資料狀態 | 前端顯示行為 |
|---------|------------|
| 賽事狀態 PreGame | 顯示賠率數據，可篩選時間 |
| 賽事狀態 InProgress | 顯示賠率數據，顯示比分 |
| 賽事狀態 Final | 顯示賽果，無賠率數據 |
| WebSocket 連線正常 | 顯示連結圖示 |
| WebSocket 連線中斷 | 顯示斷線圖示 |

**錯誤處理**：

| 錯誤情境 | 使用者看到的行為 |
|---------|---------------|
| WebSocket 中斷 | 顯示斷線圖示，最後一筆資料停留不更新 |
| SignalR 錯誤 | 依賴重整機制自動嘗試重連 |

### 遊戲設定（/game）

**路由**：`/game`
**對應 API**：
- `GET /api/{gameType}/Game/List`（推測）→ 取得比賽列表和對應設定
- `POST /api/{gameType}/Game/Setting`（推測）→ 更新比賽設定

**這個頁面能做什麼**：
- 搜尋特定日期、球種、聯盟的比賽
- 查看每場比賽使用哪個設定模板（系統設定／聯盟設定／遊戲設定）
- 修改比賽設定（啟用／停用、Swap、玩法參數）
- 選擇現有模板套用至比賽
- 查看比賽的設定修改記錄
- 點擊聯賽名稱、隊伍名稱跳轉到詳細資訊頁

**功能限制**：

| 限制條件 | 使用者看到的行為 |
|---------|---------------|
| 比賽 useGameSetting = 2（未設定） | 無法更新設定，看不到編輯按鈕（需人工確認） |
| useGameSetting = 1 或 0 | 顯示更新按鈕、Log 按鈕、「選擇」按鈕 |
| 比賽狀態為 Final 或 Cancelled | 「選擇」和「更新」按鈕可能 disabled（需人工確認） |

**狀態說明**：

| 資料狀態 | 前端顯示行為 |
|---------|------------|
| gameStatus=0 | 顯示「即將開始」 |
| gameStatus=1 | 顯示「進行中」 |
| gameStatus=2 | 顯示「已結束」 |
| gameStatus=3 | 顯示「延期」 |
| gameStatus=4 | 顯示「取消」 |
| useGameSetting=0 | 顯示設定名稱 +「使用聯賽設定」 |
| useGameSetting=1 | 顯示設定名稱 +「使用遊戲設定」 |
| useGameSetting=2 | 顯示「系統設定」 |

**錯誤處理**：

| 錯誤情境 | 使用者看到的行為 |
|---------|---------------|
| API 錯誤或 Network Error | 使用 `$checkApiError` 統一處理 |
| 更新失敗（code != 2000） | 顯示錯誤訊息 Alert |
| 更新成功 | 顯示成功 Toast，導回遊戲列表 |

## 跨頁面的共用規則

- **語言切換**：繁體中文／英文，切換後所有頁面即時更新，說明文件也隨之更換
- **登入狀態**：所有路由（除 `/login`）都需要已登入，否則導向 `/login`
- **登入過期**：`CheckLogin` 檢查失敗時，清除 cookie 並導向登入頁
- **黑暗模式**：透過 cookie 儲存使用者偏好，切換時套用至全域樣式
- **側邊欄**：可收合，寬度隨之變化；每個設定模組有獨立的導覽項目
- **時間格式顯示**：統一使用 `$date.UnixToDateTime` 和 `$date.UnixToTime` 過濾器
- **日期選擇器**：使用自訂 `DatePicker` 元件，格式 YYYY/MM/DD
- **搜尋條件記憶**：各模組的搜尋條件會存入 Vuex（Render module），切換頁面後回上一頁仍保留
- **所有列表頁預設排序**：依 updateTime 或 addTime 倒序
- **Loading 狀態**：所有 API 請求期間顯示全頁 Loading 動畫，超過 3 秒顯示取消按鈕
- **API 錯誤處理**：統一透過 `$checkApiError` 方法處理，會檢查 response.data 並顯示對應錯誤訊息
- **Token / Cookie**：使用者登入資訊存於 cookie `user`（含 UID, Company, Account, TeamName）

---

## 權限控制邏輯

- **路由守衛**：所有路由（除 `/login`）進入前會檢查 `vue-cookies` 中是否有 `user` 資料，若無則導向 `/login`
- **登入驗證**：呼叫 `CheckLogin` API 確認 cookie 中的 UID 是否仍有效
  - 成功且目前在 `/login` → 導向 `/`
  - 失敗且非 `/login` → 清除 cookie，導向 `/login`
- **前端權限**：未見角色區分，所有已登入使用者可查看所有頁面
- **後端權限**：前端只做 UI 路由控制，真正的操作權限由後端 API 驗證

## 常見錯誤（此前端專屬）

- ❌ 日期選擇器未選取時顯示「No Date Selected」，但搜尋條件仍會帶入空值 → 應在前端驗證
- ❌ 部分搜尋欄位未輸入必填項目時仍可點擊搜尋 → 應在前端加上必填驗證或 disabled 控制
- ❌ 切換遊戲類型時站台列表動態更新，但可能造成選取不存在的站台 → 需確認站台切換邏輯正確
- ❌ Loading 狀態若 API 卡死，3 秒後顯示取消按鈕 → 取消後的狀態復原需人工確認
- ❌ Token 過期僅在路由切換時檢查 → 長時間停留同一頁可能導致 API 呼叫失敗卻未重新導向登入頁
- ❌ 搜尋條件記憶在 Vuex 中，若使用者多開分頁可能造成狀態不一致（需人工確認）
