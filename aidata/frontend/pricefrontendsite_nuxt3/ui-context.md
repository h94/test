## 頁面功能描述

### 即時比賽頁面（Live Game）

**路由**：`/:country/game`
**對應 API**：
- `GET /api/v1/games` → 取得比賽列表
- `GET /api/v1/games/counters` → 取得各日期比賽數量
- `SignalR Game Hub` → 即時比分推送

**這個頁面能做什麼**：
- 選擇運動類型（足球、籃球、棒球等）
- 選擇日期（今天及前後數日）
- 篩選聯盟
- 查看比賽清單，包含隊伍、比分、狀態、倒數計時
- 進行中的比賽會即時更新比分
- 若有直播來源，顯示直播按鈕
- 點擊比賽可進入詳細分析頁

**功能限制**：

| 限制條件 | 使用者看到的行為 |
|---------|---------------|
| 比賽狀態為 PreGame（0） | 顯示「即將開始」及開賽倒數計時 |
| 比賽狀態為 InProgress（1） | 顯示「進行中」、即時比分、比賽時間 |
| 比賽狀態為 Final（2） | 顯示「已結束」及最終比分 |
| 比賽狀態為 Cancelled（3）或 Postponed（4） | 顯示「比賽取消」或「比賽延期」，比分顯示「-」 |
| 比賽有直播網址時 | 進行中的比賽顯示直播按鈕（需人工確認是否判斷登入） |
| AI 預測進行中的比賽 | 排序提升至列表頂部 |
| 篩選聯盟後無比賽 | 顯示「無符合條件的比賽」 |
| 載入中 | 顯示骨架屏（LoadingCard） |

**狀態說明**：

| 資料狀態 | 前端顯示行為 |
|---------|------------|
| `status = 0` (PreGame) | 顯示綠色「即將開始」，顯示開賽倒數計時 |
| `status = 1` (InProgress) | 顯示紅色「進行中」，顯示即時比分與比賽時間 |
| `status = 2` (Final) | 顯示灰色「已結束」，顯示最終比分 |
| `status = 3` (Cancelled) | 顯示灰色「比賽取消」 |
| `status = 4` (Postponed) | 顯示灰色「比賽延期」 |
| `liveUrl` 存在且比賽進行中 | 顯示直播按鈕 |
| `aiInProgress` 包含該比賽 | 比賽排序提前並顯示 AI 標記 |

**錯誤處理**：

| 錯誤情境 | 使用者看到的行為 |
|---------|---------------|
| API 請求失敗 | 顯示錯誤 Toast，列表為空（或保持最後一次快取） |
| WebSocket 連線中斷 | 比分停止更新；重新連線後恢復（需人工確認） |

### 預測遊戲頁面（Predict Game）

**路由**：`/:country/predict-game`
**對應 API**：
- `GET /api/v1/predictgame` → 取得可預測比賽及賠率
- `POST /api/v1/predictions` → 送出預測

**這個頁面能做什麼**：
- 選擇運動類型和聯盟
- 查看可預測的比賽（通常為賽前比賽）
- 每場比賽顯示多種玩法：1X2、讓球 (HA)、大小 (OU)、全場讓球 (GameHA)、全場大小 (GameOU)（視該比賽提供的賠率）
- 點擊賠率按鈕選擇預測，可累積多場預測後一次送出
- 查看未送出的預測暫存

**功能限制**：

| 限制條件 | 使用者看到的行為 |
|---------|---------------|
| 未登入 | 點擊賠率按鈕或送出預測時，彈出登入 Modal |
| 比賽已關閉預測（如已開始） | 可能不出現在列表中，或按鈕禁用（需人工確認） |
| 該玩法賠率為 0 或不存在 | 對應按鈕不顯示 |
| 同一場比賽同一玩法已預測 | 可能需要限制重複預測（需人工確認），目前前端無明確阻擋 |

**狀態說明**：

| 資料狀態 | 前端顯示行為 |
|---------|------------|
| 比賽 `openPredict = true` 且 `status = 0` | 顯示可預測的比賽，賠率按鈕可點擊 |
| 比賽 `openPredict = false` 或 `status != 0` | 可能不顯示在預測遊戲列表中 |

**錯誤處理**：

| 錯誤情境 | 使用者看到的行為 |
|---------|---------------|
| 送出預測失敗 | 顯示錯誤 Toast（例如「系統忙碌」） |
| 載入可預測比賽失敗 | 顯示錯誤 Toast，列表為空 |

## 跨頁面的共用規則

- **時間格式**：依使用者選擇的時區和語言格式顯示。預設格式為 `YYYY/MM/DD HH:mm`（24小時制），部分頁面使用相對時間（如 `timeago.js`）
- **金額顯示**：Z 幣數量使用千分位逗號分隔，超過百萬時顯示 `x.xxm`（如 Header 中的餘額），商城價格使用千分位
- **登入狀態**：全域變數 `User.Account` 判斷是否登入；未登入時點擊需要權限的操作會彈出登入 Modal，並記錄當前 URL 供登入後返回
- **API 錯誤處理**：每個 API 呼叫各自檢查 `error`，並透過 `store.global().SetToasts` 顯示錯誤訊息，多數不顯示技術細節
- **Token 過期**：推測在 `apis/index.ts` 有全域攔截器處理 401，若無則可能依賴個別頁面處理（需人工確認）
- **多語系**：所有文字透過 `t()` 函數讀取 i18n 字典，語系由 Google Sheets 同步
- **廣告顯示**：未登入或非 VIP 用戶可能看到 AdSense 廣告（需人工確認），VIP 則隱藏
- **圖片**：使用 WebP 格式，若加載失敗自動回退原格式（需人工確認）

## 權限控制邏輯

- **路由守衛**：部分需要登入的頁面（如 `/users/*`）可能由全局 middleware `user.global.ts` 強制導向登入，但目前觀察到頁面內部多數自行判斷登入狀態；具體需人工確認 middleware 實作
- **功能隱藏**：
  - `IsAdmin` 控制管理員專用 UI（如測試環境按鈕、隱藏遊戲模式）
  - `UserSubLogLibrary.CheckIsVip()` 控制 VIP 功能顯示（如去除廣告、VIP 專屬競猜）
  - `User.Account` 存在與否控制登入相關操作
- **前端只做 UI 控制**，後端 API 才真正驗證權限；前端不可完全依賴 UI 隱藏進行權限管控

## 常見錯誤（此前端專屬）

- ❌ 多處使用前端時間判斷截止（如倒數計時） → 應以伺服器回傳的 `serverTime` 為準，避免用戶端時間不準  
- ❌ 狀態對應顯示文字（如比賽狀態、驗證狀態）直接寫死在 component 中 → 應提取至設定檔，方便多語系維護  
- ❌ 部分列表頁面未處理空陣列 → 應顯示「目前無資料」而非空白  
- ❌ 金額顯示部分頁面未格式化千分位 → 應統一使用 `FormatterLibrary.BreakpointNumber`  
- ❌ Token 過期後可能未統一攔截 401，各頁面需自行處理 → 應在 axios/fetch 全域攔截器中統一處理，清除登入狀態並導向登入頁  
- ❌ 圖片加載失敗的備援機制只在 `WebpImg` component 中處理，部分直接使用 `<img>` 的地方無備援 → 應統一使用 `WebpImg` 或提供備援邏輯  
- ❌ 預測送出沒有樂觀鎖或防止重複點擊 → 可能導致雙重提交，需在點擊後禁用按鈕直到回應
